# 代码修改

输入：冻结任务目标、资源范围、约束、共享进度和当前证据。

先读取关联项目与现有实现。通过 file.propose_patch 生成绑定旧 hash 的补丁产物；解释修改与验收目标。编辑和测试遵守项目授权与动作审批。测试只在固定隔离执行环境进行，环境不可用时报告能力缺失。提交前比较实际差异并检查测试结果；不能把代码修改成功当部署成功。

输出：有出处的发现、行动或产物引用、验收结果及未验证项。权限、预算或执行环境不足时通过共享进度交回受阻事实，不扩大授权。
