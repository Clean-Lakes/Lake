# Lake Desktop

Wails/React 客户端。请从仓库根目录运行 `scripts/build_lake_desktop.sh`。脚本会同时打包
已签名的 Lake CLI，默认输出到 `~/Library/Application Support/Lake/builds/`，成功构建后只保留最新一个版本；需要安装到 `~/Applications/Lake.app` 时显式加 `--install`，原应用会备份。构建或安装失败时保留之前的构建。单独运行 `wails build` 的应用缺少这个必需的后端进程。

侧栏按湖展示会话和资源。会话可新建、切换、重命名、归档和恢复；每轮消息保存在 `~/.lake/lake.db`，切回会话时恢复上下文。切换会话会关闭之前会话的 SSH 连接。
输入框底部可在已登记的模型之间切换；切换会重新启动当前会话的 Lake Agent 进程并关闭当前保持的 SSH 会话，对话历史仍在。
盾牌按钮打开全局 SSH 静默权限：只读检查默认直接执行，其他命令默认逐次确认。开关写入 Lake 数据层，下一次 SSH 操作即生效；资源自身仍需执行授权。普通回车换行，`⌘+回车` 发送。

会话绑定本地代码项目后，顶部“代码工作台”提供文件树、文件预览、Git 状态/提交图/差异与终端。工作终端按会话及项目绑定，显示用户和实际目录，保留 `cd`/`export` 状态。每条 Shell 命令仍须批准，可在空闲时显式关闭终端；退出应用时中止命令。收起面板、切换会话或模型会保留终端。该终端按行执行，不提供交互式 TTY；Shell 命令本身没有文件系统沙箱。

代码项目区域的服务器按钮可为已登记 SSH 主机添加远程代码工作区。远端根目录先经 SSH 校验，工作区授权独立于主机执行授权。绑定后顶部与面板显示远端用户、主机、端口和目录；面板支持有界文本读写和单行命令。写入按原文件 SHA-256 条件保存，每次写入/命令运行均经系统对话框单独批准；断线后的结果显示“未知”，核对远端状态前不会自动重试。

输入框的图片、视频与 PDF 按钮均可在发送前预览。视频使用系统 AVFoundation 提取最多四张有界关键帧；PDF 使用 PDFKit 生成首页 JPEG 和有界文本。会话只保存派生预览，原始文件不进入模型或数据库；Web 同样可回看和下载预览。

所复制的 beUI 组件遵循 `frontend/BEUI_LICENSE`。开发时可设置
`LAKE_CLI_PATH` 指向已编译的 Lake CLI，然后在此目录运行 `wails dev`。


侧栏“运维工作流”的 `+` 打开工作流 v2 管理，可编辑 JSON/YAML、校验/预览、保存修订、选择代码项目、查看运行节点/事件并恢复。运行与恢复回到对话审批卡。“设置 → 自定义专员”管理独立模型、工具白名单、范围、轮数、启停与任务恢复。插件页展示 MCP/Hook 声明数量，启用后在新会话装配；停用和摘要变化会阻断旧会话调用。详细 CLI 与检查点规则见[四项闭环说明](../../docs/migration-closure.md)。

工作流侧栏的文件夹按钮创建目录，每个目录可继续创建子目录、重命名或删除空目录。v1/v2 工作流与目录均可拖动：行中间移入目录，行上下边缘排序，湖标题移回根目录。目录移动保留所有子项，禁止跨湖移动及循环嵌套。组织信息持久保存在 SQLite，目录展开状态保存在本机界面。

工作会话提供“问 AI / 执行命令”两种输入方式。执行结果同时出现在聊天时间线及终端面板，可引用 #E 记录向 AI 提问。AI 命令提案支持“这一步我来 / 交回 Lake”，保留原工具调用并返回核验过的手动执行结果；本机和远程均使用持续 Shell。会话事件保存有界、脱敏的命令及输出；湖志继续仅记录命令哈希。应用重启只恢复记录，未完成的历史命令显示为未知。

运维结果支持原生图形化卡片：指标、状态占比/条形图、异常提示、可搜索和筛选的清单、可点选节点的执行流程图。Agent 通过只展示数据的 `lake_visual_report` 工具整理已有事实；工作流执行轨迹默认收起，AI 分析保存的输出后展示实际巡检数据；执行完成不代表业务健康。单步骤使用紧凑状态行，多步骤依赖才显示流程画布。图形化数据经过字段/大小校验和脱敏，随会话事件保存，桌面及 Web 可回看；模型上下文保留报告事实。图形化结果后的长篇分析默认折叠；旧长回答可点“转为图形化”，仅整理已有资料。没有健康检查的数据标为待确认，不能因进程运行就当作健康。展示工具的参数错误会以补正提示返回模型，不中断整轮；执行、授权、取消或保存错误仍保留失败状态。旧版仅含执行步数的报告收为执行详情，不折叠实际分析；已保存执行轨迹存在时去掉重复报告。旧报告格式错误可点“重新整理结果”，只使用既有数据和保存的运行记录，不重新执行工作流或命令。

报告通过 [json-render](https://json-render.dev/docs/catalog) 组合动态界面。Agent 可在同一份报告中提供可选的 `ui.root/elements` 布局，将指标、图表、异常提示、清单和流程放入网格、卡片、标签页或折叠区域。组件目录限定为 `Stack/Grid/Card/Tabs/Accordion/Metric/Chart/Finding/Table/Flow`，数据组件引用已校验的报告字段；标题、结论、范围和依据仍由报告外框展示。布局必须覆盖全部报告数据，最多 64 个元素、8 层嵌套，不接受脚本、HTML 或执行动作。未提供布局的旧报告自动获得默认布局；历史布局无效时也保留事实并回退。标签页支持键盘切换，切换时保留清单筛选状态，窄窗口自动调整列数。布局随会话持久保存，桌面和 Web 使用同一组件目录。

聊天进度按实际工具事件展示：列出/读取/搜索文件、编辑、新建、删除、多文件修改、检查点保存和恢复、代码状态与差异、命令、浏览器、数据库/Kubernetes、脚本和工作流操作均使用具体动作状态行。代码专员内部操作同样显示，附带实际路径或目标；patch 区分修改、删除和混合操作，远程写入区分新建和编辑。完成后继续保留，相邻已完成的文件读取、变更、搜索和命令可合并为一行，展开后查看逐项目标、状态和耗时。主 Agent 的工具前说明与活动按顺序交错。上下文压缩成功后即时显示“上下文已自动压缩”。失败、取消及未知结果分别展示；已结束或重开的历史会话不会把未确认结果标为完成，也不会永久转圈。桌面实时通知和 Web 回看共享动作目录与事件转换逻辑，新增内置工具须通过动作目录覆盖测试。
