Lake v0.3.32 · macOS Apple Silicon

- 修复 Pilot 状态岛被历史暂停任务覆盖的问题：新一轮专员工作完成后正确显示“已结束”，只有准确属于当前会话和轮次的暂停任务才显示“已暂停”。
- 恢复执行和等待确认时优先显示真实活动状态，保留当前任务的暂停、其他专员并行执行及断线重连提示；不修改历史任务、审批、操作或验收结果。
- 沿用 0.3.31 的 Pilot 统一权限和简短最终总结。macOS 继续内置签名 TypeScript 运行时，无需安装 Node，仅提供 Apple Silicon 包。

## 已知范围

本版并非旧版功能完整替代：附件/图片、上下文压缩/回退和文件恢复、部分 Kubernetes/旧工具适配、工作流运行与日程、完整安全恢复及其他平台仍有未完成项；准确同轮补充协议尚未接通。保存的配置不代表能力已经实现或连接成功。完整列表及分阶段证据见 [TypeScript 说明](https://github.com/Clean-Lakes/Lake/blob/master/runtime/typescript/README.md) 和 [等价矩阵](https://github.com/Clean-Lakes/Lake/blob/master/runtime/typescript/parity.json)。

新范围的记忆积累/使用默认关闭，旧 Go Memory 不自动导入。旧安全策略或恢复状态不兼容时继续保留原限制。取消历史命令锁不改变当前权限、SSH 信任、停止、Plan 或明确只读范围；新命令可能再次产生相同命令的实际效果，执行前仍应依据当前目标和结果判断。

## 下载、升级与回退

仅提供 macOS Apple Silicon（M 系列）arm64 ZIP、DMG 和各自 SHA-256，要求 macOS 13.5+；不发布 Windows 包。沿用 Lake Local Development Code Signing 持久证书，尚未使用 Apple Developer ID 公证。

升级前结束当前操作并备份自己的 Lake Home。自动更新先退出旧后端，在准确生产 Home/data 以不启动任务的模式准备独立 TS 数据库，最多等待 120 秒；准备失败或新 UI 在 45 秒内未就绪时恢复旧应用。原数据库不改写，未知操作不重放。

首次手动启动的准备阶段可能需要时间。需要回退时先正常停止当前内核，再使用备份的兼容旧应用；不要删除安全记录或混用 Dev 数据。TS 新会话不会反向同步到 Go；回退后若两边产生分支历史，需核对后处理，不能直接覆盖或盲目重新迁入。安全迁移已收尾的数据不能降到不支持该记录的版本。

从 0.3.27 或更早客户端自动更新时，执行的是旧客户端携带的安装器，仍受原 45 秒总就绪窗口约束，不能提前获得新版的 120 秒准备阶段。若首次迁移较大导致旧安装器回退，请保留备份并改用本版 ZIP/DMG 手动安装；本版安装器的单独准备与回退测试仅证明从本版开始的后续更新路径。
