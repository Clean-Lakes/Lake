# 聊天文件附件

在聊天区域拖入文件、向输入框粘贴文件，或点击输入框下方的“＋”选择文件。ZIP、TAR、安装包、文档、配置、未知类型和空文件均可作为普通附件保存。每个普通文件最多 512 MiB，每条消息最多 8 个普通文件；符合条件的图片仍可使用原有图片预览。

附件上传到当前 Dev 或 release 自己的数据目录，按项目和会话隔离。二进制内容不进入模型上下文。发送后的附件名称保存在聊天历史中，待发送队列和服务重启也保留文件引用。移除草稿中的附件只是不随该条消息发送。

示例：

> @测试服务器 把 deployment.zip 传到 /opt/releases/app-v2.zip。先检查压缩包目录，确认没有越界路径或链接，再解压到新的版本目录。说明部署步骤，完成后检查服务和健康接口。

Agent 使用 `inspect_attachment` 检查元数据、ZIP/TAR 目录或有界文本预览，使用 `stage_attachment` 将原件传到明确的本机、SSH 主机或 Docker 容器路径，然后通过现有命令和文件工具完成解压、部署及验证。目标父目录须已存在；创建目录可以先使用现有命令工具。其他压缩格式由目标上相应的解压工具处理，并先检查完整目录。

传输会校验 SHA-256，默认拒绝覆盖目标文件。覆盖需要显式指定，传输统一使用会话权限中的“静默修改文件”：开启后附件直接传到明确目标，关闭时才确认本次传输，不单设上传权限。“静默执行命令”不能代替文件写入授权；解压和部署命令仍遵循命令权限。上传、选择文件或文件内说明都不会自动授权部署或执行。中断后结果不明的操作保留记录，不会自动重新派发。

文件夹请先压缩。大小超过图片预览限制、模型不支持识图的图片也能作为普通文件用于传输。资源连接导入仍可使用文本附件，并由明确的“导入资源”请求触发。
