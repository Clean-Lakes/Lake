# 旧策略资产体系完全退出

2026-10-29，基于 develop。取代 C4 后保留的人工资产应用与 N1 承接适配。自然记忆仍是实验功能。

## 行为

- 所有旧资产停止注入。删除 Engine 策略 provider、选择/撤销适配器和旧实验执行兼容入口；模型请求只保留当前规则、自然记忆、项目记忆和 Skills 的既有接点。
- 移除「历史资产与兼容管理」、人工编辑/审核/采用/晋升、候选/实验和 N1 承接 UI/API 客户端；移除相关无生产调用的仓库方法、控制器和 HTTP 处理器。用于构造真实旧版数据与验证历史格式的写入/读取辅助代码仅在 `_test.go` 中，不进入产品二进制。
- 认证与项目可见性检查后，旧策略所有 HTTP 方法均 410；N1 legacy/preferences/changes 包含旧版本读取和撤销也 410。拒绝发生在正文解析和幂等回执重放之前。
- 新自动形成、整理、压缩捕获、formed-preferences/formed-changes 与独立 recall 开关不改语义，不继承旧 consent，不补扫或转换历史正文。

## 数据迁出

旧资产迁出活动记忆，进入本地档案。格式 v7 在单个 SQL 事务中添加 `legacyAssetArchive`（准确原 assetId/scope/revision/时间）和 `legacyAssetSettingsArchive`（原设置完整行），再更新策略 schema marker/hash。已有库先生成权限受限的升级备份；原 v1～v6 SQL/hash 保持不变，DDL 失败全部回滚。启动恢复事务随后关闭全部旧应用/学习/纠错开关，重启幂等，不改自然记忆开关。

保留原表承载正文和关系，避免破坏原引用或复制一份绕过来源撤回的正文。目录里的 revision 是退出时版本，原版本、绑定、条件、关键词/有效期、审核/拒绝、晋升依赖、N1 映射、事件、回执和实验/用量账本都是审计数据。所有状态均归档，不只选择曾采用的偏好；不自动生成新自然偏好或 Skill。

`lake memory export-retired-assets --home PATH --output FILE` 从只读连接的一致事务快照导出上述旧资料，输出带 `runtimeUse:false`，文件仅属当前用户，目标必须不存在。不启动 Store/后台任务，不访问供应商。表集合由原 DDL 静态允许清单决定，不导出模型设置、SSH 凭据或新自然偏好。来源撤回后的导出不会复活已清理正文。已导出文件和离线备份由用户管理。

## 必须保留的边界

| 保留项 | 原因 |
| --- | --- |
| 原 SQL/hash、准确版本和来源/tombstone | 解释历史、完整迁移、防止恢复已撤回正文 |
| 来源删除、项目/资源归档的派生内容清理 | 旧正文退出后仍需遵守用户删除与原项目权限 |
| 作业/模型派发身份、原请求 hash、结果未知与用量预留 | 不将未知改为未执行，不重发、不退款 |
| ADK 真实操作、审批和未知操作账本 | 退出提示词功能不能绕过实际工具授权和核实 |
| 历史纠错卡及报告解码结构 | 可读审计，展示真实未知结果，无继续执行入口 |
| 当前自然记忆共用的范围、严格 JSON、事务和 hash 支持 | 是新记忆的有效依赖，不能按旧文件名误删 |

旧 API 的项目鉴权不会因返回 410 被省略；导出是本机拥有者显式执行的全 Home 私有备份操作，不是向其他项目开放旧正文的 Web 接口。

## 验证与回退

使用签名后端直接运行 Lake Dev，不打包、不发布。Windows 只做本机交叉编译；原生 WebView2/ACL 验收本次仍未授权执行，不将编译通过等同原生通过。更新相应原生测试，使下次授权验收检查入口不存在和旧 API 410。

旧版应在任何恢复写入前拒绝 v7。回退仅使用升级前备份的隔离副本验证，不能将旧库覆盖最新任务、撤回和未知账本。具体本次执行结果记录在[验收记录](../validation/legacy-asset-exit.md)。
