# Lake Memory：N4 压缩前增量捕获

N4 从 #113 合入后的 `develop@8bd2c60be18ac4872e57afc8389d93f8ecbf72e7` 开发。Lake Memory 是记忆组件；捕获来源、后台提炼和回答时使用是三个阶段。本阶段补前两者之间的压缩交接，不开放 N5 的新偏好召回，不重启旧策略执行器，也不开启运维 V2 门控。

## 来源与压缩入口

接受真实用户轮次时登记有界宿主来源，保留实际消息 ID、根轮次、原话、原模型身份、项目/资源绑定、原同意 epoch 与时间。只有新自动记忆已主动开启时才使用 N4 增量捕获；原项目记忆开关本身不授权额外压缩提炼，单独开启旧项目记忆仍走原终态链路。N4 所有派发共用 N3 的项目/Home 日上限。只登记已获同意的新来源；没有宿主消息 ID、忽略记忆、Plan、子代理或关闭采集的当前来源不登记。不会在首次开启或升级时扫描旧历史补授权。

工具结果只在执行器返回时登记调用 ID、原始结果 hash、有界片段、实际完成状态与时间；Schema 2 继续要求原有受信证据上下文。failed/unknown/running、未经完成登记的摘要内容和普通 MCP 文本不成为成功操作证据。用户原话仍只是用户陈述，不因为工具或模型复述而升级为已验证状态。

共享 `Engine.compact` 在确认达到阈值或收到手动压缩后、任何模型历史投影覆盖之前捕获增量。因此自动摘要、手动摘要、模型切换/恢复触发的维护、直接工具预览、官方 ADK SummarizeEvents 以及摘要失败后的预览恢复共用同一捕获点。低于阈值的无变化 SDK 回调不触发捕获。

本次捕获使用登记的真实来源，不读取生成摘要作为新证据。清空、回滚及手工恢复历史不产生学习授权，并撤回尚未交接的对应捕获快照；已保存记忆仍走各自的撤销/遗忘流程。旧版本中没有登记信息的历史不凭文字相似度补造消息身份。无宿主消息 ID 的外部 CLI 调用继续沿原终态接口工作，不宣称具备 N4 的中途捕获。

## 持久增量与背景处理

继续使用唯一 memory outbox、N3 队列和 worker。捕获本身没有模型请求或工具调用。轮次结束和压缩按相同登记记录生成增量：用户原话最多登记一次；后续只交接新的已完成调用 ID，保留原观测时间。稳定快照 ID 来自原根轮次、真实消息和本次证据集合，与压缩次数/摘要文字无关；空列表规范化避免序列化后身份漂移。

采集进度只表示已进入持久 outbox；成功处理仍由 N3 事务/coverage 决定。一个来源若已形成偏好，后续证据区间不能再次运行旧更正或将新的 pending conflict 标为解决；独立新事实仍可按原权限提交。真实的新用户消息仍可合并同义内容或明确更正。

前台新请求和手动压缩优先。通知只登记待交接的会话身份，worker 在空闲后交接和提炼；模型/次数/重试预算继续沿 N3。应用关闭时不运行额外服务。后台恢复只使用登记记录和已有 ADK 迁移索引，不遍历对话内容发明新来源。

## 有界与缺口

- 最多八个待交接轮次，登记原话总量在入队时检查 128 KiB；单条原话超过 64 KiB 不裁成新的授权。
- 宿主结果登记全会话最多 64 条，每条片段最多 2 KiB；一个快照最多 24 条、24 KiB 证据，总快照不超过 128 KiB。
- 沿用最多 20 条 outbox。满时保留登记及未覆盖尾部，空闲交接腾出空间后继续处理，不把入队失败当完成。
- 片段裁短、登记上限或不可恢复遗漏保留明确 gap；片段可供受限提炼，不声称覆盖全部原始输出。原始会话/操作记录继续保留。
- 可选来源检查/捕获失败不改变压缩原有的成功、失败、取消、审批或未知操作行为。短暂来源检查失败留待后台重试；恢复后解除暂时提示，不锁成永久额度错误。真实会话和原 canonical 写入失败仍遵循原错误边界。

界面使用“部分来源尚未完整采集”的非阻塞状态，不把任务改成失败。已经截断的原始尾部不会因为更新整理时间而成为完整观测。

## canonical 恢复与撤回

在既有 ADK projection 增加可选、独立版本的 `memory` 信封，包含 outbox、来源登记、准确 ACK、证据上下文和最近输入。旧信封缺失时保留已有缓存兼容；未知版本明确拒绝解析。旧 SQL、schema/hash 和操作账本不变。

捕获先进入持久来源交接，再替换模型历史；终态使用原 canonical 写入。启动仅对业务会话仍存在的既有 ADK 迁移索引恢复丢失的缓存，跳过已删除业务会话，重交接依赖 N3 Store 幂等，不新增模型或通知。ACK 保留准确 ID/hash 回执，不为后台确认占用前台会话；加载前一份 projection 时过滤准确本地回执。若缓存及最近 ACK 一起丢失，可重复交接原快照，Store 的来源覆盖保证不重复派发/提交，而不是把未知成本退款。

新 materialization、模型派发和事务提交都重验来源/范围/同意。关闭、遗忘、删除或 source hash 变化后不凭序列化配置重新授权；后台清理无效的派生待办正文。遗忘会登记来源会话的异步清理，原对话原文并不因此被当作已删除；删除对话继续走原删除权限。全局内容的来源隐私继续沿 N3 管理接口。

验证与实际限制见 [N4 验收](../validation/natural-memory-compaction-n4.md)。原始 P/R 文档只作为历史设计；本阶段不宣称学习提高任务收益。
