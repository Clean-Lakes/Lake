# N2 自然形成与更新提示

N2 在 [N1 管理基础](natural-memory-foundation-n1.md)上新增自然表达偏好的采集、持久化、变更提示与撤销。保持实验、默认关闭；用户全局和项目各自明确开启，旧学习/纠错/项目提炼设置不构成新同意。当前阶段只积累和管理新偏好，尚不向回答注入；新召回在 N5 交付，语义批量整理在 N3 交付。

## 来源与范围

- 完成轮次沿用现有 MemoryOutbox → projectMemoryTurns/Jobs → 单一 memory worker。前台仅产生有界快照，不等待提炼、扫描记忆或创建另一模型/工具循环。普通无信号文本不新增自然偏好提炼；信号只作廉价筛选，不能单独授权写入。
- 快照的 natural 同意记录、SourceMessageID、epoch、策略版本由宿主配置。只接受实际业务用户消息的完整一致文本；源消息须晚于本范围本次开启时间。关闭/重开、项目删除/归档、源消息变更、忽略本轮、Plan 和子代理都不能借旧上下文新增。
- 单次无工具语义提炼最多形成一项明确长期的表达/报告偏好。正文必须是当前真实用户消息中含范围和长期意图的准确连续原话；不能用助手复述、引用/代码块/日志、工具输出补授权，也不凭固定“记住”口令写入。无法确定时 ignore/review，均不保存正文或要求用户逐条审核。
- 项目偏好需明确当前项目范围；全局需明确跨项目范围，并单独开启用户全局自动记忆。全局内容仅表达偏好，不导入项目事实；宿主另拒绝带当前项目/资源名称的正文。全局视图隐藏私有项目、会话、消息身份和原始来源，但仍依赖原消息可用性。
- 环境事实、执行方法、安全/权限修改不属于本提取器。原直接保存/遗忘工具的授权边界保持不变。成功直接写入避免第二份表达；失败的直接保存尝试不否决独立获得同意的自然偏好提炼。

## 共享后台与事务

现有项目记忆提炼同时开启时，使用同一次 completion 的 preference/legacy 两个严格 JSON 输出；原来源、项目设置和版本检查保留，偏好与项目知识在同一 SQLite 事务结算。准确相同正文不能同时存到两个表示。自然偏好关闭的轮次仍沿用原提炼路径。

自然偏好请求复用现有 worker、模型适配器、租约、退避和终态。前台新请求立即取消辅助请求并撤销租约，不等待网络结束；最后提交还检查前台状态、准确快照 hash、lease token/期限、源消息与当前同意 epoch。

单任务沿用最多三次失败尝试；自然偏好派发在 provider 调用前记账，每项目 UTC 日最多 20 次，取消/中断/未知响应不退还预留。没有绕过上限的自然任务手动重试；达到限制保留 blocked 状态，任务本身仍可正常完成。队列上限每项目 100，快照有效期七天。N3 继续实现增量合并、水位、语义冲突和预算等待等完整队列契约；N2 不声称已经交付这些能力。

## 存储与演化

业务库新增独立 naturalPreferenceMeta v1/hash，N1 marker/hash 保持不变。升级前一致性 0600 备份、DDL/marker 事务及未知 hash 拒绝，与旧迁移/恢复写入之前的校验保持分离；不建立第二个人知识库。

- Entries：scope/topic 的当前 revision/state，唯一范围内主题。
- Revisions：不可变 parent、真实来源身份/hash、quote hash 和时间；Content 独立存放可遗忘的正文。
- Changes：保存/明确更正/撤销/遗忘的前后准确版本与来源；不复制正文。Acks 持久记录用户收起的提示。
- Suppressions：无正文的同源去重/防复活记录。Dispatches 保留每次预留、结果及已知/未知用量；重启不归零。

模型须复用同范围已知 topic，更正须明确表达替换及准确当前 revision。不同正文没有明确更正时拒绝覆盖；未完成的冲突语义整理留给 N3。列表/索引有界，不保证 N2 已消除所有语义重复。

撤销产生新 revision，恢复对应旧正文或变为 undone，保留历史；更晚修改、撤回来源或源不可用时返回冲突，不覆盖当前版本。同源被抑制，不能靠重试/恢复立即写回。撤销/遗忘后新的真实明确指令可重新形成同主题偏好，但须晚于撤回，不借旧来源恢复。遗忘删除全部正文历史与相关待办快照，保留无正文墓碑；删除源会话同样清除依赖正文与待办，并使全局派生不可读。

新偏好不创建 strategyBinding，不与 N1 承接/原 resolver 竞争；不开启运维 V2 门控。

## API 与界面

保留 N1 路径；新增全局 `/api/natural-memory` 和项目 `/api/projects/:id/natural-memory` 下：

| 路径 | 用途 |
| --- | --- |
| `GET/PATCH settings` | 新同意、独立 revision/epoch；项目 true 不开启全局，V2 测试模式仍拒绝开启 |
| `GET formed-preferences[/:id]`、`GET formed-preferences/:id/revisions/:n` | 自然偏好和准确历史版本，来源重验 |
| `POST formed-preferences/:id/forget` | CAS 遗忘并清正文 |
| `GET formed-changes[/:id]` | 不可变记录、准确前后正文/范围及可见来源 |
| `POST formed-changes/:id/undo` | 准确 revision 的事务撤销 |
| `POST formed-changes/:id/dismiss` | 持久收起提示 |

延用既有认证/Origin、宿主项目检查、严格 JSON、去敏和幂等身份。写入成功后才随原会话快照/event 提供“已更新项目/用户偏好 · 查看 · 撤销 · 收起”。提示不打开对话框、不改变前台任务状态；无变化/失败不假报更新。查看在用户点击后显示准确前后正文和来源可用性。

设置入口为“策略资产 → 自动记忆 · 实验”，继续保留 N1“记忆内容承接”。关闭停止新增，已保存内容保留；原项目记忆/人工资产使用仍由原开关控制。新偏好使用控制与整体入口收敛在 N5 交付前，不伪装为已接入回答。

## 验证与边界

冻结的 60 个自然意图案例和三轮判据不变。独立偏好与组合提炼分别实测，报告采用相同生产 prompt/parser/宿主来源检查，保留漏识别和 ignore/review 差异；这不是全部 V2 事实质量验收，也不保证所有模型效果。

回归覆盖同意、准确来源、事务回滚、scope、撤销/遗忘、来源删除、前台抢占、派发预留、租约、旧工具、Plan/忽略、接口和提示。真实 Dev 使用签名快速启动，不制作安装包。兼容回退仅在隔离两库副本验证；不以旧库覆盖真实新任务或撤回记录。Windows 原生验证/CI 需另有环境和授权。

实际代码 SHA、全量检查、两种真实模型三轮评测和 Dev/升级回退记录见 [N2 验收](../validation/natural-memory-formation-n2.md)。
