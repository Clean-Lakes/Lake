# R4：条件匹配、请求清单与经验反馈

基于 PR #80 合入后的 develop `c8cb35c`。R4 提供可解释的本地选择与反馈，不宣称收益成立；R5 的同模型配对验证仍待推进。PR #67 保留。

## 不增加模型检索的选择契约

reuse 是不可变版本条件：keywords（至多 8 项、每项 2 字符至 64 UTF-8 bytes）、general（仅用户偏好/报告要求）、validUntil（RFC3339 UTC 截止）、needsReview。前台使用真实根任务的有界 UTF-8 前 8 KiB，不由模型/工具文本提供资源、标签或权限；英文词有边界匹配，中文按显式子串。先过滤来源、权限、场景/资源/宿主标签、有效期与复核状态，再按匹配关键词数量、用户优先级、稳定 ID 排序。通用偏好是显式选择，关键词方法优先。最多 3 条，保守计完整 JSON 封装和固定说明，总额不超过 4,096 bytes；不足则省略，不截断规则正文。

相同/换行差异正文去重；同互斥组的多个相关成员全部排除，不自动选赢家。已有上下文、加载的 Skill/记忆包含同正文时避免重复注入；不更改同名 Skill 发现顺序，不写回源文件。系统不做任意语义冲突推断，当轮要求/固定权限继续优先。可选资产在进入上下文前不可用时降级；已使用内容无法确认来源/权限时仍按原规则停止，不能保留已撤回的上下文继续操作。

方法类版本由宿主保存模型名称/协议和内置目录 hash（不含 URL/密钥/头部）；实际执行模型/目录变化时标记需复核并排除。预算/思考参数变化不会误判模型升级。相同名称下的供应商静默升级、任意服务软件/环境版本不能自动检测；通过明确截止/待复核/停用管理。旧偏好保留原明确采用语义，旧方法没有结构化条件则待复核。保存新版本记录当前宿主指纹，仍需明确采用；导入不信任外部指纹或验证声明。

日常任务按上述规则检索；显式隔离 A/B 快照仍测试准确指定版本，不能把 B 臂变成没有资产的对照。隔离执行仍受封装预算、权限、来源与固定评分约束。

## 使用与反馈

已有 PromptManifest 是持久权威记录，不增加前台学习写入或另一套日志账本。清单增加可选 assetSelectionReasons（准确 ref、reason、匹配数量），选择冻结到轮次，实际请求再按上下文去重/预算筛选。清单记录 prepared，不代表网络派发成功、模型实际使用或收益；反馈是用户观察，不能自动升级验证等级。

当前项目 `GET /usage` 返回最近 50 个会话选择；`GET /usage?sessionId=&before=` 在宿主核对项目后读取运行时自己的已登记 artifacts，20 项分页，不回传正文、关键词、消息或私有项目来源。使用 runtime history migration 映射限定到真实会话；清理业务会话后不能通过已知 requestId 读取。可选日志读取失败只影响设置页，主任务不等待它。

`POST /usage/:requestId/feedback`：sessionId、准确 ref、expectedRevision、outcome=helpful|neutral|harmful|not_used、suspend。必须在该项目/会话真实准备清单的 selected 列表里；伪造请求/版本或跨项目拒绝。反馈按每请求/资产版本 CAS、幂等保存。suspend 只在 harmful 时允许，重验当前有效绑定仍为此准确版本，建立项目停用覆盖，不改全局或其他项目；换版本后不能误停新版本。明确停用会取消当前项目已注入旧内容的在途上下文，资源操作不重放。普通反馈不更改开关、采用或学习状态。

## 存储和兼容

策略 v6 在同一业务 SQLite 增加 strategyReusePolicies（不可变版本条件及宿主指纹，可遗忘）和 strategyUsageFeedback（项目内准确使用反馈，仅标识/hash/枚举）。复用既有采用、来源、撤回、不可变版本与 PromptManifest；不新增 ADK 主 schema。撤回时复用条件随派生私密副本清理，反馈/准确请求标识保留审计。迁移前 0600 备份，DDL/标记同事务，未来 schema 在恢复写入前拒绝；旧程序只能在隔离的兼容副本回退，不能覆盖当前账本。
