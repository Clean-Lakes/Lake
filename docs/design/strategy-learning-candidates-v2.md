# P4 真实来源与候选学习

后续 P5 的快照评估与 v3 增量迁移见 [P5 说明](strategy-learning-experiments-v3.md)；本文记录 P4 交付边界。

P4 在 P3 可见资产之上交付 T16–T19。入口仍为「工作区 → 设置 → 策略资产」：全局总开关及学习子项是上限，项目可进一步限制。默认关闭；开启只影响之后开始的轮次，不扫描历史补学。自动纠错、效果评估和 A/B 对比仍属于 P5–P7。

## 采集与来源

普通 Web/Desktop 的 core、terminal2、db-query-editor 主轮次可学习。仅采集完成/失败终态中的明确纠正信号或真实配对工具失败；取消、审批挂起、隔离角色、SRE 协调器、工作流及辅助提取不产生学习来源。明确纠正信号使用保守前缀：纠正一下、请纠正、更正一下、请记住、以后请、以后不要、下次请、下次不要，以及 Correction:、Please remember、Next time。普通负面语气不作为触发依据。

Web 在普通消息及队列派发时把真实 messageId 作为不可从 JSON 设置的宿主字段传入 Engine。Engine 保存带用户消息 ID、hash、项目/会话/轮次、开始/结束时间、profile、模型身份及授权 generation 的 outbox。用户原文最多 8192 字节，脱敏后的最后助手回复最多 8192 字节；至多 24 个工具证据仅保留真实 call ID、工具名、状态及结果 hash，不保存原始工具输出。unknown/未验证证据不证明成功；恢复时补出的 unknown 结果不算真实工具失败。队列快照最多 32768 字节，每会话最多 20 条待移交记录。

Web 适配器按精确消息 ID 检查宿主真实项目、会话、用户消息文本及 hash，使用解析后的时间而非 RFC3339 字符串排序核对先后；对当前已配置模型/终端秘密再次检查，随后登记 task_outcome 来源。轮次唯一键为 sessionId + turnId，固定自动幂等键使崩溃后重放不能重复排队。保存和排队前重新核对 generation：关闭再开启不会补学旧 outbox。正常运行在终态移交；启动时重试持久 outbox，非暂态错误安全跳过，不改变原回复。用户也可以明确提交当前项目真实 user message ID，登记为 user_correction；HTTP 不接收自报快照、哈希、actor、scope 或验证等级。

## 一次无工具提取

独立后台 worker 等待前台空闲，并优先等待同轮次已排队的项目记忆提取结束，再读取来源。使用既有 Engine.sideCompletion 和共享模型并发槽，最多一次无工具、无会话模型调用；不新增模型/工具循环，不启动 ADK 子任务，不写回原会话或触发递归学习。

自动轮次使用原模型身份；用户显式登记消息没有原模型身份时使用当前模型。无法解析模型时停止，不静默换模型。一次调用最多 60 秒，受任务总过期时间、MaxOptimizationRequests 和 MaxAdditionalTokens 限制；输出上限取模型上限、4096 和剩余预算的最小值。预算按输入 UTF-8 字节数加固定余量保守预留，并记录 provider 实际 usage；未知用量保持未知。这里只消费一次提取请求，不实现 P6 的多轮优化预算循环。

输入包括经过核对的来源、目标资产的精确旧版（仅修订时）及当前启用的项目记忆索引。原轮次选择忽略项目记忆时，不读取索引或进行记忆正文比较。提示词明确将来源当作不可信数据，只提取可复用偏好/工作方法，不提取事实记忆、临时状态或未经证实的成功。索引超过 8192 字节时省略，不发送半截文本。

结果必须为严格 JSON：schemaVersion=1，candidate=null 或单个含 title/kind/body/reason/sourceIds 的候选。拒绝重复 key、大小写别名、未知字段、额外文档、错误类型、伪造来源 ID 和超长正文/理由。正文上限 4000 字节，理由上限 1000 字节，来源最多 8 个且必须来自本任务。模型不能指定范围、适用 profile、actor、验证或采用状态。

落库前核对有效 lease、过期时间、generation、来源及目标资产 CAS；profile 来自宿主快照，范围固定当前项目，verification 固定 single_observation。模型理由保存在任务结果中，血缘关联所有真实输入来源；模型实际引用子集另保留在结果 sourceIds。候选可在资产列表检查、编辑并明确采用，绝不自动绑定、全局推广、写项目记忆或覆盖正式 Skill。

## 恢复、撤回与去重

strategyJobs.runtimeId 稳定关联一次 strategyProposalRuns。调用前原子写 running 与请求摘要；摘要覆盖提取版本、固定提示词、输入、模型身份和输出/上下文预算。运行表只登记辅助模型调用状态与 usage，不替代资源操作账本。

- 未派发的 lease 可在重启后回队列；最多领取 3 次。
- 已派发但没有已保存结果：重启标为 unknown，任务停止为 interrupted，不自动重发。用户检查后可用新的显式请求重试。
- 已保存严格验证后的结果：恢复仅重试业务提交，不再调用模型。业务提交与资产/血缘/完成状态同一事务；临时提交失败保留结果，释放 lease 供恢复。
- 已提交结果：重复扫描不产生第二资产/版本。
- 关闭开关、撤回来源、项目/版本变化或取消任务会阻止迟到结果发布；运行中的调用每 250ms 检查 lease，并响应取消。即使取消清除了 lease，原调用仍可用受保护的 lease hash 登记 usage，不能重新授权发布。

相同来源集合、目标版本和 generation 的活动/成功任务复用任务 ID。新资产对相同来源集合的既有候选、已有全局/本项目资产正文及启用的项目记忆正文做确定性去重；正文比较只统一 CRLF 和首尾空白，不改不可变原文/hash。重复或无候选记为成功 no-op，原因可见。语义近似正文的识别仍依赖提取提示词，当前不承诺语义向量去重；不会删除/覆盖已有记忆。

撤回来源使快照正文和关联模型结果正文清空、取消未完成任务、使来源资产停止应用，保留不含原文的 hash/血缘。通过业务接口删除原会话时，同一事务清空该会话来源快照、关联提取结果并取消未完成任务；删除候选资产也清空生成它或修订它的提取结果。真实消息变动时，每次读取/完成都会重新判为不可用。来源历史引用不建立阻止普通会话删除的外键。此操作撤回学习来源，不删除原会话历史或已由用户明确另存的手写资产。

## 接口与界面

仅 `/api/projects/:projectId/strategy` 提供学习接口，沿用现有同源认证。变更需 Idempotency-Key；新增目标 expectedRevision=0，修订沿用精确版本 CAS。

| 接口 | 用途 |
| --- | --- |
| GET /sources | 分页来源，真实用户正文、终态/profile、工具证据引用与可用性 |
| POST /sources | 明确登记真实用户 messageId |
| DELETE /sources/:id | 单向撤回来源，幂等，无恢复/授权扩张 |
| GET /proposals | 分页任务状态、原因、用量、结果理由与资产引用；不暴露 lease |
| POST /proposals | 从至多 8 个真实来源排队，可带精确目标修订 |
| POST /proposals/:id/cancel | 幂等取消，不能重开已完成任务 |

列表按创建时间倒序，单页最多 50；界面每 5 秒刷新当前学习列表，翻页期间暂停自动刷新以保留位置。生成后手动「刷新学习与资产」查看候选；新候选不覆盖用户正在编辑的正文。支持来源选择、明确登记、撤回、取消和理由/用量展示。界面不在原对话中刷学习通知。

## v2 迁移与回退

P2 `strategy_schema.sql` 字节保持不变；新增 v2 learning 表和独立不可变约束。版本/hash 在任何旧迁移或重启写入前验证。已有 v1 库先 VACUUM INTO 私有权限的 `lake-web.before-strategy-v2-<id>.sqlite`，再在事务中增加学习表及替换仅允许 version=1 的 schema marker；失败整体回滚。v2 后重开不重复备份；未知版本/hash 拒绝打开。

P3/P2 的版本保护会拒绝 v2。需要回退应用时先退出 Dev，保留当前 v2 数据、ADK/资源操作账本及凭据，使用升级前备份建立另一隔离 Home 的兼容副本，仅在确认旧数据语义后验证；不得用备份覆盖升级后已经产生业务操作的当前库。关闭学习可立即停止此阶段能力，无需回滚数据。

本阶段来源快照保留到用户撤回/业务删除；尚无 30 天定期裁剪或历史消息浏览器，手工登记需真实消息 ID。SQLite 历史页/WAL/备份按私有数据管理，不声称物理擦除。

本阶段仅在本机隔离 Dev 验证，不发布生产版本。验证见 [P4 记录](../validation/lake-strategy-learning-p4.md)。
