# R1：日常任务与策略在线实验隔离

实施基于 `develop@46fd6daa`，承接[用户资产与经验复用计划](../../plan/refactor-user-assets-and-experience-1.md)。主机检查修复与快速 Dev 启动分别由 PR #69、#70 交付；本阶段只取 PR #67 的记忆/学习边界修复，不包含在线工具裁剪、来源枚举或预算收尾。

## 日常路径

日常任务仅按独立的应用/学习开关工作。未启用本版本在线实验时，配置中的 `StrategyCorrectEnabled=false`，不注册 `revise_readonly_strategy`，不预留策略在线额度、不创建观察/修订控制器或纠错停止卡。模型仍能在原工具权限、审批和操作账本约束下处理错误并选择下一步。

资产解析在尚未选入任何资产时发生错误，冻结空选择并记录 `asset_service_unavailable`，继续普通任务；敏感资产首次发现时整批省略并记录 `sensitive_content`。这些诊断不包含原始错误、正文或凭据。主会话保存失败和 context 取消继续作为真实错误传播。

已有选入资产时必须持续证明准确版本和来源可用：来源撤回、权限变化、绑定失效或无法重新核实，停止当前上下文，不自动重放操作。只有学习设置发生变化且准确资产选择不变时，保持冻结版本和本轮清单，允许任务继续。空选择的轮次也不会在中途引入新采用的资产。

HTTP 只修改学习开关不取消普通轮次；关闭正在应用的能力、撤回来源/资产及改变活动实验设置仍按边界停止。没有使用资产且没有开启实验的轮次，不因策略资产操作统一取消。候选生成仍由宿主提取；明确纠正不等于授权写项目记忆，记忆工具拒绝不创建或闭合资源纠错缺口。

## 旧同意迁移与兼容

- 当前在线实验同意版本为 `2`。PATCH 设置新增可选 `onlineConsentVersion`，只有 `onlineCorrectEnabled=true` 且版本为 `2` 才保存有效在线同意；仍需全局/项目、master/correct 等已有交集限制。
- 缺少版本的旧客户端即便回传 true，也按在线关闭保存，不阻止它关闭学习或修改应用。未知的非零同意版本返回参数错误。
- 使用设置 JSON 的 `runtimePolicyVersion=2` 标记 R1 迁移，不增加 SQL 表。启动在任务恢复之前、同一事务中处理旧 true：保存只读 `legacyOnlineConsent`（原启用值、设置 revision、epoch），清除可执行 true，递增 revision/epoch，并产生 `online_consent_retired_v2` 审计摘要。旧值不只留在文档或 UI，旧二进制读到的执行字段也已关闭。
- 没有修改 SQL schema、资产正文、血缘和既有操作账本。JSON 字段扩展随原设置存储；迁移幂等，后续保存保留旧同意记录。
- 旧设置范围内尚未派发的实验任务（含未启用在线的旧快照优化）取消，原因 `online_consent_retired`。在途/未知任务的 runtime ID、dispatchState 和待核实状态保留，由已有恢复核实与 epoch 检查阻止自动重放/失效提交，不重置预算或伪造成功。已停止的在线轮次和历史卡片保留。

## 界面与实验边界

常驻开关只展示总开关、应用和积累候选。在线同意和快照优化位于默认折叠的实验分区；在线勾选明确说明可能提前停止任务，需用户重新选择并保存。显示旧试用同意已停用及当前有效状态。隔离评估/历史报告也置于折叠入口，原历史报告和研究工具暂保留。

这是 R1 的隔离，不表示后台学习全部解耦完成：终态快照、outbox 转交、共享模型槽位和学习预算仍须 R2 改造。R3～R5 的晋升、匹配、反馈及收益验收也尚未交付，不将控制流通过称为收益成立。
