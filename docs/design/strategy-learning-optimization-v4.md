# P6 有界快照优化

P6 在 P5 的合成观测快照上实现 T24–T27：提案、独立试跑、合成修订、重新验证、共享预算、停止、持久阶段恢复及显式保存。它不增加 Python/CLI 运行依赖，不启动真实服务故障，也不把在线普通任务接入纠错。后者仍是 P7；原计划涉及真实服务故障环境和跨任务收益的完整 M2 验收尚未满足。

## 用户入口

「工作区 → 设置 → 策略资产」增加可保存的“允许隔离实验有界优化”开关，默认 false。它是 `correctEnabled` 的本期生效范围，普通对话不会据此启动修订。实验要求总开关、应用、学习、隔离优化在用户/项目有效交集中全部允许；请求不会替用户打开任何开关。

选择一个精确项目资产作为种子，一个开发场景、一个保留场景，每场 1 次配对，再点击“开始有界优化（含合成复验）”。P5 的普通 A/B 和三次配对入口保留。全局资产需先由用户明确复制成项目资产；项目、来源、模型及 Skill 权限沿用 P5。

报告展示阶段、结构化停止状态、无进展轮数、每个候选正文及修改依据、实际运行/清单/复位证据、开发/保留分组和整体成本。通过固定验证后才出现“确认保存合成候选”；用户预览后明确保存同一资产的新版本，采用仍是独立操作。

保存/清理使用页内可见的第二步确认，兼容原生 WebView；可返回报告而不执行。设置能力声明为 correctMode=isolated_snapshots、onlineCorrect=false，不表示普通任务已接入自动纠错。

## 固定搜索计划

为遵守既有最多 12 个新增模型请求和 6 个变体运行的硬上限，本期串行探索一个候选，再合成一次，不并行探索两个候选：

| 阶段 | 操作 | 运行身份 |
| --- | --- | --- |
| 0 | 默认内置策略运行开发场景 | baseline_development |
| 1 | 根据种子方法、开发任务和已观察到的实际行为提出一个候选 | 独立无工具 propose 请求 |
| 2 | 首轮候选在全新环境运行相同开发场景 | proposal_development |
| 3 | 根据种子、候选及两次开发运行的行为合成修订 | 独立无工具 synthesize 请求 |
| 4 | 合成正文在全新环境重新运行开发场景 | synthesis_development |
| 5 | 默认策略独立运行保留场景 | baseline_holdout |
| 6 | 同一合成正文独立运行保留场景 | synthesis_holdout |
| 7 | 固定检查、血缘、开发经验元数据及停止状态提交 | 不调用模型 |

总共 5 个 ADK 运行和至多 2 次辅助请求。典型每个运行读取一次观察再答复，合计 12 次请求；多工具轮、输出恢复或失败会消耗同一额度，可能在最终阶段前停止，不能加预算凑出通过结果。`maxRuns<5` 或 `maxRevisions<2` 时拒绝此固定计划，较小请求/token/时间预算可提交并在实际耗尽处停止。临时读取重试没有新增自动循环，额外传输重试上限不会被当作另一份额度。

界面 A/B/C 在此分别指开发基线、首轮候选、合成复验阶段，报告保留精确 variant 和临时候选 hash。**本搜索轨迹不是同版本 B 与“B 加纠错”的单变量对照**，不能据此声称纠错的独立因果收益。普通 P5 A/B 用于精确版本配对；更多候选、三次重复和真实服务环境需要后续独立批次评估。

## 候选与固定评估

辅助请求复用现有 `Engine.ExtractStrategyProposal` 的一次无工具 completion 和模型并发限制；所有变体仍调用 `RunStrategyVariant → ExecuteTurn → 官方 ADK`，没有第二套资源执行循环。只读私有快照适配器保留全部 P5 宿主隔离。

提案/合成只看到开发任务、种子正文、实际开发运行的公开输出、确实读取过的开发观察，以及允许引用的真实 run ID。序列化的冻结场景仅含元数据；执行前按 ID/version 重新取得登记观察，不能把反序列化后空的私有材料当作实际证据。保留任务、观察、输出、固定期望、评估分数和其他项目资料均不进入辅助输入。

输出采用严格 JSON：schemaVersion、candidate 或 null。candidate 包含 body、reason、refutedHypothesis、changes、expectedInformation、stopCondition、sourceRunIds；正文不超过 4000 UTF-8 字节，每个解释字段不超过 800 字节，来源只能是当前阶段实际开发运行。拒绝未知/重复字段、尾随文档、伪造来源、空解释和敏感内容。候选不具备写工具、权限、判据、采用或 Skill 修改权；没有可支持的改进允许返回 null。

候选临时引用为 `trial_<job>_<stage>@1/hash`，仅在本实验 child 内可解析，不是假装已经写入正式资产。正式版本保存后以正文 hash 关联这次实际试跑，报告/清单保留原临时身份。继承种子的适用条件；未实际注入候选的运行不能通过候选验证。

进展由固定检查判定：硬检查（边界、正常结束、输出结构、证据）不能退化，其他检查必须有实际增加；仅换措辞、改正文 hash 或新时间戳不算进展。第一轮提案及合成都计入最多 2 轮修订；连续无进展达到有效上限即停止，重复阶段恢复不重复增加计数。合成与种子/首轮正文完全相同时提前停止。相同意思不同措辞可能只有在试跑后才能识别，因此不会仅凭文本变化延长预算。

权限越界立即停止，不换工具绕过；固定检查确认的认证/权限阻塞、目标歧义、缺能力或 unknown 正确停止也不强行优化。运行失败、复位失败、无候选、无进展、预算耗尽、验证失败、保留集退化和结果未知都有独立终态，未运行样本保留 not_executed，不删差样本。

## 预算与恢复

业务层复用 P2 strategyJobs 的单并发、来源/资产 CAS/generation/租约，复用 P5 的整场 requests/tokensCharged 预留与结算。辅助请求和全部 ADK 请求计入同一预算；未知 usage 或崩溃预留不退款，模型价格未知。活动时间按阶段累计，当前激活还受任务绝对截止时间约束。辅助调用/每个变体另有 60 秒截止；等待用户不继续派发，不清零已消耗的额度。

每个 run、propose 和 synthesize 在入队时预先分配固定 ID。模型派发前先保存 running/请求 hash/预留；结果在独立事务中保存，阶段随后推进。重启：

- 有 running/unknown 调用：保留 unknown，停止为 awaiting_reconciliation，剩余 planned 改 not_executed；本期不尝试从供应商恢复未知模型输出，不提供重放式“继续”。
- 只有已完成结果或尚未派发的下一阶段：保存 awaiting_user，释放执行占位；用户点击“从已保存阶段继续”后才运行后续阶段。已经保存的 run/result 不重新执行，结果提交与阶段推进之间崩溃也复用原结果。
- 继续需在首次等待 TTL 内、尚有原预算、未超过原领取次数、模型/记忆/Skill/来源/资产/开关及 generation 均有效。重启不会延长等待期限；用户关闭、撤回、取消或过期后不能借继续恢复授权。
- 对崩溃期间无法准确知道的活动时间保守计入上次激活到重启的时间，上限为整场时间额度；长时间离线可能耗尽额度，不能编造停止时刻退款。已知等待期间重启不重复计时。

取消、开关和来源变化由周期 watchdog、每次请求/读取以及结果提交重验。已发出的模型 usage 仍结算，迟到正文不发布；取消不声称回滚资源效果。

## 保存、血缘和隐私

只有开发基线与合成之间出现固定检查改进、合成开发和保留结果均通过、无保留退化/缺失，且当前来源和设置仍有效，才能明确保存。保存同事务创建新修订、fixture_validated（**仅指定合成快照检查**）、来源和血缘；旧修订及采用绑定不变，不能升级为 multi_task_validated。单个开发与保留案例不证明通用有效性或统计显著性。

来源为真实 fixture_evaluation，关联 tested_by、proposed_to_fix、composed_from、compared_with；这些关系只接受真实实验调用/运行节点，普通 API 不能凭空声明。体验中的经验记录只包含开发集计数及局限元数据；不另发反思模型请求，不把保留场景写入经验或 P4 学习来源，也不把生成结果递归喂给自动学习。

清理实验、撤回原来源/本次评估来源、删除相关资产/原会话或遗忘项目记忆时，同时清空输入快照、辅助候选结果、运行产物和经验摘要；停止后的独立 ADK 目录由 P5 清理器删除。已知用量、身份/hash/状态及审计边保留。报告导出不包含共享原文、完整冻结输入、凭据、租约或原始推理。SQLite 历史页/WAL/私有备份仍需按隐私数据管理；暂无定时保留期裁剪。

用户已明确保存的正式资产正文通过资产删除单独清理；清理其评估来源会使该修订的来源不可用，不能再当作当前可验证/可应用资产使用。

## v4 兼容

冻结 v1/v2/v3 DDL 与 hash 不变。v4 仅增量增加运行 variant、优化阶段/活动/等待/保存状态表及不可变辅助调用记录。v3 升级前创建 0600 的 `lake-web.before-strategy-v4-*` 一致性副本；旧版本升级保留原兼容命名再直接事务迁移。ALTER TABLE 和新表失败时原标记/列同时回滚；未知版本/hash 在恢复写入前拒绝。

P5 不能直接打开 v4。优先关闭隔离优化停止新工作；旧程序回退在另一个隔离 Home 使用兼容升级前副本，不覆盖后续业务库或资源操作账本。验证与实际 SHA 见 [P6 验证记录](../validation/lake-strategy-learning-p6.md)。
