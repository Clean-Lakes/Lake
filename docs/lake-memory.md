# Lake Memory 使用与历史兼容（实验）

在「工作区 → 设置 → 记忆 · 实验」分别管理项目与用户全局。**自动积累与使用各自默认关闭**：开启积累不自动开启使用；停止积累仍保留已保存内容；停止使用不删除内容。明确长期偏好无需逐条审核或说“记住”，只在持久保存成功后轻提示查看/撤销。

当前明确要求优先。自然偏好只影响表达，不提供执行权限；资源事实、操作方法和历史经验在执行前仍需核实。后台整理和压缩前增量捕获不阻塞当前任务；暂缓记录不能当作已经保存或处理成功。普通会话和 Pilot 协调层可使用，专员与工作流不继承。原项目记忆/Skills 继续按自身设置工作。

## 旧策略体系已退出

旧人工资产应用、采用/审核/晋升、Skill 快照导入、N1「旧偏好承接」、候选/实验管理入口均已移除。旧正文不再进入模型请求；普通对话、编辑器、Pilot、专员和工作流都不能用旧开关或旧回执恢复注入。新自然偏好和项目记忆/Skills 按各自范围与设置继续工作。

升级到归档格式 v7 时，事务内登记全部旧资产并保存原设置，随后持久关闭旧 master/apply/learn/correct/online 开关。原正文、准确版本、适用条件、来源、采用/拒绝、N1 映射和历史审计仍保存在原表中，作为只读档案；不会自动转成新偏好、项目事实或已安装 Skill。已停用、未采用、被拒绝和复杂条件资产也只归档。

## 导出旧资产档案

本地命令读取一致的数据库快照，写入新的私有 JSON 文件：

```sh
bin/lake memory export-retired-assets --home "$HOME/.lake-dev" --output /tmp/lake-retired-assets.json
```

使用其他 Home 时显式指定对应目录。输出路径必须尚不存在；命令不覆盖文件、不打开工作台、不恢复任务、不调用模型。导出包含当前可保留的旧正文和条件，属于用户私有资料，不应提交到仓库。已导出的文件与备份由持有人自行保管、删除。

所有旧 `/api/strategy`、项目 strategy API 和 N1 legacy/preferences/changes 适配 API 在认证与项目可见性检查后返回 410，包含历史读取；不再保留旧管理接口。新 formed-preferences/formed-changes、自动记忆设置和 recall-settings 继续工作。

## 历史审计、来源撤回与回退

原 schema v1～v6 SQL/hash 不改写；v7 添加归档目录和原设置档案。原资产/版本/来源/采用/拒绝/血缘/回执/实验结果及用量账本保留，ADK 历史请求清单和纠错记录保留。历史纠错卡只展示审计，不提供继续执行；unknown/待核实仍保留调用身份与用量，不重发、不退款，也不宣称操作已经撤销。

删除来源会继续清理可撤回的派生正文和实验副本，保留身份/hash/tombstone。原表是档案正文的唯一事实源，避免再创建一份不能随来源撤回的正文副本。过去已导出的文件及离线备份不会被自动删除。

较旧二进制应拒绝 v7。回退只使用升级前的独立离线副本，不能将旧库覆盖最新任务、偏好、来源撤回或未知操作账本。详细迁移/保留边界与验收见[旧体系退出](design/legacy-asset-exit.md)。C1～C4/N1 文档是当时的阶段记录，不再是启用旧功能的操作指南。

## N2 自动形成偏好（实验）

在“记忆 · 实验”选择偏好适用范围：当前项目或所有项目，再按需开启“自动积累偏好”和“回答时使用偏好”。两个开关独立保存。已保存的偏好直接展示正文；来源/版本、修改记录和整理状态按需展开。遗忘需再次确认，取消不会删除内容。只处理开启后的真实新消息；例如“以后这个项目的报告先列证据”无需额外说“记住”。完成轮次后由共享后台提炼，持久成功才轻提示查看/撤销，不阻塞任务。关闭停止新增，正文保留；遗忘会删除该偏好的全部正文历史，撤销不会覆盖更晚修改。

自然积累、管理和使用分开控制：N3 提供有界语义整理，N4 实现压缩前补充捕获，N5 接通独立使用开关后的新会话表达偏好。原项目记忆独立使用；旧人工资产已停止注入。新同意不继承旧学习/纠错开关，不开启运维 V2。具体来源、准确版本、限额和 API 见 [N2 契约](design/natural-memory-formation-n2.md)。

## N3 空闲整理与兼容入口

相邻且同范围的待整理消息最多六条合用一次后台请求。同义偏好保留独立来源，明确更正产生新版本，含糊矛盾保留待核实；查看和撤销均不要求离开当前对话。完全相同的有效原话可本地去重，不新增模型请求。待整理、已处理、暂缓和撤回分别显示；预算、来源或版本不满足会暂缓，任务本身不因此失败。

旧资产、采用条件、历史候选、报告与承接均在折叠兼容入口，旧执行 API 继续 410；内容没有批量删除或自动采用。N3 本身只积累和管理；N5 的独立跨会话实测另行记录，不能用同一对话的上下文响应代替召回证据。详见 [N3 契约](design/natural-memory-idle-n3.md)与[验收](validation/natural-memory-idle-n3.md)。

## N4 压缩前增量捕获（实验）

Lake Memory 在有真实宿主消息身份、已获同意的新来源上登记增量；摘要或工具预览覆盖历史前交给同一 outbox，后台空闲后再提炼。摘要不是新授权/证据，重复压缩和轮次结束不重复采集。来源超出预算时显示未完整采集，原始操作记录保留；关闭、撤回或删除后仍重验。N5 负责独立开启后的新偏好使用。实现边界见 [N4 契约](design/natural-memory-compaction-n4.md)及[验收](validation/natural-memory-compaction-n4.md)。


## N5 使用自然偏好（实验）

在「工作区 → 设置 → 记忆 · 实验」选择当前项目或用户全局，再开启「使用本项目/用户全局自然偏好」。使用默认关闭，与自动积累独立；关闭积累仍可使用已保存内容，停止使用不删除内容。项目使用开关只影响项目偏好，全局选择独立控制用户偏好；本轮忽略同时忽略两者和原项目记忆。

当前明确要求优先，项目偏好其次，用户全局偏好最后。只有有效来源、无未解决矛盾的当前版本进入少量短预览；长偏好由模型按准确 ID/版本只读获取，不额外调用检索模型。普通会话和 Pilot 协调回复可用，专员/工作流不继承。偏好不是事实、操作方法或执行权限，环境与操作前提仍应核实。原项目事实与历史经验可从统一入口打开，仍按原设置、来源和范围使用。

访问记录区分准备提供、索引和读取，模型遵从/收益未知；点击记录可进入统一记忆管理。遗忘、撤销或停用后重新校验，在途已用自然偏好时停止后续请求/工具，不重放操作。准确来源、输入预算、恢复与已测限制见 [N5 契约](design/natural-memory-recall-n5.md)及[验收](validation/natural-memory-recall-n5.md)。旧人工资产仅归档；运维 V2 仍单独验收，不因 N5 完成而全部删除。C3 已合入 #117，C4 结果与平台缺口见下文。

## 历史诊断

普通请求不新增旧实验清单。准确自然偏好的准备/索引/读取记录继续工作。历史清单、纠错和未知操作记录保留在运行时账本中；旧资产和实验资料可通过上面的本地归档命令导出。宿主测试的可选提示词诊断不恢复旧资产注入。

## 当前验证入口

离线兼容回归使用 `python3 scripts/verify_memory_compatibility.py --report /tmp/lake-memory-compatibility.json`。签名 Dev 后端的隔离运行使用 `python3 scripts/verify_memory_compatibility_dev.py --report /tmp/lake-memory-dev.json`；只创建临时 Home、使用本机合成模型，不读取工作库或真实供应商凭据，不替代原生 UI 验收。旧 P8/R5 试跑脚本仅保留退役提示；旧 verify 文件名是当前离线回归的兼容别名。升级后的旧二进制验证应确认拒绝 v7，不能继续期待旧版打开新版工作库。Windows 本次未运行原生 CI，不能用交叉编译或 N5 旧结果宣称 C4 原生已通过。
