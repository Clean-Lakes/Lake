# Lake Pilot

Lake Pilot 将原 SRE 协作和分层操作选择放在同一个入口。它按项目保存，默认关闭。输入区沿用原文字按钮：灰色为关闭，主题前景色为开启（浅色主题为黑色）。旁边的小箭头打开设置，不增加第二个 SRE 开关。

## 自动推进

“自动推进”默认关闭。关闭时，专员在新的资源操作前提供处理方向，选中方向后通过底部唯一的主按钮继续。默认收起“选择具体操作”；展开查看不会改变委托方式。主动调整勾选或点击“仅执行所选操作”才锁定命令集合，主按钮显示“执行所选 N 项”；收起详情保留锁定，“允许 Lake 调整”可恢复方向委托。变更仍需原有权限与审批。

选择区保留次要的“本步骤交给 Lake”和“暂不执行”入口。展开、选择和勾选不会执行。命令正文在操作层展示，工具原名与 JSON 参数收在“工具与参数”内，供需要时核对。

开启自动推进后，新任务由 Lake 自行选择和推进。设置保存不改变已开始任务的策略；步骤委托也不修改项目默认值。主开关关闭后，子设置保留，但不能启动新的协作任务。项目有运行任务时，服务端拒绝切换主开关；运行中仍可保存下一任务的自动推进默认值。

## 专员与进度

| 专员 | 分工 |
| --- | --- |
| 协调者 | 明确范围、制定依赖、分配工作、汇总结论 |
| 调查员 | 只读收集现场证据、核对假设、交付发现 |
| 执行员 | 执行批准范围内的具体操作并记录实际结果 |
| 验证员 | 独立只读复测，按原验收规则判断结果 |

步骤导航放在原专员消息头下方，复用原湖生态头像、正文与审批。导航由真实计划生成，不给每个角色复制相同的排障阶段；同一工作项仅显示一次。长说明在导航中省略显示，点击可查看完整说明、状态和完成条件；首条进度消息若仅重复步骤说明，不再同时铺开同一段正文。独立发现与报告保持显示。执行中的主正文保持稳定，模型实时叙述收入默认折叠的“运行详情”，只局部更新阶段与调用计数，避免流式内容反复改写整条消息。会话只在实际内容增高时跟随滚动，计数、状态、同一行文字和事件游标变化不会触发滚动；窗口尺寸变化仍适配布局，手动上翻仍暂停跟随。Pilot 活动条不使用独立计时器或持续旋转动画，用时显示最近一次真实活动时的快照。方向与命令选择不会增加步骤数量或修改步骤身份，命令成功也不会直接增加步骤完成数。

## 执行、恢复与兼容

| 选择方式 | Agent 可以调整的范围 |
| --- | --- |
| 本步骤交给 Lake / 自动推进 | 在当前步骤、职责、目标及权限内调整方向和命令 |
| 按此方向继续 | 保持方向 ID、标题和目的，通过验证后的新候选批次调整命令，无须再次选择；换方向重新询问 |
| 仅执行所选操作 | 精确锁定工具、参数与依赖；失败不能静默改用其他操作 |

任务的自动推进默认值不能覆盖当前步骤后来明确选择的方向或命令。只读检查失败时，可以直接报告失败，也可以在委托范围内尝试替代检查。替代结果必须来自同一次 attempt、同一资源、失败之后真实成功且包含完整来源的只读操作，再关联原失败记录；失败历史保留，未取得证据的缺口仍阻止完成。单条字面量 `grep -c` 实际结束、输出完整的 `0` 且退出码为 1 时，视为检查完成但没有匹配项，保留原退出码和输出；其他非零退出、超时、复合命令和截断结果继续按原规则处理。策略拒绝及未执行的命令无需关联替代采样，工具会明确说明原因，不能误报为存储故障。未知变更仍需原核实流程，执行成功也不能替代独立验收。

候选经服务端验证真实工具、参数、风险和依赖。提交只引用当前候选 ID，不接受客户端改写可执行正文；决策绑定原任务、计划、步骤和 attempt。未选择的资源调用会被阻止，其他角色的选择不能放行当前专员。调查员、协调者和验证员的新 Pilot 操作保持只读，自动推进不提升权限。

选择等待复用原 ADK 人工输入与专员调用；决策保存在原 SRE 任务，实际操作继续进入原账本。重启恢复原等待与 attempt，不创建另一套执行循环。结果不明的操作沿用原核实规则，不能用选择或自动推进重放。

首次迁移将主开关与自动推进设为关闭，并保存旧 enabled 来源；此迁移只运行一次。旧 SRE API 与新入口共享 enabled，旧 API 不覆盖子设置。没有 Pilot 策略的历史任务沿用原执行语义；已保存工作流继续按既有自动运行方式执行。专用终端、数据库会话和 Plan 模式保留原行为。

## 当前开发范围

当前是 [草稿 PR #98](https://github.com/Clean-Lakes/Lake/pull/98) 的首个工作切片，已经实现设置、迁移、真实选择门禁、原 ADK 等待与崩溃恢复、自动推进、独立导航及合成协议下的真实文件取证。

以下内容仍待后续实现和验收，不能视为完整方案已交付：

- 自动运行中的步骤级“暂停并选择”，以及与其他并行专员隔离的局部 hold。
- 执行员与验证员的更细分多阶段模型，以及结构化业务完成条件；当前保持原角色/kind、冻结变更和确定性验收约束。
- 真实供应商模型的方向质量，以及 Lake Dev 中真实故障、审批拒绝、独立恢复验收的全套演练。

完整目标与任务状态见 [实现方案](../plan/feature-lake-pilot-1.md)，实际验证及限制见 [验证记录](validation/lake-pilot.md)。
