# Lake Pilot

## 多干员共同对话（TypeScript）

在 Pilot 中说“全部干员给我报数”，或要求指定干员亲自介绍、发表意见，Pilot 会登记一次召集。宿主在召集时冻结收件人名单，每位干员使用独立上下文回应；头像和姓名来自实际角色身份，回复进入当前 Pilot 对话，也保留在该干员频道。新的共同讨论可以引用当前对话最近的公开内容，不读取其他专员的执行历史。

对话下方显示已回应人数及尚未回应的干员，区分等待唤醒、正在回复、失败、超时、停止和中断。默认等待 120 秒，可在调用中指定 15～300 秒；全部收件人取得回应或明确终态后，Pilot 根据实际结果另行汇总。未回应者不能计为到齐；模型汇总失败时保留成员原始回应和缺席状态。一次最多召集 64 位干员，每个项目最多同时保留 4 个未结召集；执行复用原全局 4、项目 2 的共享并发容量。

Pilot 的停止同时取消本项目未结束的召集和汇总；单个专员的停止只取消自己的未结回应。已到达的回复保留，停止后的迟到输出不再投递。应用重启将未结对话标记为中断，不自动重新唤醒；新的用户请求可以发起新的召集。

共同对话只生成文字。报到、讨论、汇总不创建业务任务，也不证明资源已经检查或业务工作已经完成；需要操作资源时仍由 Pilot 通过原派工入口单独分配和验收。

Lake Pilot 将原 SRE 协作和分层操作选择放在同一个入口。它按项目保存，默认关闭。输入区使用原风格的罗盘文字按钮：单击按关闭→手动选择→自动推进→关闭循环，关闭为灰色，开启为主题前景色（浅色主题为黑色），自动推进额外显示浅蓝 AUTO 标签。没有独立设置箭头或第二个 SRE 开关。

## 自动推进

“自动推进”默认关闭。关闭时，专员首次执行资源操作前提供 2～4 个方法或来源有区别的步骤级方向；相同工具、参数和依赖仅换名称不会变成多个选项。调查和独立验证不能以“只读”“单个目录”“需先读清单”为由省略备选方案。仅运行时已冻结的明确动作、最终汇总需补齐单一来源时，允许附原因的单一方向。方向覆盖本步骤的后续读取与正常回退，不按文件或单条命令反复询问；选中后点击实色“确认方向并继续”。默认收起“选择具体操作”；展开查看不会改变委托方式。主动调整勾选或点击“仅执行所选操作”才锁定命令集合，主按钮显示“执行所选 N 项”；收起详情保留锁定，“允许 Lake 调整”可恢复方向委托。变更仍需原有权限与审批。

选择区保留独立的“交给 Lake 完成本步骤”和“暂不执行”入口。展开、选择和勾选不会执行。命令正文在操作层展示，工具原名与 JSON 参数收在“工具与参数”内，供需要时核对。

开启自动推进后，新任务由 Lake 自行选择和推进。设置保存不改变已开始任务的策略；步骤委托也不修改项目默认值。关闭后再次开启固定从手动选择开始，不沿用隐藏的自动推进值。当前会话运行或断线时，入口禁用；服务端仍保留活动任务保护与设置版本冲突检查。

## 继续与重跑

普通聊天由模型结合会话判断是否需要专员。开启 Pilot 后，对已完成的只读调查说“继续再来一次”等要求重新执行的指令，应通过 `restart_task` 创建新任务，保留原目标及精确资源范围，重新制定计划并取证；已完成的旧任务和证据不改写。新任务采用当前项目的手动/AUTO 默认值，不继承旧任务的推进策略。暂停中的合格只读调查仍可继续或重新开始；变更计划、已派发的非只读历史操作和仍在执行或待核实的操作不能通过此入口重放。策略拒绝或明确未执行的提议保留原记录，不当成已发生的变更，也不重放该提议。

每次协调模型请求在上下文压缩后附上本轮 ID、开始时间及任务时间/状态，区分历史报告与本轮执行。提交交接并不代表执行完成，旧文件哈希也不能证明已经重跑。询问旧结果时可以直接解释，但不能把历史报告说成刚执行的结果。若模型只输出临时正文，沿用现有的一次补交机会，仅提供正式答复与协作交接工具；支持的 OpenAI/Responses/Azure 协议在此阶段要求函数调用。DeepSeek 的强制调用与思考模式不兼容，仅这次补交序列化请求临时关闭思考，保留用户配置及专员执行时的思考设置。仍未提交决策则如实失败，不增加循环，也不自动将正文当成执行结果。本轮模型答复失败不会被历史任务覆盖成完成。普通新一轮答复结束后，Lake Island 与上下文状态按本轮展示；旧的终态任务不覆盖本轮，仍在执行或待核实的操作继续保留其状态。

## 专员与进度

| 专员 | 分工 |
| --- | --- |
| 协调者 | 明确范围、制定依赖、分配工作、一次性汇总结论；常规只读巡检不另建表格骨架、比较或中间汇总步骤 |
| 调查员 | 只读收集现场证据、核对假设、交付发现 |
| 执行员 | 执行批准范围内的具体操作并记录实际结果 |
| 验证员 | 独立只读复测，按原验收规则判断结果 |

最终汇总逐字段区分历史基线、当前采样和健康预期。没有同字段的历史值时，只报告现状与缺口，不声称“没有变化”；独立重读相同的当前快照也不能补造历史基线。

步骤导航放在原专员消息头下方，复用原湖生态头像、正文与审批。导航由真实计划生成，不给每个角色复制相同的排障阶段；同一工作项仅显示一次。长说明在导航中省略显示，点击可查看完整说明、状态和完成条件；首条进度消息若仅重复步骤说明，不再同时铺开同一段正文。独立发现与报告保持显示。执行中的主正文保持稳定，模型实时叙述收入默认折叠的“运行详情”，只局部更新阶段与调用计数，避免流式内容反复改写整条消息。会话只在实际内容增高时跟随滚动，计数、状态、同一行文字和事件游标变化不会触发滚动；窗口尺寸变化仍适配布局。布局锚定和程序滚动事件不会自动解除跟随；手动上翻、拖动滚动条或进入历史详情仍暂停，回到实际底部恢复跟随，正在跟随时向下追赶不暂停。Pilot 活动条不使用独立计时器，用时显示最近一次真实活动时的快照；执行中的圆环、文字与当前步骤动效由浏览器独立推进，快照更新保留原节点和动画。方向与命令选择不会增加步骤数量或修改步骤身份，命令成功也不会直接增加步骤完成数。

## 单行状态岛

开启 Lake Pilot 后，会话顶部沿用原悬浮标题、玻璃底、共享字体与湖生态头像，采用 B「当前行动岛」：主行显示当前专员与正在做的事，次行显示其他专员状态，右侧仅保留状态色细环/结束图标与展开箭头，顶部不展示步骤数字，真实已完成/总步骤数保留在展开详情与无障碍说明中，不使用工具调用数、模型轮次或虚构百分比。切换方向、重试命令不增加步骤进度；恢复后沿用已完成记录，新计划按自己的记录计算。

等待方向选择、等待补充、等待审批、排队、执行、暂停和失败分别呈现；单个专员等待时仍显示其他专员继续执行。主动暂停为中性灰，尚在执行的原操作显示“正在暂停”，未知变更仍优先提示核实。结束调查不等于恢复验收通过，结论不足会保留在详情中。

右侧图标和环与下方上下文共用当前会话状态色：运行蓝、待确认黄、完成绿、需要关注红；结论不充分保留关注色和说明。

点击右侧进度可查看实际参与角色的分工与各自进度，点击角色定位原消息，“查看完整计划”定位原计划。面板左缘对齐上方标题与专员之间的分隔线，右缘对齐状态岛边界；窄窗口用整个标题气泡的宽度，避免外溢。以220ms展开、160ms收起，箭头同步旋转；没有重复的关闭按钮。入口只查看和定位，不执行命令、不授予权限；再次点击入口收起，Esc关闭后返回触发器，外部点击和移出焦点也会关闭。窄窗口优先保留会话名、真实状态图标与展开入口，长标题省略，完整内容通过提示和详情查看。

同一状态的快照更新原位保留节点、尺寸、展开状态与焦点，不为Pilot播放循环扫光或计时刷新。关闭 Pilot 时，专员信息用 120ms 淡出、宽度用 280ms 平滑收回普通会话状态；原标题锚点和会话正文位置保持不动，隐藏内容不可聚焦。减少动态效果时直接切换；开启时也可以读取历史SRE任务的实际进度，不补写历史执行策略。

## 专员资源执行过程

Pilot 的每个执行子级按真实资源 ID 分组，复用普通模式的资源行和 Mini Box。同一资源后续命令归回原组，原始参数和输出按需展开；没有明确终端类型的工具保留原操作记录。单个本机或 SSH 命令资源默认展开，同一轮计划涉及多个命令资源时默认折叠；第二个资源出现只收起尚未手动操作的盒子一次，用户手动开合及完整输出的阅读状态始终保留。

Mini Box 复用原材质、当前操作光带、状态和终止交互。并行专员只读取自己实际派发的命令记录：同时校验父会话、资源、终端 generation、attempt 时间与命令归属；准确终端/entry 句柄优先，缺少句柄时只接受唯一匹配的最近派发，歧义不展示和操作。终止仍由服务端验证准确命令与权限，不扩大职能或执行权限。

## 执行、恢复与兼容

| 选择方式 | Agent 可以调整的范围 |
| --- | --- |
| 交给 Lake 完成本步骤 / 自动推进 | 在当前步骤、职责、目标及权限内调整方向和命令 |
| 确认方向并继续 | 保持原方向标题和目的，通过验证后的新候选批次调整命令，无须再次选择；仅 ID 改名但目的逐字相同沿用原决定，真正换方向重新询问 |
| 仅执行所选操作 | 精确锁定工具、参数与依赖；失败不能静默改用其他操作 |

重复呈现已锁定的同一工具、参数及依赖集合，也沿用原决定，不扩大操作集合。自动推进或整步委托直接执行职责内的操作，无需先反复调用方向提议工具。相关读取及其回退归入同一专员交付项，只有真正前置关系才串行；需要独立验证时保留验证员，协调者消费已有事实与证据，不重复重算整份报告。

任务的自动推进默认值不能覆盖当前步骤后来明确选择的方向或命令。只读检查失败时，可以直接报告失败，也可以在委托范围内尝试替代检查。替代结果必须来自同一次 attempt、同一资源、失败之后真实成功且包含完整来源的只读操作，再关联原失败记录；失败历史保留，未取得证据的缺口仍阻止完成。单条字面量 `grep -c` 实际结束、输出完整的 `0` 且退出码为 1 时，视为检查完成但没有匹配项，保留原退出码和输出；其他非零退出、超时、复合命令和截断结果继续按原规则处理。策略拒绝及未执行的命令无需关联替代采样，工具会明确说明原因，不能误报为存储故障。每次模型请求都会带上当前未补齐的只读检查，以及时间、资源和来源均合格的替代操作候选；候选只通过来源校验，仍由专员判断是否真正覆盖原检查。关联被拒绝时明确指出旧采样、截断来源或错误操作ID，避免反复尝试同一无效关联。结构化 grep 会把零匹配规范为退出码0；需要原生退出码时使用单条 shell grep -c，工具结果本身已含退出码。专员提交报告后仍有只读缺口时，灵活委托的只读角色会在同一个步骤、同一份账本中得到一次补齐机会，最多使用原剩余额度中的8轮模型调用。补齐标记与上限持久化；命令锁定、执行员、冻结动作、未结束操作及待核实变更不走该流程。仍不满足条件则如实暂停。未知变更仍需原核实流程，执行成功也不能替代独立验收。

候选经服务端验证真实工具、参数、风险和依赖。提交只引用当前候选 ID，不接受客户端改写可执行正文；决策绑定原任务、计划、步骤和 attempt。未选择的资源调用会被阻止，其他角色的选择不能放行当前专员。调查员、协调者和验证员的新 Pilot 操作保持只读，自动推进不提升权限。

选择等待复用原 ADK 人工输入与专员调用；决策保存在原 SRE 任务，实际操作继续进入原账本。重启恢复原等待与 attempt，不创建另一套执行循环。结果不明的操作沿用原核实规则，不能用选择或自动推进重放。

首次迁移将主开关与自动推进设为关闭，并保存旧 enabled 来源；此迁移只运行一次。旧 SRE API 与新入口共享 enabled，旧 API 不覆盖子设置。没有 Pilot 策略的历史任务沿用原执行语义；已保存工作流继续按既有自动运行方式执行。专用终端、数据库会话和 Plan 模式保留原行为。

## Super-agent 统一入口（2026-11-02）

已切换的项目使用持续 Pilot 与独立 Worker。新要求、旧会话补充、普通/Plan 与专用入口由宿主进入同一来源事件；专员详情保持原问题/审批、任务检查与终端。右侧任务检查默认收起，进入专员或任务状态更新不自动展开；点击顶部箭头、执行过程或证据入口可查看。历史只读，继续沟通回到 Pilot。旧 SRE 开关不作为该工作区的第二个运行模式。 验证与边界见 [运行架构](design/lake-superagent-runtime.md)。

Super-agent 直接复用当前项目的原资源树、文件夹、连接与终端入口，不增加“项目执行范围”或资源勾选配置。未单独配置过 Security 项目策略时，宿主将项目目录接入既有会话权限适配器，自动跟随同项目可用资源的增删；读取、写入和命令仍按已存在的权限设置处理。已有明确项目策略、禁用本机、引用范围、原审批和未决操作继续生效；其他项目资源不进入当前 Pilot。

主对话中的专员报告显示其实际来源专员的头像和名称，点击回复头部可进入该专员继续沟通。Pilot 自身的协调回复仍显示 Pilot；历史投递也按原绑定显示来源，不通过正文或当前选中的专员推断署名。

聊天只展示专员的报告正文，不在末尾附加任务标题、状态或“验收：通过”等台账尾注。任务状态仍在顶部和任务清单中查看；旧报告按准确投递来源去掉程序附加的尾注展示，原消息和验收账本保留。

## 一个专员入口，多项独立任务（2026-11-03）

Pilot 会话不显示“@专员，请去做一下”及其后续补充派工气泡，避免重复播报。专员频道仍显示带 Pilot 署名的任务内容，后续补充显示为“补充要求”；直接发给专员的话仍按用户消息显示。派单原始记录及任务来源关联继续保留，不产生新模型输入、执行授权或重复任务。

输入框的 `@` 菜单在“资源”前显示“专员”分类，列出当前项目已创建的专员及职责，允许按职责搜索。专员只在该分类中显示，“全部”继续聚合资源、Skills 和 MCP，计数与实际候选一致；切换分类替换候选列表。头像使用固定图标列，与名称保持紧凑间距。同名专员使用各自准确 RoleID，选择后与资源、Skills 和 MCP 一样形成可删除的随文引用；发送时宿主校验项目归属及当前名称，再将准确 RoleID 提供给 Pilot 复用，不能按显示名替代身份。引用不授予资源权限。

当前实施候选把侧栏改为长期角色频道。同一运维专员里说“检查优刻云”“另一台呢”“继续优刻云”，由 Pilot 判断创建B或找回A；聊天记录在同一入口连续展示。任务的执行会话、资源、期限、轮数、审批和证据各自保留。“比较这两台”建立独立比较任务，通过准确来源读取历史证据；历史结果不代表当前健康。

专员创建后即从 100 个不同图形的湖生态头像库中按稳定 RoleID 组合外观，无需先派任务；改名和换任务保持外观，侧栏、顶部、任务检查及 Pilot 中的报告使用同一身份。图形按“池畔小龟”的圆润轮廓与自然分色细化；闲时轻眨眼或摇叶，真实会话中播放各自的分部件动作。点击会话时各有短回应，重复点击和键盘进入也能触发；暂停/停止静止；系统减少动态效果会取消动画。头像不配置权限，也不改变执行或验收状态。

侧栏专员正在执行时显示转圈。新完成的任务用绿色圆点提醒，打开该专员就清除；已读状态按项目和专员保存。

同一专员的多个活动任务显示实际执行数量；单独停止一个后，侧栏切换到仍在执行的任务标题，空闲时显示最近更新的任务。输入框的“停止该专员全部任务”作用于本角色的所有活动任务；只停止一项时，进入对应任务详情点击“仅停止此任务”。Pilot 的停止作用于当前项目全部活动任务。停止保留草稿、历史和原操作，已核验的只读取消显示“已停止”，真实未知副作用仍需核实。

专员频道和单项任务的顶部状态栏都有“任务清单”按钮。展开后可按标题和状态选择这位专员的任务，查看对应的执行详情。当前任务的原始要求也可在清单中展开查看。

点击回复后的“执行详情”在右栏查看对应任务，处理审批或停止时沿用该任务原身份；不需要创建或管理内部会话。专员直聊不重复显示头像/名称，Pilot 主对话中的专员报告继续保留实际来源头像与名称。当前项目原资源树和权限不变。实现验收进度见[长期专员频道计划](../plan/feature-specialist-channel-1.md)，该工作不自动启用长期 Memory。


当前频道候选的已测范围和剩余阻塞见[频道验证记录](validation/lake-specialist-channels.md)：A/B独立只读诊断已取得原始结果，历史比较读取保留来源与未验收状态；开发验证不代替用户逐项验收，也不自动开启Worker Memory。


## 多位专员共同处理一项任务（TypeScript Dev）

例如对 Pilot 说：「让运维专员和数据库专员一起排查接口超时。运维查代理日志，数据库查慢查询，作为同一个任务验收。」两位专员会在各自的频道中看到同名、同编号的任务。打开右侧任务详情可以看到参与者、谁已经提交，以及整项任务是否通过。每位专员的审批、问题和停止按钮只作用于当前查看的执行。

也可以在任务还没结束时请 Pilot 把另一位专员加入，原任务编号和截止时间保留。共同任务最多有 8 位长期专员；同时执行数仍受项目的调度上限约束。任务内的临时子智能体不计为长期专员。

专员先提交自己的结果。最后一位提交后，宿主按当前权限重新核验所有参与者的原始证据，只签发一张目标验收回执。某人被停止、部分完成或仍有待核实的操作时，其他人可以继续，但不能据此宣告整项通过。已经结束的历史任务不会因升级而被重派。

## 长期专员管理

资源任务默认交给合适的长期专员，包括一次简单主机检查、数据库查询或知识库检索。已有合适专员就复用，没有则创建后派单。Pilot 负责理解要求、协调和汇总；纯聊天或解释已有结果直接回答。明确说「Pilot 亲自检查，不要委派」时仍可由 Pilot 执行，工具与项目权限保持一致。这项分工由模型遵循，不是新的安全许可或关键词拦截。

普通 Pilot 直接任务也只需调用业务工具，再提交 `work_finish(summary, outcome)`，不混用 `work_begin/work_update` 的手动步骤流程。显式计划继续使用原计划工具及验收条件。旧自动任务若已通过步骤验收，最终收尾复核同一执行代次的真实业务证据后完成，不重跑命令、不替换原回执；过期、权限变化、未决操作或只有目录发现仍不能通过。

在 TypeScript Dev 的「设置 → 巡检」中统一设置当前项目的巡检模式，对本项目的专员任务生效。任务详情「执行过程」只展示该次执行已有的「任务巡检记录」，不再提供模式设置。默认「仅观察」会定期使用当前模型核对可疑停滞或偏离分工的情况。「允许纠偏」可向原专员发送一次定向提示，并在工具执行前的暂时性模型故障后有限重试。「关闭」会停止该项目的巡检。也可以问 Pilot「刚才哪位专员卡住了？巡检有什么依据？」

Super-agent 专员的普通任务直接注册步骤并自动推进，按实际工具回执验收，不逐次弹出计划和人工验收卡片；只有 Plan 模式先确认计划。具体资源操作仍按项目现有权限审批，旧人工验收约定继续保留。

可直接告诉 Pilot：“创建牛马专员，负责核实证据，头像用河狸，暂时不派任务”“把牛马专员的头像改成河狸”“把发布专员的职责改为……，后续任务默认用 Codex”“恢复牛马专员的自动头像”。Pilot 使用 `list_specialists` 读取准确角色及当前版本，使用 `list_specialist_avatars` 查本地头像 ID，再通过 `manage_specialist` 保存名称、职责、头像及后续任务默认后端。更新只提交改动的字段，不必重填其他配置；只有保存回执成功后才报告已修改。

显式头像是角色的显示配置，同一 RoleID 在侧栏、标题、任务详情和 Pilot 报告中同步显示；没有显式选择时继续稳定地按 RoleID 分配。河狸、海狸及 🦫 可查询到 `beaver`；`avatar_id=auto` 恢复自动分配。只接受 Lake 现有的 100 项本地图形，不从职责文本推断头像；用户未指定职责时保存空职责，不用动物外观填充。创建和配置不附带执行任务，保留准确 RoleID 与频道，重启后资料继续存在；同名角色需要通过当前上下文及目录区分。

默认执行后端仅支持当前 Lake 原生或 Codex，保存只影响后续新任务。该入口不修改本机 Codex 的登录、模型、思考强度、服务地址、项目权限或任何凭据。已有任务仍使用原冻结职责与执行绑定；当前头像的显示更新不改写历史任务。

右键侧栏专员可选择“删除专员”，键盘可在该行按 Shift+F10 打开。确认后停止该角色当前及待派发任务，从侧栏和 Pilot 的可用专员列表移除；若正在查看该专员，返回 Pilot。历史对话、任务、操作与审批记录保留，删除不表示远端操作已撤销或未知结果已解决。同名角色按准确 RoleID 独立处理，重启不会恢复已删除角色，旧路由不能继续派给它；需要再次建立时使用新的角色身份。

删除状态保存在规范库 schema6 的角色退休时间；schema5 升级前沿用一致快照备份。旧 reader 拒绝新库，回退使用迁移前完整配套数据或保留兼容 reader 向前修复，不删除退休标记或原始账本来绕过版本保护。

后续派单先查角色并用 `route_work(role_id=...)` 复用其稳定身份。每个独立任务仍创建不同的 Task、Worker、ADK Session 与 RootTurn，不将长期频道历史复制到任务上下文。任务建立时保存角色名称、职责及版本快照；编辑只影响后续新任务，已有任务的目标、上下文、资源、审批和用量保持原账本语义。

专员职责是工作说明，不是额外权限。仍使用当前项目原资源目录与权限，不新增资源勾选层。管理操作仅接受本项目已接纳的真实用户输入，引用原事件与准确原文，按事件/part_key 幂等保存；编辑须使用当前 revision，过期版本先重新读取。列表支持分页，包含尚无任务的角色；Worker 和自动观察事件不能修改专员资料。

本次规范库 schema4 → schema5 迁移前生成私有一致快照，补齐旧 Worker 的职责快照并保存原任务身份。旧二进制拒绝 schema5；回退需停止新内核并恢复迁移前完整配套数据，或保留兼容 reader 向前修复，不能让旧程序继续写新库。验证见[长期专员管理验收](validation/lake-specialist-management.md)。

## 用自然语言管理配置（TypeScript）

直接在 Pilot 中说出要增删改查的对象。例如：“在资源里新建生产环境文件夹”“把测试入口移到生产环境下面”“把这台主机的端口改成 2222，其他配置保留”“删除这个文件夹及里面的资源”“恢复刚删除的资源”。Pilot 查询当前项目的准确对象和版本后保存；删除沿原回收站保留资源身份与历史。项目有其他活动任务、待分配要求或终端时，仍须先结束相关占用才能删除。

也可以说：“创建一个名为 health-check 的 Skill，内容是……”“把 health-check 停用”“修改这个 Skill 的内容”“删除这个 Skill”“注册这个 Skills 目录”。Skills 是 Lake 全局配置：Lake 管理的内容可以修改，删除时移入私有回收目录；导入内容只读，删除只从 Lake 解除注册，不删除来源文件。移除注册目录也不删除文件。删除标记保持停用，避免同名导入项或旧版本误启用；明确创建新的同名 Skill 才恢复该名称。

MCP 支持“新增一个 HTTP MCP，名称……，地址……”“修改这个 MCP 的地址，保留认证”“停用/删除这个 MCP”“测试连接，并只向当前项目启用指定工具”。全局服务配置和当前项目启用范围分别保存；新增或编辑不会自动连接或启动进程。显式连接测试受 Pilot 的 MCP 调用开关及本机执行限制约束，项目启用只接受当前真实目录中的工具；省略工具列表时保留既有范围，首次选择全部必须明确指定。既有全局继承与单服务拒绝仍有效。

这些配置操作由 Pilot 直接处理，不为它们创建业务调查任务。读取、写入和连接测试分别沿用文件读取、文件写入、MCP 调用的当前权限偏好；Plan 只查询配置。保存只修改用户要求的字段，未知结果不报成功，也不自动重放未确认提交。同名对象有歧义时先区分准确目标。凭据值和凭据文件引用不传给模型；新 SSH 没有凭据时如实保存为待配置，可在资源设置中补齐，或按用户明确选定的同项目 SSH 来源由宿主内部复用凭据。

## 专员使用项目资源

任务先围绕业务目标建立，资源可在执行中按需发现。`work_begin.asset_refs` 为可省略的资源参考，不是固定执行白名单；先读取数据库、之后补充集群节点时继续同一 GoalID 和 Worker，无需结束并重建任务。补充不重置步骤、验收版本、累计轮数或绝对期限。真实使用的资源还可从该任务的操作账本关联展示。

任务资源快照作为历史保留；实际操作仍解析当前项目中的准确目标并检查 Pilot 继承权限、连接版本和明确边界。增加资源参考不签发授权、不撤销原操作，也不解决原 unknown 结果。保存工作流及内部子角色仍执行原模板/子范围限制。已有 Security 契约的自动接续按原操作及句柄核验，无关历史参考变更不会阻断整个任务；缺少受信描述的旧自动接续继续保守核验。

每项任务的 Worker 都能从所属项目的目录选择主机、数据库等资产，或使用项目已开放的 MCP 和技能，无需为每位专员单独配置资源。只用 MCP 查询发布记录时，专员可以用空资产清单建立任务，普通任务自动注册计划后直接发现服务、列出工具并调用，无需用户提供主机地址。操作审批和结果验收仍在这项任务内处理。

项目内专员与各项任务统一使用 Pilot 的权限设置，专员输入区不再显示独立“权限”按钮。修改 Pilot 设置会作用于后续操作，旧专员选项中的权限快照不能覆盖它。Pilot 权限中的“调用 MCP 工具”开启后，专员直接调用项目已启用的 MCP 工具；关闭时仍按具体操作确认。该选项包括可能修改外部系统的 MCP 工具，不会将它们判定为只读，也不覆盖明确配置的项目策略、资源范围或服务未决调用检查。其他项目不会随之开启。

权限来源和版本随操作冻结，设置变化后旧提案不能继续使用过期授权；已成功取得的历史工具回执仍按原快照核验。原有待确认卡片不会伪造为用户已同意，可停止旧任务后在当前权限下重新派发。

项目可选择继承 Lake 全局设置里所有已启用的 MCP。开启后，新增、启用或停用服务会自动反映在专员目录中。此选择按项目保存，重启后仍然生效。项目已有的单服务绑定优先，包括禁用和工具范围。项目设置和接口见[工具入口与执行边界](security/tool-entrypoints.md)。

专员在生成第一份计划前暂停时，向 Pilot 重新提出原查询会沿用原任务和 Worker 恢复计划流程。MCP-only 查询使用空资产清单，随后由宿主确认计划再调用工具。原调用用量、期限和后续验收保留。


### TypeScript Dev：取消任务轮次硬限制（2026-11-08）

Pilot、专员、临时子智能体和多专员共同任务不再因累计模型调用轮数暂停；旧会话的 `maxSteps` 和旧任务的 `roundLimit` 也不再形成执行上限。任务详情不显示“已用 / 上限”或共同任务轮次额度，TypeScript 会话配置不再提供工具循环上限。调用量继续按原任务和成员记录，供诊断和 Watchdog 判断进展。

已因旧轮次上限暂停的任务保持暂停并提示限制已取消，可通过当前输入或明确恢复继续；升级不会自动重放旧操作。任务的绝对期限、主动停止、权限检查、未决结果与统一验收继续生效。早期文档中的“累计轮数”现在仅指统计，不再作为门禁。

## 项目外部 Agent

专员聊天框的模型菜单默认选择 Codex。发送后，宿主直接创建该专员负责的新任务，并冻结 Codex 执行绑定；发送完成仍保持 Codex 选择。普通模型与 Codex 共用这个菜单，选择普通模型后使用 Lake 原生执行，并保存为该专员的新任务偏好。已有任务保留原执行者，继续原任务使用其准确任务入口。

Pilot 和专员模型菜单中的“配置 Codex”均可打开当前项目的 Agent 设置并保留草稿。Pilot 保持自己的协调模型，菜单另列专员 Codex 的具体就绪状态；自动检测本机 Codex 的登录状态、实际模型与思考强度，缺登录时提示在本机 Codex 完成登录。启用时自动识别本机 Node 22.22+ 或 24.14+ 及配套 npm，在 Lake 私有目录准备固定适配器并验证 ACP 握手；手工路径覆盖放在“高级设置”。直接复用 CODEX_HOME（默认 ~/.codex）的已有登录与配置，不再填写项目独立 Key；Codex 任务不依赖普通模型的 Key。没有可用运行时时显示具体原因，不自动安装系统 Node；实际推理认证仍在执行时核验。连接测试不发送业务 prompt，不复制登录文件或修改本机配置。

专员频道与任务执行详情显示“专员 → 任务 Worker → 执行 Agent”、实际派发/运行状态和回传报告。没有运行记录时显示“尚未派发”；“已回传”只表示外部运行结束，任务完成仍由真实工具回执验收。输入区只保留原模型入口；供应商名称中含 Codex 的普通模型仍是模型服务，独立 Codex 选项以 Agent / ACP 标识。

Agent 设置还可修改专员的新任务默认后端。未设置偏好的专员默认 Codex，明确保存过的原生选择继续有效。修改连接配置或本机 Codex 的配置/账号会停止旧调用，后续新任务使用最新配置；同账号令牌正常刷新保持身份，旧 Worker 不被改写。已移除 runtime-acp 外部后端及其新任务入口，历史运行与未知操作保留，不自动改派。原生 Worker 可以通过 Agent 创建 codex-acp 子任务，或使用 run_external_agent 委派 Codex 执行段；原生子任务也可委派外部段。独立任务、逻辑 child 与外部执行段保留各自身份，回传不会自行生成验收证据。当前范围与未验证项见 [ACP 兼容记录](validation/acp-agent-execution/compatibility.md)。
