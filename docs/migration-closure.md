# 四项迁移功能闭环

Lake 保持 Go/Eino 单运行时，“专员”统一对应受范围限制的 Eino AgentTool。本次新增功能适用于新版本创建的任务；旧专员任务仅有摘要和状态，无法凭空重建执行上下文。

## 插件 MCP 与 Hook

插件安装后默认关闭。启用时核对整个安装包的摘要与权限，新会话加载 MCP 服务和 Hook。MCP 每次调用、Hook 每条命令仍通过 Lake 审批；已启动会话中禁用、版本切换或文件变化会阻断继续调用。Hook 收到的只是事件名称、工具名和摘要等允许字段，其输出不加入模型指令。

清单示例：

```json
{
  "name": "observer",
  "version": "1.0.0",
  "mcp": ["mcp/local.json"],
  "hooks": ["hooks/start.json"],
  "assets": ["assets/observe.sh"]
}
```

`mcp/local.json`：

```json
{"name":"local","transport":"http","url":"https://example.com/mcp"}
```

也支持 `stdio`，声明 `command` 与 `args`。包内可执行命令使用 `assets/` 路径并列入清单。HTTP 必须为 HTTPS 或本机 HTTP。声明不得包含 env、headers 或任何凭据字段。

`hooks/start.json`：

```json
{"version":1,"hooks":[{"event":"SessionStart","command":"assets/observe.sh"}]}
```

来源脚本须有执行权限，安装后的脚本为 0700。Hook 命令只能使用包内明确声明的 asset，不接受项目外路径；超时为 5 秒，输出有界。修改包内容后需要安装新的版本并重新启用。

```sh
lake plugin inspect /path/to/plugin
lake plugin install /path/to/plugin --sha256 <inspect返回的sha256>
lake plugin enable observer
lake plugin list --json
```

`plugin list --json` 返回 `mcp_servers` 和 `hook_declarations`。插件 MCP 使用带摘要后缀的独立服务名，凭据保存在本机私有文件。启用插件后按返回的服务名执行 `lake mcp login --name <服务名> --header Authorization`；stdio 使用 `--env <变量名>`。凭据值通过终端输入。桌面在“设置 → 扩展与权限”展示服务数量及插件状态，可启用或停用。

## 自定义专员

桌面“设置 → 自定义专员”支持新建、修改、启用、停用、删除。字段包括：

- 标识：`lake_specialist_` 开头；最多 32 个配置。
- 独立模型：选择已登记模型，凭据由模型提供方的私有凭据文件读取。
- 工具白名单：显式列出 Lake 代码/SSH/Kubernetes/数据库工具或会话中已加载的 `mcp_*` 工具。
- 范围：所属湖、登记的代码项目、允许的资源 ID；“所有资源”仍与当前父会话资源范围相交。
- 轮数：1–32。

专员不能递归委派或执行另一个工作流。项目必须与会话绑定的登记项目相同，资源不能跨湖。配置变化后旧会话中的该专员拒绝调用；停用即时生效。新会话会根据专员说明自动展示对应委派工具。工作流 v2 `specialist_task.specialist` 填同一标识，使用相同配置。

CLI 配置通过 stdin：

```sh
lake specialist configure < specialist-request.json
lake specialist list
lake specialist run lake_specialist_inspect --lake <湖名> --request-file task.txt --project <项目ID>
lake specialist tasks
lake specialist status <任务ID>
```

配置文件为 `{"action":"specialist_save","specialist":{...}}`；specialist 对象与桌面字段相同，使用 `name`、`description`、`instruction`、`model`、`tools`、`max_turns`、`scope`、`enabled`。scope 使用 `lake_id`、`resource_ids`、`all_resources`、`project_root`。代码工具要求登记项目；未绑定所需项目或未加载所需 MCP 工具的专员不会出现在会话工具列表中。

## 专员执行恢复

每个新任务在 `~/.lake/specialist-checkpoints/<任务ID>.json` 保存原始任务、已准备的专员范围、模型响应和工具执行结果。目录为 0700，文件为 0600，单任务上限 16 MiB。它们包含项目上下文和工具输出，不包含模型配置凭据；SQLite 仍只保存任务元数据和请求/响应摘要。私有文件通过原子替换和 fsync 保存；每任务文件锁防止并发恢复。

恢复时验证专员配置、模型、白名单、项目及资源范围与检查点一致。由 Eino 重放已持久化响应，已完成的模型和工具步骤不会再次调用外部服务。正在进行的只读工具可以重试；写入/执行/外部工具若没有确定结果，默认拒绝重试。完成步骤可复用，即使进程在提交最终工作流节点前退出。

```sh
lake specialist resume <任务ID> --lake <原湖名>
# 人工核对外部结果后，才允许重新尝试未知写操作：
lake specialist resume <任务ID> --lake <原湖名> --retry-writes
```

代码任务必须使用原来登记项目。远程代码专员从原会话的远程工作区绑定恢复，并重新核对授权；绑定变化会阻断恢复。桌面“自定义专员 → 最近专员任务”提供恢复入口与明确的写操作重试选项，执行回到对话审批卡。旧任务没有检查点时不展示恢复按钮。检查点损坏、权限错误或符号链接会被拒绝。

工作流专员检查点按运行 ID、节点 ID、扇出项绑定，恢复不会把相同请求的两个不同节点合并。

## 工作流 v2 桌面管理

侧栏“运维工作流”的 `+` 打开 v2 管理页面。支持 JSON/YAML 编辑、静态校验、当前湖目标/权限预览、保存定义、修订、启用/停用、代码项目选择、运行历史、节点状态、事件及恢复。修订携带版本号，过期编辑拒绝覆盖。编辑内容需先保存才能运行。

运行及恢复通过结构化会话桥发送定义/运行/项目 ID，不依赖模型解析。执行前确认整个请求；风险节点和内部工具继续请求批准。审批卡、节点进度和最终状态进入会话记录。未知写节点默认不重放；核对后允许重试仍需要节点与工具审批。

CLI/桌面共享结构化管理接口：

```sh
lake workflow manage < request.json
```

支持 action：`list`、`runs`、`status`、`events`、`validate`、`preview`、`save`、`amend`、`enable`。保存传 `lake` 与完整 `definition` 文本；修订额外传 `id` 和 `expected_revision`。执行沿用 `lake workflow run/resume`，桌面使用实时审批桥。

## 验证

### 会话内澄清问题

桌面和交互终端支持 `lake_ask_user`。Agent 需要选择目标、配置或偏好时，在当前运行中提出 1–3 个问题；每题可提供 2–3 个选项，也可自由回答。桌面点击“回答并继续”后，答案回到本轮工具执行，继续原任务，不新建一轮对话。只有一个问题时，也可通过主输入框直接回答。人工等待没有普通工具的 90 秒时限，退出会话会取消等待。

问题和回答作为有界会话事件保存。历史已回答问题显示结果，未回答且运行已结束的问题显示中断状态，不能向新运行提交；后续轮次和重启后保留已回答的澄清上下文。错误、迟到或重复回答不能解除其他问题的等待。澄清答案不替代 SSH/代码/MCP 操作审批；问题工具不索取或接受模型密钥和私钥等凭据。

### 原生 SSH 长任务

主 Agent 增加 `lake_script_start/status/wait/cancel/jobs`。已登记脚本预计超过 20 秒时，后台启动并返回持久任务 ID，主会话在同一轮通过最多 60 秒的只读等待持续跟进到终态。Go/Eino、普通 SSH 20 秒及专员 5 分钟的全局时限保留；远端依赖 Linux Python 3 和脚本使用的 shell/程序。

本机 `~/.lake/script-jobs/` 只保存不可变身份：任务 ID、资源 ID、SSH 目标摘要、脚本 ID/摘要、语言、最长运行秒数和创建时间。目录 0700、文件 0600，使用 fsync 和只创建一次的原子安装。远端 `~/.lake-script-jobs/<任务ID>/` 保存控制程序、脚本、配置、原子状态和有界输出；每个输出日志最多 128 KiB，查询只返回末尾 8 KiB。

启动响应丢失或损坏时，仍返回原任务 ID 和 `unknown`，只能查询；同一执行身份不会再次启动。工作进程与 SSH 连接分离，进程重启后可用 ID 查询和继续等待。连接恢复只在 SSH 命令派发前重试临时握手/连接错误；主机密钥或认证失败不重试，执行后的未知写不重放。任务所在资源撤权、越出冻结范围或 SSH 目标改变都会阻止控制请求，审批等待之后也重新检查。

启动和取消在 Agent 中保留统一执行审批及 SSH 审批；状态查询、列表与等待为只读。停止对话只停止等待，远端任务继续到配置的最长时间；远端取消需要单独批准，通过 TERM/KILL 终止该任务的前台进程组，再查询确认终态。脚本启动的外部服务、脱离进程组的守护进程或容器内部任务不保证随取消终止，脚本需自行设置外部命令的时间上限。工作进程消失或服务器断电可能成为 `unknown`，不会自动重跑。

```sh
lake script start <脚本ID> --resource <湖/资源> --timeout 720 --json
lake script status <任务ID> --json
lake script wait <任务ID> --seconds 60 --json
lake script jobs <湖名> --json
lake script cancel <任务ID> --json
```

专员收到确定的执行前拒绝可继续调整；父轮次失败时，已经交回结果的专员保留完成状态，执行中的专员才显示失败。相关修复及真实回归方案见 `plan/feature-script-longtask-1.md`。

## 工作流模型分析、目标任务及故障恢复实测（2026-10-01）
