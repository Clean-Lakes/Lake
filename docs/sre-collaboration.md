# Lake SRE 协作

此功能当前按项目显式开启。进入普通会话，在输入框旁开启 **SRE 协作**。主模型读取当前消息、已有对话（包括可用图片）、目标绑定与任务事实，决定直接回答、澄清问题，或通过协作工具组织专员。可以直接说资源名称或沿用上下文中的目标；`@资源` 是可选的选择方式，当前权限要求显式引用时仍需选择。需要模型；无需另开角色面板。

四个专员在同一对话回应：协调者建立与修订 Plan；调查员只读取证，区分事实、假设和缺口；执行员提交具体操作及影响；验证员重新采样验收目标。角色只在实际接手后发言，不强制每项任务都有四个角色。头像为最大 22px 的无背景湖生态图形。

专员按 Plan 的真实依赖协作：不同角色的独立就绪步骤同时运行，每个角色同时处理一个步骤；同一资源的操作仍通过资源锁依次派发。变更步骤独占调度，依赖变更的验收必须在变更结束后开始。每位专员拥有独立模型历史和完整工具循环，发言与状态随实际运行更新；最终回复按完成时间追加。任一步失败时取消其他在途专员，等待它们退出后再释放会话。

专员可用 `sre_team_update` 广播实质发现或向另一角色请求复核，消息在同一对话显示发起者与接收者。每轮模型请求获取有界的最新团队状态与消息，也可用 `sre_team_read` 主动查看状态、证据索引和已登记的原文；新证据在采集后即可共享，无需等专员结束。共享原文仅限当前任务、专员已分配且父会话仍授权的资源。其他专员的结论是待核对上下文，不能代替自己的独立采样，也不构成操作授权。消息不会隐式启动尚未调度的角色，不保证对方即时回复；专员应在自己的工作范围内处理请求，不能无限等待。旧只读任务在暂停后继续时，若仍有独立就绪的调查工作且没有验证员，并具备其他独立检查或可复核的既有证据，会先由协调模型重新分配剩余工作并保存新修订。原目标、范围、验收、交付物和依赖保留，已完成取证沿用原记录与时间并标记来源，不重新采集，也不算新的独立验收。升级后的计划至少有两位可实际开展独立工作的专员；不满足约束时保留旧计划与证据并明确报错。正在执行、有变更或存在未知结果的任务不自动升级；新计划与已明确协作的计划由模型根据上下文安排工作。

普通模式由主模型直接使用工具，不再启动旧 Scout／Trace／Deep／Beacon 委派。历史 `multiAgentMode=auto` 设置不再生效，界面不再提供第二套多 Agent 开关。历史子任务和证据保留，不自动重放。只有项目开启 SRE 协作后，才创建新的协作专员；关闭后可查看、暂停或结束历史任务，重新启动／继续执行需先开启 SRE。

专员继承普通 Lake 的完整工具目录，包括 Shell、持久终端、文件、SQL、Redis、Docker、已启用 MCP 和 Skills。领域仅用于组织职责，不把调查员限制为固定探针。工具调用继续遵守父会话当前授权、已分配资源与每次操作审批；父会话收紧权限后，子专员同步收紧。Shell 等不透明操作在实际派发前写入持久记录，结果不明时不重放。普通工具输出也会生成可分页的真实证据。专员可边解释意图、边调用工具、再根据新事实调整，正在执行的角色消息显示模型实际进度；最终结果仍由真实工具记录和验收约束决定。

- **只出计划**：说明本次只讨论方案。模型结合上下文选择 `plan_only`，Plan 保存在草稿，点击开始执行后才派发步骤。引用或解释“只出计划”这个词不会由程序直接创建计划。
- **修改与继续**：运行中先暂停并等待在途步骤结束；在卡片修改目标或步骤描述，或在对话说明新要求。描述编辑不改已绑定动作参数；具体动作参数通过对话重新制定。每次修订保存新版本。
- **确认操作**：确认卡片显示本次真实目标、影响、停止条件和折叠详情。按钮走现有操作审批；危险操作仍要求输入指定确认文字。当前会话的静默权限仍生效。
- **独立验证**：验证员运行独立的完整工具循环，可以补充主机、应用、日志或数据检查。自动验收另外使用声明的固定只读探针，按类型、阈值、样本数和时间窗计算结果；只计入运行时指定的本次采样证据，补充工具和模型结论不能替代验收。工具成功不等于业务恢复；无探针或证据不完整时保持无法确认。人工验收只用于计划明确声明的人工条件，并保存时间及来源。
- **结果不明**：进程中断后不重放已派发动作。先在操作记录“记录核实结果”，写明依据，确认已执行或确认未执行。前者跳过动作后重新验证；后者在继续时重新提交动作并遵守当前权限。人工核实不代表恢复验收。
- **专员追问**：可以点名或在 `@` 候选选择专员。主模型决定直接解释、请某位专员解释已记录事实，或安排新的调查步骤；引用不授予操作权限。普通追问不强制执行已有草稿。
- **历史**：会话操作中切到执行记录，展开执行流程与每个事件；可按任务筛选、分页读取历史任务与证据。修订与详情保存旧计划，消息锚点不会随更新移动。
- **导出**：结束任务后可导出 JSON 运行手册草稿。草稿保留来源，不自动成为项目记忆、可执行脚本或已批准方案。既有只读工作流另有显式 API 适配入口。

当前边界：验证不通过后暂停，由用户补充证据或修订计划，不自动尝试多轮处置。新老项目均默认关闭。SRE 入口暂不处理附件、资源导入和专用终端／数据库会话，沿用这些入口原有行为。保存的工作流通过 SRE 专员执行，项目未开启 SRE 时拒绝启动工作流；模板和历史仍可查看。没有新建全天候告警服务，也没有对现有生产资源自动执行演练。

任务事实保存在当前 Lake Home 的 SQLite 中，证据原文使用私有权限。Dev 只使用 Dev 或显式隔离 home，不能复制正式版凭据。

专员回复默认将成功操作收为一行可展开记录，失败、等待确认和未知结果仍直接可见。同次失败在对话中保留专员提示，不再重复显示父会话的系统错误副本。证据和完整操作原文始终保留。

自动上下文摘要收到未完成响应或输出额度耗尽时，最多重试一次纯摘要请求；仍失败则尝试保留原用户消息与调用身份、裁切模型侧工具输出预览，并至少预留 1/16 输入空间后继续。裁切不改变持久原文、不重放工具、不提交不完整摘要，也不能把缺失输出当成成功证据。不能安全缩减或已取消时仍停止；手动压缩失败不替换原历史。

主模型在正常聊天循环中选择是否调用 `sre_collaborate`，没有额外的关键词意图分类器，也没有固定的“请先 @ 资源”回复。该工具只登记交接意图；父回复结束后，服务端重新校验任务归属、资源范围和当前权限，再创建任务或交给专员。主模型不能直接通过 Shell／文件写入绕开执行员。模型推断出的资源不会自动记为用户的显式授权引用。

主模型每轮必须提交明确的收尾决策：`sre_collaborate` 实际交接工作，或 `sre_reply` 提交完整回答／必要的澄清问题。只输出“我先检查”等普通文字不会启动任务，也不算完成决策；程序会在同一轮提醒模型继续选择一次。仍未提交决策则显示失败，避免把未执行的承诺标为完成。路径继续由模型根据上下文选择，不按措辞触发资源操作。

完整子智能体继承父会话的模型上下文、单次输出额度、会话偏好与模型循环上限，拥有独立历史和正常上下文压缩，不再套用旧调查 Agent 的 32 次工具调用、34 轮循环、64k 累计用量或十分钟运行截止。子智能体可根据工具结果持续判断和调用工具，始终遵守外层取消和单次模型请求超时。任务累计用量仍持久计量，预算按创建时父会话的 contextWindow × maxSteps 计算，与单次上下文窗口分开；默认 64k × 500 为 3200 万累计 token 的最大运行额度，实际按返回用量结算，继续任务不清零。历史默认预算在继续任务时迁移并保留已用量，自定义较小预算不自动放大。仅纯计划 JSON 输出及报告格式修正阶段不下发执行工具；验证员先完成独立工具循环，再由运行时采集固定验收探针，使验收证据晚于本次复核中的操作。已声明的冻结变更必须有对应实际成功操作才能完成，自动验收仍使用运行时新采样计算结果。可选固定探针保留旧计划兼容，其相同成功采样会复用记录；验证员始终重新采样。预览裁切时，专员可分页读取自己本次运行的原文。无法形成有效报告时暂停并保留证据，不把工具成功冒充业务恢复。

正在执行的专员持续显示活动指示、实际阶段、耗时、工具调用次数与已采集证据数。阶段来自真实模型等待/思考、资源锁等待和工具调用；不显示虚构进度。结束、暂停、待确认和未知结果不展示正在执行动效，减少动态偏好停用动画。验证员使用原计划步骤、交付物及分配资源；无固定验收探针时保留其实际复核回复，但不会因此自动通过恢复验收。

Plan 对真正未知结果优先显示“结果待核实”，列出对应目标与工具，并提供“查看并核实”入口；在途操作尚未形成原记录时，该入口先按用户操作暂停任务。继续/修订的交接在主模型工具调用阶段就检查未知阻塞，返回可操作指引；正式答复替换本轮未执行的临时承诺，工具与决策历史保留。

桥接层确定尚未调用终端执行的参数校验或空闲终端校验错误，使用类型化“未执行”结果，不再误判为未知。传输错误、执行后超时和未收尾的后台操作仍是未知。重启时仅对历史 Shell/终端命令的精确运行时错误 Invalid command 且原参数确实不能通过本地校验的记录纠正为未执行，记录运行时核实来源；不重跑、不清除其他未知，也不基于任意错误文本断言成功。

## 官方 ADK 执行与恢复

四个角色的模型与工具循环统一由官方 ADK Go v2.6.0 LlmAgent/Runner 执行；计划 DAG 编译为 WorkflowAgent 的 FunctionNode、依赖边和 JoinNode；ADK 调度就绪节点、依赖汇合、失败取消及同伴退出。角色串行与变更独占作为业务约束编译成额外依赖边。Lake 继续负责计划版本、权限交集、资源锁、预算、真实证据及确定性验收。协调者的计划生成与格式修正阶段不获得资源操作工具。`EvaluateSREChecks` 对冻结探针来源、目标、字段、比较算子、样本和时间窗做不调用模型的判定；模型描述不能升级验收结论。

审批和专员问题可在进程重启后恢复到原角色、原 attempt 和原调用。正常运行中，同一个角色的一批工具按顺序执行；独立角色仍并行。停止会等待子任务退出，已经发出的远程命令按原句柄观察；未知结果不会自动重发。界面中的人工核实只记录实际结果，不执行命令。恢复与备份边界见 [ADK 运行时说明](experiments/adk-runtime.md)。

### 只读超时与变更结果不明

SRE 操作保存运行时计算的 `risk`。只读检查超时保留原始 `unknown` 记录和错误，表示没有取得完整采样；可在同一专员中用新的调用重新检查，也可继续或重新开始暂停的只读调查。新采样有独立调用及证据，不能把它的完成记录归给旧超时。旧记录缺少风险字段时，按保存的实际工具和参数用当前可信策略判定；不能依据模型声称、角色、任务名或“超时”字样降低风险。

`unknown` 且不能证明为只读的操作仍需核实，继续、重开、修订计划都不能绕过。新的只读检查可以用于检查实际状态。普通会话可从侧栏会话菜单进入“执行记录”，按需展开“待核实操作”；先停止当前运行，再根据原目标、原句柄或日志选择实际结果并填写依据。该入口只记录核实事实并保留审计，不重发操作；仍无法确认时保持未知。`dispatched` 表示仍在运行，只显示进度并等待原句柄结果；不能重复派发，也不要求人工把正在运行的操作判为成功。

只读检查未获得完整结果且没有后续成功采样覆盖时，步骤未完成，不能由模型报告补成成功。聊天回复结束显示“回复结束”；任务暂停、变更待核实、任务完成以及结论不充分分别按实际 SRE 状态展示。普通聊天的完成事件不能把暂停的任务改成绿色完成。

### 编排与生命周期归属

SRE 不再在 DynamicNode 内维护另一套 running / completed 调度循环、goroutine 派发与 channel 收尾。每个计划步骤是一个 ADK 节点，多依赖步骤通过 JoinNode 汇合。ADK 负责实际执行与取消传播，Lake 的 attempt、AgentRun 和 PlanRun 状态作为兼容界面的执行投影与业务审计保留，不作为节点就绪和完成的另一套调度依据。

成功步骤返回带步骤指纹的结构化 Output，由官方 SessionService 连同 NodeInfo 持久化。明确继续同一计划运行时，复用该会话已有的成功输出，仅重新执行没有成功输出的步骤；失败、取消和进程丢失不是自动重试指令。此处是失败执行后的新 invocation，不能等同于 ADK 对 RequestInput 的原生等待恢复。审批和追问继续使用子角色原有的 ADK 等待与恢复机制。

旧记录没有新版节点输出时，可导入已证明完成的历史结果。变更的真实执行记录先于 ADK 节点输出保存；若在两者之间中断，仍依据已完成的实际变更记录去重，避免重新派发。未知结果、仍在执行的操作、权限交集、资源锁、冻结动作参数与验收规则继续由 Lake 约束。新版已存在节点输出时，普通步骤不再从 attempt 的成功标志决定是否执行。

等待状态统一由角色的实际审批／追问事件投影，恢复一个角色不会清除其他角色的等待。取消与失败分开记录，未知的资源效果独立保留。图执行结束后 PlanRun 标记结束；业务验收不满足时 Task 可以继续等待补充条件，不能把已结束的执行保持为运行中，也不能把模型回复结束当作业务验收通过。
