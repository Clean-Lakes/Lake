# 策略资产、学习与有界纠错

这些能力用于保存可检查、可回滚的个人工作方法，目前在 Lake Dev 验收，**所有新能力默认关闭**。无需安装 Harness² 或 Python 运行时；应用沿用官方 ADK Go 模型与工具执行流程。Python 仅用于仓库的开发验收脚本。

资产可以手写，也可以从真实纠正中生成待审核候选。保存、验证与采用是三件独立的事：**保存新版本不会替换当前采用版本，实验通过也不会自动采用**。来源关系用于追溯，不证明效果或因果。

## 从一条手写资产开始

1. 打开「工作区 → 设置 → 策略资产」，选择「用户全局」或「当前项目」。第一次使用时所有开关关闭。
2. 点击「新建」，填写标题、类型和正文。例如报告要求：`区分已观察事实、推测和待核实事项；给出引用依据，不把一次健康检查当作业务整体恢复。`
3. 按需填写场景、资源类型；留空表示该维度不限。场景支持 `core`、`terminal2`、`db-query-editor`；多个值使用英文逗号。领域标签必须由可信宿主明确提供，当前没有标签时不会匹配带标签资产。
4. 点击「保存新资产」，检查正文、版本及来源，再点击「采用此版本」。采用绑定的是准确的资产 ID、revision 和内容 hash。
5. 打开全局「总开关」和「应用已采用资产」，保存开关。项目尚未保存独立设置时继承全局；项目已经保存时，也必须允许应用。
6. 发送新消息。旧轮次不会被悄悄改写；实际模型请求有 PromptManifest，可追溯本轮采用/排除的版本。

先只开启应用即可。无需同时启用学习或纠错。普通对话、终端和数据库编辑器支持资产注入；SRE 协作角色、工作流等使用不同的提示词契约，当前不注入这些用户资产。在线纠错是独立能力，可以在受支持的只读 SRE 调查中使用。

## 开关、作用范围与优先级

界面的勾选值需要点击「保存开关」才生效；同时查看面板中的当前有效状态。

| 开关 / API 字段 | 行为 |
| --- | --- |
| 总开关 `masterEnabled` | 控制所有新增策略能力；关闭后不新建学习/优化任务，后续轮次回到原策略 |
| 应用 `applyEnabled` | 在支持的场景中注入已采用的准确版本 |
| 学习 `learnEnabled` | 从符合条件的真实纠正/终态证据生成候选，不自动采用 |
| 纠错 `correctEnabled` | 允许显式的有界快照优化；也是在线纠错的总限制 |
| 在线只读纠错 `onlineCorrectEnabled` | 另行同意正常任务中的受信只读纠错；P6 旧设置没有这个同意时保持关闭 |

有效设置取全局、已保存的项目设置和场景限制的交集。项目只能收紧，不能越过全局；预算取较小值。未保存过项目设置才是实时继承，保存过后不会自动跟随全局放宽。

提示词由固定权限/安全规则、内置策略和用户策略/当轮上下文组成。历史偏好不能覆盖本轮明确要求、固定工具 schema、权限、审批或未知操作核实规则。

同一资产的项目绑定覆盖全局绑定，包括项目显式停用；同标题的不同资产不会互相覆盖。优先级 0～1000 仅影响排列与输入预算，不代表更高权限。同一互斥组存在多个适用成员时全部排除，需用户解决；不自动挑一个。正文相同会去重，资产输入总预算有限，排除原因记入清单。

已有手写 Skills 和项目记忆仍按原规则运行。策略总开关不会将它们一并关掉，也不会将候选自动写入 Skill 或项目记忆。

## 编辑、导入、回滚与删除

- 编辑后「保存为新版本」，查看与父版本的正文差异；想让它生效，需要再次「采用此版本」。
- 选择旧版本并「回滚到此版本」，新增采用事件，影响后续请求。原版本、运行证据和外部操作账本保留。
- 项目内可查看并覆盖全局资产的采用状态；编辑全局正文需要切回全局管理范围。
- JSON 导入先载入待确认正文，保存为新资产。导入文件的来源、验证等级、采用声明不作为可信证据继承。导出资产或 `SKILL.md` 供用户检查、移植，不自动安装。
- 从已登记、启用的 Skill 导入的是正文快照，原文件保留。应用还需要读取权限；源文件改动、停用、不可读后旧快照停止应用，需重新导入并确认。
- 「来源与采用历史」可查看版本、来源 hash、提取/优化/评估/采用关系及时间。其他项目的私密正文不会因为全局引用而开放。
- 删除资产会停用并清除正文快照，保留不含正文的追溯身份；撤回学习来源会阻止后续应用/提交并清除相关私密副本。清理实验原文与删除正式资产不同，已经明确保存的资产版本不会因此被冒充删除。

桌面端的删除与放弃编辑会在页面内再次确认。「返回编辑」或 Escape 保留正文；「确认操作」才执行。不要把关闭设置窗口当作保存。

## 从真实纠正积累候选

在当前项目开启总开关和学习后，受支持的普通轮次会观察真实用户纠正、配对的工具失败等信号。也可在「学习候选」中登记当前项目真实用户消息 ID、选择来源并生成候选。不会扫描历史批量学习，也不会因普通问答反复生成。

提取使用有预算的无工具请求；候选、提取任务和来源可检查、取消或撤回。候选标为「单次观察，效果尚未验证」，必须人工检查是否泛化过度、是否含敏感内容，再单独采用。自身的反思/候选/实验不会成为递归提取的新来源。无来源、权限变化、过期 worker 或不合法结果不能提交新资产。

## 快照评估与有界优化

在当前项目的「隔离快照实验」选择准确资产版本、开发案例及保留案例。内置 15 个合成快照（12 个开发、3 个保留），覆盖磁盘、日志、容器、数据库、连接/权限/能力缺失及无关对话。它们不连接真实目标，不执行故障注入。

普通快照对比仅支持 A「内置策略」与 B「指定资产」；在线纠错 C 不在这个执行器里。保留集不能用于生成提案，固定评分规则不会发给优化模型。复位失败、未知 usage、调用失败都应保留，不算候选获胜。

有界优化按「基线开发 → 提案 → 提案开发 → 合成 → 合成开发 → 基线保留 → 合成保留」执行，含 5 次独立试跑、2 次无工具辅助请求，共用一个总预算。合成版必须重跑，不能把候选分数相加。没有进展、额度耗尽或关键退化时停止，允许没有胜出候选。

临时候选不会改变正式资产。检查完整报告后，「确认保存合成候选」仅新增正式版本，并记录真实血缘；采用仍需另外确认。`fixture_validated` 只表示通过指定合成快照，不能当作真实服务、多模型或生产有效性证明。

已保存的已知阶段可能显示「从已保存阶段继续」；继续会重验模型、Skills/记忆、来源、设置和剩余预算。崩溃时已派发但结果未知的调用保留 `awaiting_reconciliation`，不能自动重发；重启、换角色或修改计划不重新领预算。

## 在线只读纠错如何停止

需同时开启总开关、纠错及**独立的在线只读纠错**。它只在实际出现失败且宿主能够证明操作只读时介入；简单问答不会因此采样，也不会自动启动实验。

一次修订需要明确源证据、被否定假设、具体修改、预期信息、停止条件和下一项准确的只读检查。工具说明、日志或模型声称“安全”不能成为授权。任意 SQL、MCP 不透明操作、写入/传输、换目标及后台操作均不能作为在线自动重试。

原失败或 unknown 记录保留，重新采样使用新的操作身份。只有同一可信检查在同一目标取得真实成功结果才关闭相应缺口；读到别的日志、换措辞或模型说“已恢复”不算。检查缺口关闭也不等于业务恢复，仍须满足原任务验收标准。

| 初期硬上限（项目/父任务可更严格） | 数值 |
| --- | --- |
| 同检查额外只读采样 | 2 次；不叠加已有底层重试 |
| 策略修订 / 连续无进展 | 各 2 次 |
| 顶层实验 / 变体或在线观察 | 并发 1 / 总数 6 |
| 新增阶段模型请求 | 12 次，包含辅助、报告和恢复请求 |
| 附加累计 token | 100000；usage 未知保留保守预留，不记零 |
| 活动时间 / 单次人工等待 | 600 秒 / 24 小时 |

任务卡显示原证据、实际版本、修订、缺口、请求/token 和停止原因。计数是纠错阶段总用量，包含最终报告，不是相对关闭模式的净增量。

| 停止原因 | 后续处理 |
| --- | --- |
| `completed` | 只表示记录中的检查缺口已闭合，查看真实结果和业务验收 |
| `no_progress` / `budget_exhausted` | 查看已尝试事项，人工决定新任务；不直接清零重试 |
| `permission_blocked` / `target_ambiguous` / `capability_missing` | 先明确授权、目标或能力；不能通过改写提示词绕过 |
| `awaiting_reconciliation` | 检查原操作的真实状态，走既有核实流程；不自动重发 |
| `awaiting_user` | 仅符合恢复条件时显式继续，沿用原预算并重验设置/权限/有效期 |
| `cancelled` / `failed` | 保留历史，检查错误和在途状态后决定下一步 |

## 关闭与退出演练

1. 在 Dev 选择要退出的范围，关闭在线纠错、纠错、学习，或直接关闭总开关，点击「保存开关」。关闭总开关最直接；全局关闭可限制所有项目。
2. 查看运行任务及实际操作账本。设置变更会使旧策略轮次失效并停止后续派发；已开始的原任务/外部动作按原有取消与核实语义收尾，不能声称外部效果已撤销。
3. 需要时在学习/实验列表取消任务。已经在途的未知请求或操作保留身份与审计，不删除库、清空上下文或恢复旧数据库来掩盖。
4. 发送新消息确认没有资产注入或新增纠错请求。已有手写 Skills/记忆按原规则保留，资产正文和采用历史仍可查看。
5. 重新开启只影响新的允许请求，不追赶历史、不自动恢复旧实验。重启后查看旧报告和预算是否保持；需继续的已知任务由用户显式操作。

回滚采用绑定与回退应用程序不同。当前 Web 策略存储为 v4，升级前生成兼容备份；未知 schema 拒绝打开。旧二进制可能没有拒绝新库的能力，**只能在隔离 Home 离线打开迁移前的兼容副本**。不能恢复旧库覆盖最新操作账本。macOS 回退也必须使用兼容的签名构建。

## 开发验收与推广门槛

本阶段不发布正式版。验收状态及 V01～V16 映射见 [P8 验证记录](validation/lake-strategy-learning.md)，各阶段原始边界见 [开发计划](../plan/feature-strategy-learning-1.md)。

本机/目标平台可运行不需要凭据的专项回归：

```sh
python3 scripts/verify_strategy_learning.py --report /tmp/lake-strategy-regression.json
```

它输出本机 OS/架构、提交、dirty、真实测试身份/状态及退出码，原始日志留在报告旁的私有文件中；报告不会自行宣布桌面、真实模型或跨平台通过。

macOS 签名 Dev 集成演练（先按 [开发规范](../CONTRIBUTING.md) 构建，退出已运行的 Dev）：

```sh
scripts/build_lake_desktop.sh --dev --install
python3 scripts/test_strategy_learning_dev.py \
  --report /tmp/lake-strategy-dev.json --hold-for-ui
```

脚本校验当前干净提交、Dev Bundle ID、签名和后端 hash，创建全新私有 Home，只使用无密钥 loopback 模型夹具。A/B/C 各运行 3 次，轮换顺序、每臂独立 Home、服务状态复位；随后在原生 Dev 演练运行中关闭、重新开启及无关对话。提示窗口准备好后，检查面板、版本、确认步骤、浅/深色、窄窗口与键盘，**正常退出这一个 Dev**；脚本再用同一个签名后端检查重启不重放、报告/预算保留和两个 SQLite 库完整性。UI 是否合格需人工另记，脚本不会自动打勾。不要同时开第二个后端使用该 Home。

可靠性脚本的模型输出被固定，只能说明控制流与成本计数符合预期。[补充验收](validation/lake-strategy-learning-p8-completion.md) 使用明确配置的 Dev 模型，记录了 16 个真实隔离案例、三类任务每臂三次配对和数据库任务族的 M2 真实执行链。结果为 inconclusive：C 臂有停止样本，合成候选未通过固定保留检查，保留基线。三类通用保留案例的基线不能当作合成候选的胜出证据；没有跨模型或生产推广结论。

真实验收测试默认跳过，仅在显式指定 Dev 模型时访问该提供方、产生实际请求用量；不从正式 Home 导入凭据。在干净源码上执行，三个报告必须指向本机私有位置：

```sh
LAKE_P8_SOURCE_COMMIT="$(git rev-parse HEAD)" \
LAKE_P8_DEV_MODEL_HOME="$HOME/.lake-dev" LAKE_P8_REAL_SERVICES=1 \
LAKE_P8_SMOKE_REPORT=/tmp/lake-p8-provider.json \
LAKE_P8_LIVE_REPORT=/tmp/lake-p8-services.json \
LAKE_P8_OPTIMIZATION_REPORT=/tmp/lake-p8-optimization.json \
go test -race ./internal/web -run '^TestP8Real' -v -count=1 -timeout=30m
```

测试要求本机可用的 Docker（预置 `docker.io/library/postgres:17-alpine`，记录实际镜像 ID）、curl、lsof 和非 root 文件权限身份；只创建并清理自己的临时容器/文件/监听器。宿主负责制造和复位故障，Actor 只有准确的只读观察权限。`LiveRead` 是 Go 宿主专用回调，不能由 HTTP 或模型设置；普通界面的实验仍为合成快照。运行完成只表示完整采样和记录，不表示答案全部通过或候选可采用。

CI 仍只在同仓库 `develop → master` 提升 PR 自动运行，或用户明确要求手动触发；日常 `develop` PR 不运行。ADK 平台工作流补充 Linux/Windows 专项报告。macOS 容器/交叉编译不能替代 Windows 实测；平台结果未收齐时不得宣称发布验收全部完成。
