# 人工策略资产与历史记录（实验）

> **C1 已停用新增执行。** 在线纠错、自动/手工候选提取和产品内新增 A/B 实验不再运行。已保存的资产、采用绑定、来源及历史报告保留；项目记忆、Skills、正常工具失败处理和 Pilot 按原边界工作。

人工资产仍为实验能力，初始默认不应用。原有用户选择保留；一次采用只绑定准确版本，不证明内容有效或答案正确。后续按 [清理计划](../plan/refactor-harness-inspired-cleanup-1.md) 收敛人工内容和入口，C2～C4 尚未实施。C1 契约见 [执行退役](design/strategy-execution-retirement-c1.md)。

## 自然记忆承接基础

原策略资产按[自然记忆计划](../plan/feature-natural-memory-1.md)重塑。N1 在当前策略资产页增加“记忆内容承接 · 实验”：可预览已采用偏好的准确正文、范围和条件，确认纳入记忆管理，再从承接记录撤销。承接及撤销只整理管理归属，当前仍按原设置使用，不停用原绑定或复制正文；旧内容改变会提示待核对，来源失效后不可读。

自然形成、自动整理、压缩补提取与新召回尚未开放，新自动记忆不可开启。原有项目记忆使用/提炼与原偏好开关保留；该入口不改变 V2 门控。完整契约见 [N1 基础](design/natural-memory-foundation-n1.md)。

## 保存和应用人工内容

1. 打开「工作区 → 设置 → 策略资产」，选择用户全局或当前项目。
2. 新建或编辑正文，保存后检查准确版本、来源和适用条件，再选择「采用此版本」。历史待审核候选也可明确审核、采用或拒绝，不会自动激活。
3. 「人工资产应用」仅保留总开关和「会话应用已采用资产」。全局与项目仍取交集，项目停用覆盖同一资产的全局绑定；保存开关后对新请求生效。
4. 在新轮次验证行为；可在使用记录查看实际准备的准确版本和排除原因。记录不证明供应商已接收、模型遵从或任务改善。

普通对话、终端与数据库编辑器仍支持原有人工资产应用。Pilot 协调者、专员和工作流暂不应用这些资产；不要把普通对话复用当作专员复用已交付。资产不能覆盖当轮明确要求、工具权限、审批或未知操作核实规则。

原有关键词、有效期、待复核、模型/工具变化及来源检查继续限制旧绑定。尚未实施偏好迁移，不会把复杂方法自动转成通用用户偏好，也不会批量写入项目记忆或安装 Skill。

## 编辑、范围与来源

- 编辑产生新版本，不替换当前采用绑定；可明确停用或回滚到已有版本。
- 用户全局和项目范围维持原授权。项目内容晋升为全局仍需检查最终正文、适用条件并明确确认，不开放私有消息或原项目血缘。
- 来源撤回、权限收紧、资源或项目归档继续限制派生内容。重新启用或恢复归档不复活已撤回正文。
- JSON/Skill 导入仍是正文快照，导出不等于安装；源 Skill 被修改、停用或不可读时，旧快照不能绕过来源检查。
- 删除资产或撤回来源仍使用原确认与正文清理流程，保留不含正文的必要身份和审计；C1 没有批量删除任何内容。

## 历史候选、来源和实验

「历史候选与来源」可查看原提取任务、已知用量及未知预留，按权限撤回已有来源。没有“登记纠正来源”或“生成候选”操作；聊天中的「以后请」「纠正一下」不再触发策略提取。用户明确要求写项目记忆时仍走项目记忆原有独立意图/版本检查。

「历史对照实验」可查看、导出脱敏报告或清理原文，不再选择场景、发起、续跑或保存优化候选。旧实验结果与原 P8/R5 的 inconclusive 结论不改写。原始实现说明可在 [C1 前版本](https://github.com/Clean-Lakes/Lake/blob/081d66520dfc8f958a8eebbd84b675a183113613/docs/strategy-learning.md) 查看，不能按其步骤重新启用执行。

旧纠错卡仅供回溯；取消或机制停用不代表原外部操作被撤销，检查缺口关闭也不代表业务恢复。`awaiting_reconciliation`/unknown 仍保留真实调用身份和预算，不自动重新派发或退款。

## 升级与兼容

- 启动在恢复任务前持久停用 learn/correct/online，原选择和设置 revision/epoch 保存到 `retiredExecutionChoices`；人工总开关、应用、绑定和正文保留。
- 确定未派发的旧任务退役；有 intent、已派发或结果未知的任务保留 unknown/待核实。已完成结果不改成成功或重新执行。
- 老客户端再提交启用字段，或调用新提取/新实验/续跑等退役写接口，会得到 HTTP 410；旧幂等回执不能复活执行。合法历史访问、撤回和人工资产操作仍可使用。
- schema 仍为 v6；原 SQL 迁移、hash 与历史表保留。代码回退须在兼容离线副本验证，不能恢复旧数据库覆盖最新任务、来源撤回或操作账本。更旧的二进制不具备 C1 的接口拒绝能力。

## 开发验证

日常检查使用本地 Go、必要 race/vet、ADK 边界检查和前端检查，在签名 Lake Dev 验证。新执行退役后，旧“生成候选成功/启动实验成功”脚本不再是可运行验收步骤；通用消息等待回归与历史证据保留。不会为清理重新跑真实模型收益试点，也不自动触发手动 CI。

## N2 自动形成偏好（实验）

在“策略资产 → 自动记忆 · 实验”按当前项目或用户全局分别主动开启。只处理开启后的真实新消息；例如“以后这个项目的报告先列证据”无需额外说“记住”。完成轮次后由共享后台提炼，持久成功才轻提示查看/撤销，不阻塞任务。关闭停止新增，正文保留；遗忘会删除该偏好的全部正文历史，撤销不会覆盖更晚修改。

本阶段交付积累和管理，新偏好尚未接入后续回答；N3 的语义整理、N4 的压缩补提取、N5 的范围召回继续按计划推进。原项目记忆和已采用人工资产仍按原设置使用。新同意不继承旧学习/纠错开关，不开启运维 V2。具体来源、准确版本、限额和 API 见 [N2 契约](design/natural-memory-formation-n2.md)。
