# 默认并行节点巡检

2026-10-12。

修复通用运维已经选择集群节点，但仍只有 Lake 反复执行 inspect_host / shell / terminal 轮询的问题。旧版“自动”只提供委派工具，由模型决定调用；新版在明确只读巡检和至少两个主机目标时，由服务器固定启动真实 Scout。

- 五节点按节点启动五个 Scout。2–7 节点每节点一任务；8–21 节点均衡分配最多七个任务，每任务最多三节点；超过二十一明确提示缩小范围，不遗漏目标。
- 每个任务先通过既有工具和权限采集固定只读 status 观察，再调用独立模型汇总。status 包含主机概览、进程、根/前二十五项磁盘统计和 kubelet 服务状态，不读取 kubeconfig 或凭据，不执行任意命令，也不接管用户终端。
- 六个观察槽、六个执行实例、三个子模型槽；沿用每任务两分钟、每观察十秒、每模型四十五秒、每轮八子任务和用量预算。
- Beacon 使用原始证据前序再做一次独立模型核验；Lake 接收已完成的真实结果，并只处理缺失观察或必要的集群 API 后续。kubelet 服务活跃不能当作 Kubernetes Ready / Pod 健康。
- “继续啊”从最近明确的只读请求继承目标；相同节点范围、所有任务完成且独立验证完成、证据不超过六十秒时复用，不再重复采集。刷新、失败、节点变化或过期会重新检查。
- 关闭多 Agent、单节点、模糊目录、变更请求、用户明确要求串行以及缺乏诊断意图不自动分派。子任务保持目录/资源范围、禁用本机等权限，未知 SSH 主机密钥不会自动信任。
- 完成后若新调查又产生证据，必须重新独立核验；取消整轮会释放观察和模型槽，不启动后续核验。失败原因使用节点名称，不显示内部调用 ID。
