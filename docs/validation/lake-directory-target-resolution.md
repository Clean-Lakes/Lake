# 按项目目录解析运维目标

2026-10-12。

修复案例：侧栏“南京公司 / 新k8s集群”包含五个 SSH 节点，用户说“k8s新集群，目录下就是新集群的节点啊”，旧版未向模型传递目录路径，并在缺少 @ 引用时预检查旧绑定主机，进而根据本地 kubeconfig 推断目标集群。

本次实现：

- 模型接收工作台实际目录层级与递归资源数量。资源列表包含 folder_path / folder_names，新增 list_resource_groups；list_assets 支持 folder_ref / folder_path 精确目录查询。
- 基于实际名称对应目录，容忍“新k8s集群 / k8s新集群”的相同字词顺序及空格变化。目录和磁盘路径区分；词缀不同、否定提及、未知目录、同名目录、空目录与删除目录不猜测执行目标。
- 当前目录覆盖旧的主机、终端和本地 kubeconfig。此次目录修正先交给模型解析任务，不对旧主机作自动检查。普通工具、终端及子 Agent 在执行前校验目录范围。
- 后续追问保持范围；明确 @ 资源或明确说出唯一可见主机 IP 可以切换目标。清空资源引用同时清除范围。操作、终端创建和文件审批保持原有权限。
- 目录查找的操作记录显示“项目资源目录”，不再错误标注旧主机。

验证：

- Go 全量 AI race 测试通过；全量 Web race 测试通过（147.777 秒）。新增边界行为之后再次运行目录、工作流、资源树、子 Agent、资源引用和工具 schema 的针对性 race 回归，通过。
- 前端 79 项测试和 TypeScript 构建检查通过。
- 浏览器真实后台、临时 Home、测试模型、五个测试 SSH 资源：输入截图原句后正确列出五个目录节点，无旧主机预检查，无终端连接，无本地 kubeconfig 读取，无 JavaScript 异常。该测试没有连接生产 SSH 或生产模型。
- macOS 使用 scripts/build_lake_desktop.sh 构建并安装 arm64 签名应用；保存 ZIP/DMG 与旧应用备份。bin/lake 与整个 Lake.app 签名验证通过。
