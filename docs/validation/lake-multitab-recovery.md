# 多标签页实时连接堵塞修复

2026-10-11。

现场：Chrome 同时开着多个 Lake 标签页，localhost:4177 上有六条浏览器长连接。后端 bootstrap/catalog 正常，无执行中或待批准轮次；当前页显示正在获取会话和实时连接断开，草稿“容器呢”未提交。这符合 HTTP/1 同源六连接被 SSE 占满、快照请求排队的情况。

修复：Go 服务最多四条实时事件流，额外订阅快速返回 429 与 Retry-After，保留 HTTP 请求容量。前端实时流受限或中断时每两秒查询最新快照，查询成功后允许操作，查询失败仍阻止操作。已有查询连接健康时，SSE 重试不会反复禁用发送。隐藏标签页释放实时流及查询计时器；再次可见时拉取新快照并恢复订阅。页面离开或切换会话取消旧快照请求，快照查询有十二秒超时。

验证：针对 HTTP 鉴权、SSE 回放与四个常驻流下更多订阅拒绝后仍能查询快照/提交配置的 Go race 测试通过，go vet、9 个前端测试、TypeScript/Vite 构建、严格签名与无 Node 二进制运行测试通过。独立服务保持四个合成事件流，浏览器额外订阅被拒绝时仍完整加载会话，填入测试草稿后发送按钮可用；未调用商业模型和真实 SSH。

确认真实服务无执行/待批准轮次及忙碌终端后更新；恢复用户原 Chrome 标签页，完整历史正常加载，恢复未发送草稿“容器呢”，发送按钮可用。没有替用户发送。截图 lake-multitab-recovered.png。临时测试服务和标签页已清理。
