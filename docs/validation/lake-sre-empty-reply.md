# SRE 开关下的空白回复修复

日期：2026-10-16。

根因：SRE 缺少目标时，通过 Store 保存 assistant 提示而没有生成模型卡片；旧 timeline 根据 AI.startedAt 隐藏其后全部 assistant 消息，造成正文不可见、仅剩完成耗时。既有消息没有丢失。

修复：先按原时间投影原生消息，仅在同一用户轮次存在内容相同的实际回复卡片时去重；不同提示、不同轮次保留。原生 assistant 使用 Lake 署名。无活动 SRE 任务时，“再试试”“重试一下”“？”沿正常对话路径进入模型，不因项目启用 SRE 而被要求先选资源。已有活动 SRE 任务仍走原编排入口。

验证：TypeScript 检查通过；164 项前端测试通过；Go 分类与短追问 HTTP 回归通过；相关后端 race 回归通过。隔离合成模型验证两轮短追问都得到正常回复，且没有创建 SRE 任务。没有向用户配置的模型补发测试消息。

通过 scripts/build_lake_desktop.sh --dev --install 重新签名构建安装。在确认 Dev 无活动任务后重启；复核原会话已显示两条原先被隐藏的提示，无需重发。界面截图仅保存在本机 /tmp/lake-empty-reply-dev.jpg，不将实际资源目录或会话内容加入仓库。原生 UI 自动化读取超时，本次复核使用当前 Dev 后端的同一前端页面。

后续修订：同日移除了上述“短追问固定绕过”的临时路由处理。现在所有启用 SRE 的普通会话统一进入主模型，由模型根据完整上下文选择直接回应、澄清或通过协作工具交接；不再输出固定的先 @ 资源提示。原消息展示与按实际卡片去重的修复保留。见 lake-sre-model-coordination.md。
