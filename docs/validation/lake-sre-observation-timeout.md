# 调查采样成功但反复观察至超时

日期：2026-10-16。

通过 Dev API 只读检查用户报告的暂停任务：首步骤运行约 120 秒，已经保存五项成功证据，后续步骤尚未启动。记录显示重复主机概览／进程采样，并发生两次模型上下文摘要。主机概览的 JSON 中 `disks` 排在 `output` 之前，大量容器挂载记录占满 4000 字节模型预览，实际 CPU、负载和内存输出被截掉。模型因缺少可见信息反复采样，最终耗尽步骤时间。

修复：

- 大型主机观察预览优先保留原始输出，依旧做脱敏、有效 JSON 和字节上限校验；完整 JSON 原文与解析字段保留。
- 调查员允许分页读取自己当前运行的原始证据，禁止借用其他专员的证据。
- 相同成功探针及参数在调查步骤内复用证据 ID、采样时间；不把重试标成新样本。验证员不使用此缓存。
- 每个调查步骤最多四次工具调用，保留报告阶段；75 秒采集截止后转入无工具报告，总截止仍为 120 秒。模型采集请求提前超时也进入报告阶段，不重放工具。
- 调查上下文按确定性规则裁切，保留工具配对、证据 ID 和源信息，不再额外请求模型摘要消耗报告时间。
- 真正超时仍暂停，错误说明阶段和已保存证据数，不把成功采样当成完整调查或恢复结论。

新增回归覆盖大型磁盘数组遮挡 CPU／内存、预览脱敏、原文保留、重复采样复用、自己的证据分页与越界拒绝、采集截止仍可生成报告、无额外模型摘要，以及用尽工具额度后基于真实证据生成有效报告。

不重新执行用户服务器操作，不改写原有失败记录。使用合成模型、临时日志与隔离测试数据验证。

验证结果：定向回归、`go test ./...` 与 `go test -race ./internal/ai ./internal/web` 通过。使用 `scripts/build_lake_desktop.sh --dev --install` 构建安装并校验签名，在确认无活跃会话后重启 Dev，API 正常、原有八个会话及暂停任务的五项证据均保留。

签名二进制另做隔离 HTTP 验收：合成模型连续请求相同日志四次，实际只生成一项采样证据，随后进入无工具报告并完成两个计划步骤。验证的是运行协议、证据和时限处理，不代表已经重新验证用户服务器的调查结果。
