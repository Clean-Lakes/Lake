## 问题与行为

真实任务累计用量为 236,780 / 256,000 tokens，虽未用完 500 轮，但剩余额度不足下一次完整请求的预留。原实现只在 provider 前拒绝，未持久保存这次拒绝对应的暂停状态；调度与后续消息检查只覆盖轮数，任务投影也缺少具体原因和摘要。Web 在执行中断时再次追加 system 错误，并使用最后一条工具前叙述作为专员报告，导致正文重复错误、Pilot 只能回复“继续跟进”，没有新的服务器结果。

现在拒绝预留的同一事务写入 canonical goal 的暂停、Assignment 的 `model_budget_exhausted` 原因，以及一条幂等的 Pilot attention outbox。原预算计数、上限、期限、资源绑定和验收条件保持原值。排队、执行槽分配和 provider 再次检查这项限制；真实后续输入仍持久保存，不假标为已送达或已消费，不借新任务逃避额度。

旧版本已保存的同类引擎错误可由监督器恢复为暂停，只读取当前项目受阻/暂停任务的原投影，按 Worker generation 重验，避免迟到写入影响新的执行；没有重放模型或工具。每代只核对一次，没有每两秒重新读取整份历史的扫描。没有新增数据库列、schema 迁移、授权路径或额度扩展入口。

任务视图和路由回执传递 canonical state/reason/summary，Router 明确区分接纳输入与实际派发。Web 不再重复写预算 system 错误，也不在失败时发布工具前叙述作为结果。专员正文由原诊断投影出一条当前暂停说明，原始错误仍保存在执行记录；侧栏、页眉和检查详情显示暂停原因，仍需实际验收才算完成。
