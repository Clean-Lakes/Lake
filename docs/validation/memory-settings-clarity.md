# 记忆设置页的信息层级整理

2026-10-29，PR #121 的界面反馈改进。用户指出记忆设置中的开关、偏好和整理状态混杂、难以理解；本次集中调整设置页展示。

实际验证代码见 [checks.json](memory-settings-clarity/checks.json)。原[退出验收](legacy-asset-exit.md)的数据迁移与执行边界结论保留。

## 用户看到的变化

- 先选择「当前项目／所有项目」，再看到「自动积累偏好」和「回答时使用偏好」两个独立开关，每项只有一句说明。
- 「已保存的偏好」直接展示正文，不再用代码框、版本号和来源计数作为标题。来源/版本按需展开；已撤销和遗忘的条目收进修改记录。
- 需要确认的当前矛盾单独提示。修改记录、整理状态和机制说明默认折叠，0 项后台计数不占主页面。
- 移除无关通用页脚。项目事实与经验保持独立入口。
- 遗忘先确认，解释正文及历史副本会删除；取消和 Escape 恢复原按钮焦点。确认冻结准确版本，期间偏好更新会阻止继续删除，须重新查看。
- 私有来源的会话/消息标识不进入变更详情；实验标签、原范围授权、准确版本 API 和两个独立设置契约保留。

## 已运行检查

前端类型检查、536 项测试及构建通过。回归包括开关独立值/加载锁定、正文展示与折叠详情、私有来源身份隐藏、暂缓不冒充完成及原范围/CAS API 契约。Windows 客户端测试交叉编译和内嵌 UI 脚本语法检查通过；本次未运行 Windows 原生 CI，WebView2 缺口仍保留。

真实 macOS Lake Dev 验证了默认折叠、项目与所有项目范围切换、正文与修改记录、整理状态、遗忘确认/取消/Escape，以及浅色、深色和 1003px 窄窗口的控件与裁切。项目开关保持积累关/使用开，所有项目保持两者关；测试后恢复项目视图、浅色和原窗口宽度。

对照验证前后的 55 张记忆/历史审计表，逐行 hash 全部不变；仍有 8 个旧资产和 6 条自然偏好。只读查看和取消遗忘未造成删除或新的开关同意。
