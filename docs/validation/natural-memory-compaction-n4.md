## 持久化、回退与验收中修正

运行前以 SQLite backup API 对两个 Dev 数据库做私有一致性备份，并记录 29 个原有记忆相关表的行内容 hash。固定版本首次启动、发送本次新样本之前，这些 hash 保持一致；最终版本重启时又核对自然记忆表一致。数据库完整性检查为 ok。未执行 SQL 迁移、批量删除原资产或重置操作账本。

使用隔离数据库副本执行 **N4 → 已安装旧 Dev（54a117c9）→ N4** 的窄范围兼容检查：只启动并读取正常静态设置，无任务执行、无模型请求；自然记忆表 hash 一致、偏好 v3 保留，两库 integrity_check 均 ok，无复制密钥，日常 Dev 不受影响。这不代表任意旧版本或旧版执行任务后的写入兼容。实际回退应停止 Dev，使用经过验证的版本和对应一致性备份；不拼接单表恢复或清理未知操作记录。

验收中发现并修正：

1. 空证据 `[]` 经 JSON omitempty 往返变成 nil，导致来源身份漂移并阻断既有组合提交。统一空证据表示并加入往返/组合回归。
2. 初始启动索引恢复曾重建 9 个已删除业务会话的缓存。停止该版本后，仅把该次新生成的九个缓存移到私有备份隔离区；没有回滚数据库或操作账本。修复为索引恢复及缓存扫描均检查业务所有者存在，回归和后续启动确认不再生成这些文件。
3. 最终审查将 N4 增量捕获严格限定在新的自动记忆已主动开启时。仅旧项目记忆开启时继续原终态链路，避免增加未授权的压缩提炼请求；加入回归。

- 新增可选来源 journal/projection 有独立版本；未知版本拒绝。原 SQL/hash、执行账本和模型/工具循环不变。
- 单条结果最多保留 2 KiB 等有界限制可能遗漏原始尾部；明确显示未完整采集，不把这些区间标为完整成功。
- 无真实宿主消息 ID 的外部 CLI 仍使用原终态记忆接口，中途压缩增量不在本阶段保证范围内。
- N5 新偏好按范围进入后续回答尚未实现。同一会话的模型确认不是跨会话召回证据，本阶段不作收益结论。功能保持实验、默认受控开启。
