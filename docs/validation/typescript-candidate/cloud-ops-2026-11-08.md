# 双云 Ops 实机验证

2026 年 11 月 7–8 日在 macOS 上，使用签名 Lake Dev、TypeScript 后端、实际项目模型和两个 Linux SSH 目标执行双云 Ops 计划。每台 19 项，业务验收需要目标主机上的独立复查。模型看到业务请求，测试员保留故障注入、基线、真实命令回执和后验记录。跨任务记忆在测量请求里关闭。两台变更演练分别使用独立 Dev 项目，逐次确认命令并限制到引用资源。双机巡检和综合判断使用原双云项目。

下列首轮记录已封存；后续修复与最终 38/38 的场景验收见本文末尾。最终场景符合预期不表示首次全自主完成，也不表示 TypeScript 全量切换验收通过。

续测修复及验证了以下问题：

- 任意 SSH 命令的已知副作用缺少通用人工复核路径。新增与真实 SDK 原调用、认证对端、资源配置、终态回执和后置完整观测绑定的操作者登记与独立风险结清。无写入与已发生变更分别处理；记录真实的授权 QA 操作者，不伪造用户回复。原 Operation、退出码、attempt 与目标验收不变；已发生变更的原目标、同源及原范围禁止重放，其他独立工作仍需新的已准入请求和当前权限。目录快照不是任意 Shell 的全局无副作用证明。
- 原 SSH 跟踪结束后，SDK 内存注册表缺少句柄，无法读取原终态结果。仅对原任务确实签发、同 session/task/generation/资源、已终止的准确句柄读取持久回执；不复活 TaskStop，也不重执行命令。优刻云取消原跟踪后远端服务仍存活，独立核对 wrapper/子进程、启动 tick、参数摘要和监听后由 QA 接管，最终仅向准确测试子进程发送 TERM，wrapper 自然退出。
- 原 Worker 页面只保留过程播报，已交付总结在 Pilot/频道可见而原执行页缺失。按准确 SDK RootTurnID 投影已冻结的交付一次，保留原消息和 outbox；签名 Dev 原生页面已看到真实最终总结。
- 历史证据读取缺少命令起止时间，导致模型把索引时间或预定两秒写成实际采样间隔。补充准确绑定的 `commandTiming.startedAt/finishedAt`。模型现可只读取原回执，纠正原来真实为 33.788/34.609 秒的间隔；后来实测两秒的采样另列，不覆盖原事实。
- 强化通用执行说明：变更和验证分开，降低身份后先进入可访问目录，后台服务正确分组并断开标准描述符，先保留故障取得对照再修改，整包受信摘要通过后才处理成员。未添加测试目录或命令的特许名单。
- 原生界面发现任务摘要长 SHA 在右栏溢出，补充自然换行；更新安装后在浅色、深色及窄窗口实页确认，原始命令仍可展开，原退出 1 和人工已结清但未验收的状态均保留。

## 自主规划、分配与进度的实际边界

本轮 27 个有续测记录的场景中，9 个在本轮没有额外方法提示即达标；14 个包含额外指导或独立复测；4 个是预定命令的审批/防重放控制测试。另 11 个沿用首轮封存结果。普通操作审批、方案规定的第二次授权及刷新复查与具体方法指导分别记账，不能用最终 38/38 宣称首次自主率 100%。

为检验通用说明修复，两台另用全新目录和新任务再测 S18。每台仅一条业务输入，未追加方法、纠错或替代派单。Pilot 自行派给专员；专员先比较 2 秒与 7 秒总超时、核对日志和源码，再移除本轮标志，按原 1 秒连接/2 秒总超时取得三次真实 200/RID，保持原服务进程。京东云实测三次间隔约 2.009/2.008 秒，优刻云为 2.000104/2.000112 秒；两个任务均取得宿主验收和独立 SSH 复查。此前有指导的失败/续办仍保留在历史中。

同一专员在不同任务上同时存在 SSH 命令的实测峰值，两台均为 2。本轮续测共建立京东云 16、优刻云 21 个 Worker 任务；成功的原生 TodoWrite 分别为 4、0，原生 child 实际调用均为 0。因此已证实独立任务委派和同角色并发，尚不能据此宣称模型会普遍自主拆分多步骤计划或使用子智能体。真实业务 Watchdog 仅观察，没有自动语义纠偏或救援回执；受控机制测试仍单独保留。

66 条续测输入中，京东云 31 条、优刻云 35 条。首个工具活动中位数分别为 14.4 秒（31 条）、18.4 秒（34 条）；首份专员实质报告分别为 158.8 秒（29 条）、201.9 秒（26 条）。数据包含审批等待、排队、安装、模型限流和测试员中断；其中新 S18 的一段审批等待跨越约 98 分钟的测试中断。这些不是纯模型推理延迟。CSV 另保存按相同 session/tool/参数匹配、重叠区间去重的审批等待及扣除值，也不能把扣除值直接当推理耗时。
