# 双云 Ops 实机验证

2026 年 11 月 7–8 日在 macOS 上，使用签名 Lake Dev、TypeScript 后端、实际项目模型和两个 Linux SSH 目标执行双云 Ops 计划。每台 19 项，业务验收需要目标主机上的独立复查。模型看到业务请求，测试员保留故障注入、基线、真实命令回执和后验记录。跨任务记忆在测量请求里关闭。两台变更演练分别使用独立 Dev 项目，逐次确认命令并限制到引用资源。双机巡检和综合判断使用原双云项目。

## 实测结果

| 项目 | 观测 |
| --- | --- |
| 独立派单 | 首次双机巡检只有一个归属到第一台机器的任务。修复后，相同人类输入可以按互不相交的资源集合派两个任务，同一位专员并行处理，每个执行只访问其绑定的主机。 |
| 综合判断 | 另给一条只描述业务目标的双机比较请求。Pilot 自行派给运维专员并绑定两个资源。用户在 43.23 秒后收到一份准确的比较报告，独立 SSH 核对了两侧容量与资源读数。 |
| 计划和进度 | 双机间隔采样首次停在第一轮之后。专员安排了三步，但使用无资源绑定的本地 sleep，界面也没有识别 SDK 的 TodoWrite。修复后的真实任务继续了同一个三步清单，等待 30.002 秒后，两机分别间隔 41.325 秒、40.815 秒取得第二组观察，74.589 秒交付结论。频道和任务详情都显示了真实进度，最终为 3/3。清单表示工作进展，交付验收使用操作回执。 |
| 工具及跟进 | 两台均定位到短时 CPU 进程并跟踪至退出。旧版 Linux 的无终端 ps 截断问题另在原主机复现和修复。两台均用原 SDK 后台句柄取回唯一一行预期输出和退出码 0。两台实际 HTTPS 探测证实错误域名验证失败、正常名称取得正确状态和正文摘要。 |
| 项目待核实状态 | 一台的只读目录盘点因起始工作目录权限退出 1。另一台已经删除演练维护标志，后续 HTTP 字符串断言因换行差异退出 1，独立探针三次取得 200。两条原始操作仍保留。Dev 的复核界面分别关联后续只读凭证，区分未写入和已发生变更，其他任务仍受项目门禁。 |
| 停驻状态 | 签名 Dev 中回看真实历史任务，任务与步骤均显示阻塞，两次尝试分别显示结果待核实与阻塞。原操作状态及退出码仍可核对。 |
| Watchdog | 本轮真实业务产生了巡检观测。没有出现语义干预或自动纠偏回执。受控时钟和可控服务故障的机制验证另见[巡检验证](watchdog.md)。 |

按每个场景最新一次完整证据，两台合计 12/38。其中第一台 7 项，含一项经人工续办的端口恢复。第二台 5 项。含早期业务通过的独立场景数为 13。拒绝审批后的零派发、成功解析 DNS、单独探测到服务健康都只记到对应的分项。两台的部分写入防重放用例排在最后，前置未满足。共 21 项有阻塞，其中 4 项缺部署前置，3 项只有部分证据，2 项待测。14 个演练目录均按 RID、属主和进程身份核对并清场。

55 条测试输入到首次工具活动的中位数为 9.7 秒。53 条有终态报告的输入，最后一份专员报告的中位数为 57.7 秒，包含排队、审批和失败报告。
