# Pilot 与专员首包延迟修复

已签名安装并验收的产品提交：`0f622f221f0bbf71e974fedf171c9ae657c4d232`，Lake Dev 0.3.33 / TypeScript，`dirty=false`。后续仅追加本文与合成验收证据。工作继续在 PR #235，目标 develop；未合并、未发布。

## 原因与行为

原生模型流原先固定保留 `max(80, 已注册凭据长度) - 1` 个字符。普通短句也被缓冲；长 OAuth 凭据可能让整段回复和思考等到流结束才出现。新增的 Pilot、专员首包回归在修改前均失败：服务已发送短句并保持连接打开，1.5 秒内仍没有公开正文。

现在只保留可能形成凭据或 PEM 边界的未完整前缀，安全正文、思考与工具输入增量及时下发。已知凭据跨分片仍被脱敏；私钥正文不在缓冲中累计；文本、思考及工具参数分别按真实通道处理，无关通道结束不会释放另一通道的敏感前缀。结构化错误与数值元数据沿用原脱敏入口。

原生推理启动只读取当前已验证的可选外部 Agent 能力，不再等待额外 Codex 进程连接探测。显式状态/连接检查以及实际 ACP 启动仍执行原校验。

专员已有准确派单回执、Pilot 尚在收尾时，主会话立即展示该专员的“准备处理”，保留准确来源。实际执行仍等原 `dispatchReady`：成功协调后接上真实思考，派单失败、停止、过期或只剩阻塞输入时不会冒充可运行。没有提前执行工具或改变任务/权限边界。

## Lake Dev 原生验收

运行 `node scripts/verify_response_latency_dev.cjs <新的临时元数据文件>`，使用安装后的签名应用、独立临时 Home/Web data、回环模型和合成长凭据。消息均从原生 Pilot 输入框实际发送；没有访问业务资源或复制日常凭据。

1. 发给 Pilot 后，在模型尚未下发任何文字时，原生窗口已显示“正在思考”。
2. 控制端只发送“先核对。”与“收到。”，保持连接打开。主会话已显示“收到。”，不再等完成或凑满字符数。
3. Pilot 流仍打开时，从同一输入框提交专员任务；消息立即入会话，原请求继续。释放 Pilot 后，派单回执已提交、协调回复仍由控制端持有，主会话与侧栏已显示专员“准备处理”。
4. 释放协调回复，专员显示“正在搓爪琢磨中”。只下发“先核对。”与“已接单。”并保持连接打开，主会话已显示“已接单。”；打开该任务执行过程可见两条准确记录，思考“先核对。”及公开回复“已接单。”均保留。
5. 释放完成信号，原位置显示正式报告“本地虚构文字核对完成，未访问业务资源。”，随后正常结束。

采样间隔约 25ms，各场景仅一次，不作为统计分位数或远端模型速度结论：

| 度量 | Pilot | 专员 |
| --- | --- | --- |
| 消息接受 → 开始原生回复 | 33ms | 包含人为持有前一轮与派单回复，故不用于比较 |
| 释放派单回复 → Worker 开始 | 不适用 | 32ms |
| 服务发出短首包 → 后端视图可读 | 26ms | 21ms |
| 后端观察到首包时，模型流是否仍打开 | 是 | 是 |

视图度量包含 HTTP 采样间隔，不是屏幕绘制耗时。原生窗口实际可见性由上述操作及截图确认；测试中的长等待均为控制端人为持有，远端模型生成首包/ACP 引擎启动时间未用该回环测试替代。
