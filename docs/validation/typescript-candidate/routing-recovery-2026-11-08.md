## 问题与修复

Pilot 第一次派单误写了专员 ID，返回笼统的“记录不存在”；稍后使用准确 ID 派单成功，专员实际查询及任务验收均成功。旧展示只认可相同收件人 ID 的重试，所以继续显示“1 项失败”。

- 当前请求工作集附带本项目未删除专员的准确 ID、名称和版本；目录有界、分页缺项明确引导 `list_specialists`，不截断 ID。目录只提供元数据，实际派单仍核验原项目、频道和权限。
- 无此专员或跨项目 ID 返回 `specialist_not_found` 和重新读取目录的提示。保留历史任意合法 ID 格式，不按名称模糊改派；删除专员仍返回 410。错误不会创建任务、Worker 或派单决策。
- 纠正收件人的恢复由宿主只读核验：原 ID 在全局专员记录中确实不存在；同一 SDK root、事件、part、create 动作及其他参数完全一致（仅单个 role_id 和解释 reason 可不同）；后续成功回执必须与持久决策 hash、任务、专员、Worker 和执行会话一致。有效专员改派、其他范围和真实业务失败不会套用此标记。
- 快照及 AI 读取接口一致返回展示注解。主流程显示“1 项派单重试后已恢复”，详情显示“首次失败 · 重试后已恢复”；原错误、参数、状态和后续回执均保留。恢复表示派单恢复，不是业务任务验收。
- 原有相同收件人的重试判断也要求参数和执行 root 一致，不能借后续不同范围的成功隐藏错误。
