# TypeScript 任务轮次上限取消验证

2026-11-08，用户明确要求移除任务累计模型轮次限制及其显示。Lake Dev 已从干净源码 `fe856d09ea42b1fd463d41d59db9992851a0b54c` 签名构建安装，后端 SHA256 为 `684bb893e227e5372ec0661c748296d8196eeea8b6966bd793918309b0da1bbc`。

## 行为

- Pilot、独立 Worker、临时原生子智能体及共同任务不再按累计模型轮数拒绝派单、补派、模型调用、后续输入、完成交接、人工恢复或 Watchdog 观察/有限纠偏。
- 移除交互运行时传入的 `maxTurns`、从旧 `maxSteps` 复制的配置及任务的默认 500 轮上限。后台 Memory 整理和 Watchdog 审阅的独立调度/预算没有改成无限业务执行。
- 新任务不再写 `roundLimit`；旧记录中的该字段和 `maxSteps` 不做批量清理或改写，也不参与运行资格判断。实际 `modelRounds` 持续累计，共同任务的公开统计按成员真实计数求和，不再从剩余额度反算。
- 删除任务详情的轮次用量/上限及旧样式；TypeScript 会话不提供工具循环上限设置。兼容旧 Go 后端的独立会话配置保留，不代表正式版后端已切换。
- 旧轮次暂停只做当前显示解释，明确恢复后可沿原任务继续，不在升级时自动执行或清零。原始失败、任务、步骤、操作和验收继续保留。
- 绝对截止时间、停止、项目与资源权限、待审批、未知结果处理和真实业务验收照常执行。

## 兼容与回退

`WorkGoal.roundLimit` 变为可选的历史字段，TypeScript 当前公共视图省略该字段。任务计数、原操作和验收不迁移、不清零。旧版本若依赖必填的 `roundLimit`，不能直接据新任务缺省字段推断执行资格；回退执行版本需要先适配缺省字段，且不能自动补默认上限、重放操作或改写验收。本次不安装正式版、不发布、不合并 PR。
