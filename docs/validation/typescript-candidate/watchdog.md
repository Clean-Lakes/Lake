# 专员任务巡检

2026-11-07 在 macOS arm64 验证 TypeScript Dev 的本机巡检。源码提交为 `f8698179cf08adff724834d393d2d4ad65554d0e`，安装来源清洁，签名通过 `codesign --verify --deep --strict`。

| 场景 | 观测 |
| --- | --- |
| Worker 连续读两次同一目录 | 真实 SDK、SQLite 和 HTTP 路径产生两张原始回执。加速观察时钟后，仅对该执行发起一次语义审阅。本地测试模型返回停滞，SDK 接受一条定向纠偏。 |
| 纠偏之后 | 提示入队时目标尚未验收。Worker 提交合格证据后，目标通过，巡检记录更新为「已观察到新进展」。重启同一测试 Home 后仍为一条记录。 |
| 正常等待与共同任务 | 两位成员使用相同公共任务 ID。甲等待审批时，乙的重复操作触发审阅。审批、长命令、活动子智能体及未决状态受到保护；结束等待本身不会被记录成恢复。 |
| 新数据、偏航和误判防护 | 工具新结果与相同输出可区分。计划和权限变化、后续输入、停止、关停再开启或 generation 变化使迟到结论失效。方向复核遵守独立预算。 |
| 供应商暂时故障 | 本地测试服务经真实模型协议返回 503，原始 Worker 被暂停。在允许纠偏、工具尚未调度的前提下，恢复服务后同一任务完成。模型故障仅从本次 SDK 异常取证。 |
| 恢复范围 | 每次分工最多两次自动重试，分别至少等 60 秒、300 秒。已有工具意图、审批、命令、未决操作、停止、进程更换、权限或范围变化都会制止旧重试。 |
| 只读审阅 | 使用项目当前模型的独立请求，零工具，有界目标、个人分工与观察摘要。隔离 HTTP 模型服务验证敏感信息过滤、返回结构、输出上限和取消请求。 |
| 原生界面 | 签名安装后在隔离项目打开「任务详情 → 执行过程 → 项目巡检」。展开依据可见「累计 2 次工具调用，取得 1 组不同的成功回执」，查看了原始停滞结论和后续进展。随后重新打开日常 Dev。 |

模型协议测试使用本地可控应答，尚无真实业务流量下的误报率和模型成本分布。定时器随 Dev 后端运行；关闭应用内核或设备休眠期间的监督属于后续独立进程方案。关闭项目巡检可以停止该项目后续审阅、提示和未消费的自动恢复。旧业务执行、证据与验收仍可查阅。
