# Lake 自然记忆重塑开发计划

Lake 的新记忆功能承接原策略资产：用户正常交流，系统在用户开启自动记忆后识别明确的长期偏好，在空闲时整理项目事实和历史经验，回答时按范围取用。上下文压缩前再捕获一次尚未整理的来源，减少长对话中的遗漏。用户不需要固定说“记住”，日常也不需要逐条审核、采用。

用户提出的四项要求是本计划的产品目标：交流不被记忆流程打断；后台增量合并、处理矛盾并保留来源与历史；按用户、项目和资源范围使用，服从当前要求；压缩时补充提取。以下接口字段、阶段和门槛是实施方案，尚未成为运行能力。

基线为 `origin/develop@510aad88e49916f3272404f9d0180b89954616c3`，即 [C1 #107](https://github.com/Clean-Lakes/Lake/pull/107) 合入后。C1 的在线纠错、旧策略候选提取和产品实验退役决定继续有效；新功能扩展现有记忆链路，不恢复旧开关、旧回执或实验执行器。本轮交付计划文档，代码和真实数据不变。

## 1. 用户体验与记忆内容

| 自然交流或场景 | 目标处理 |
| --- | --- |
| “以后这个项目的排障报告先给结论，再给证据” | 形成项目偏好，事务提交后轻提示“已更新项目偏好 · 查看 · 撤销” |
| “所有项目的回答我都希望用简短中文” | 用户明确表达全局范围时，形成用户偏好；用户指本机 Lake 用户，不代表团队或跨设备账户 |
| “这个项目只用于预发” | 保存为项目内的用户陈述，保留原话与时间；不声称已经核验现场 |
| “这次回答简短一点”或粘贴文档里的“以后都……” | 临时要求只影响本轮；引用内容不是用户偏好授权 |
| “上次修改代理后恢复了” | 保存符合来源要求的历史经验及条件；再次使用前核实目标和现状，不自动执行同一操作 |
| 多次选择同一种格式，但没有明确长期表达 | 可以形成待核实建议，不凭次数直接改为全局规则；不弹出阻塞确认 |
| “不再使用原格式，以后用这一版” | 同一范围、同一偏好的明确更正可生成新版本；有歧义的矛盾保留待核实，不能只按最后写入覆盖 |

一条记忆保存一个偏好、原子事实或条件式经验。永久性、范围和可靠性分别判断：长期偏好不因模型复述变得更可信；用户陈述不等于工具观测；一次成功不证明方法普遍有效。瞬时 CPU、健康状态、计划、模型猜测、凭据和大段原始日志不进入长期记忆。

统一入口称为“记忆”，提供偏好、项目事实、历史经验及近期更新；旧报告放入次级历史入口。新记忆不经过“候选—确认正文—采用”的日常流程。待核实内容仅在必要时集中展示，不要求用户维护一套研究式资产平台。

## 2. 设置与写入规则

新自动记忆需用户主动开启，提供用户/项目范围说明；旧策略 learn/correct/online 的 true 或同意记录不能转换成新功能同意。既有项目记忆的使用/提炼选择须保真映射，不能因入口改名自动扩大为用户级采集。N1 必须冻结新旧设置的映射与权限测试。

日常只突出“自动记忆”；保留独立停止使用已保存记忆的能力，可放在高级设置。关闭自动记忆停止新增采集和后台提交，保留已保存内容；停止使用后新请求不再注入或读取。界面说明两者区别；本轮忽略同时不引用、不采集，不改变原消息记录。只处理开启后的来源；首次开启不自动遍历全部旧对话。

自动写入的长期偏好必须有当前真实用户消息中的具体依据和明确适用范围。语义识别可复用后台无工具提炼请求，不再以“记住”前缀作为唯一入口；关键词只用于廉价信号筛选，不能单独证明长期意图。现有直接保存/遗忘工具的授权检查在新链路完成前保持原边界，不能通过删除前缀校验直接允许模型任意写入。

项目事实沿用记忆的来源验证规则；自动激活资源配置事实仅接受受信执行元数据与可校验字段。普通 shell/MCP 文本、失败/未知结果和模型归纳不能直接升级为已验证现状。条件式经验即使可供检索，仍标明来源性质、适用条件和使用前的检查项。无法归类或定位来源时允许不保存。

只有持久提交成功才显示“已更新”。同批多条变更合并为一条轻提示；推迟或失败仅在记忆状态中显示，不将已完成任务改成失败。查看展示正文、范围、来源和变更前后版本。撤销是带准确 revision 的新事务：只撤销对应变更；遇到后续编辑保留新内容并提示冲突，不能覆盖其他修改。撤销/拒绝形成去重依据，同一来源不能在下一次整理或压缩时立即写回来。

## 3. 空闲整理与持久增量

```text
真实用户消息和已完成证据
  → 有界、去敏的来源引用与待整理事件
  → 轮次结束或压缩前合并同一增量
  → 前台空闲后单次无工具提炼
  → 范围/来源/版本/遗忘状态重验
  → 事务保存偏好、事实、经验或待核实冲突
  → 更新提示与后续按需取用
```

前台只记录最小事件，不等待额外提炼模型、全库扫描、记忆合并或投影文件生成。后台复用现有项目记忆 outbox、队列、租约和模型适配器；支持批量合并、无变化跳过、单飞、退避和派发上限。前台新请求优先，必要时取消后台请求并撤销租约，迟到结果不得提交。

同一来源区间由轮次结束、压缩及重启恢复触发时合并处理，不因 trigger 名称不同重复调用。幂等依据至少包含所有者、项目/会话、稳定消息或事件身份、来源修订/摘要 hash、策略版本和设置 epoch。采集进度与成功处理进度分开；入队不等于已处理，被预算裁掉的来源不能标为已覆盖。有限重试与未知用量沿现有派发记录保留，不能无限重新派发。

合并仅在事实身份、范围和条件等价时去重，保留全部有效来源及演化关系。明确更正产生 supersedes 关系；不能确认的新旧冲突保持待核实，争议事实在解决前不作为确定结论注入。编辑与整理时间不刷新事实观测时间。用户修正、撤销、遗忘及来源撤回优先于任何排队结果；在途轮次的后续 provider 请求也须重验并移除失效记忆缓存。

后台仅在 Lake 运行且空闲时整理；退出后保留待办，重启再检查资格。本期不增加常驻系统服务，也不承诺应用关闭后仍进行“夜间做梦”。

## 4. 压缩前补充提取

压缩既可能是模型摘要，也可能只裁短旧工具输出。不能只在摘要模型成功后挂一个回调；需覆盖自动阈值、手动压缩、模型切换/恢复导致的维护、官方 ADK 回调及预览降级分支。清空、回滚和删除属于撤回/历史变更，不作为补学习授权。

1. 在符合压缩条件、即将覆盖历史投影之前，为采集开启后、未撤回且未覆盖的真实来源记录有界引用/去敏快照。使用业务消息、根轮次和 ADK 事件的稳定身份，不能以压缩后会变化的数组下标定位。
2. 保留原始用户陈述、真实证据状态、项目/资源绑定和时间。上下文摘要只用于当前会话交接，不能作为新的权威来源；再次压缩摘要不产生新事实或新观测时间。
3. 与轮次结束任务共用覆盖记录和去重规则。有尚未整理的增量才入队，不要求“每压缩一次就多调用一次模型”；无变化回调应零新增派发。
4. 压缩可能发生在任务中途。只处理完整、已有来源支持的偏好或历史信息；未结束工具调用、审批、unknown 以及模型当前猜测不能形成“已完成经验”。缺少完整证据的部分等待后续轮次，未处理区间不越过进度水位。
5. 采集动作不增加同步提炼模型请求，提炼仍等前台空闲。可选记忆捕获失败不能改变原压缩成功/失败、取消或工具权限语义；若权威原始记录仍在，可保留待补引用，否则显示整理缺口，不能声称已完整记忆。原会话/操作账本真实持久化失败仍按原错误边界处理。
6. 压缩失败后重试、同批次多次回调、崩溃在入队/提交/确认之间、重启恢复，均不得重复通知或覆盖更新的记忆。遗忘后压缩也不能通过旧上下文复活内容。

压缩摘要与记忆提取第一期保持独立输出契约，避免将“摘要生成成功”误当作“长期事实验证成功”。可在以后测得必要收益时讨论合并模型调用，不作为本期依赖。

## 5. 读取范围与优先级

| 内容 | 允许范围及使用方式 |
| --- | --- |
| 用户偏好 | 用户明确选择的全局范围，可作用于普通对话及适用的 Pilot 表达；不改变角色、目标或权限 |
| 项目偏好和项目事实 | 当前项目；资源相关内容另需匹配完整资源集合、代次和有效期，不能混入其他项目 |
| 历史经验 | 按项目、资源、条件及来源检索，按过去发生过的事表述；执行前重新核实，不能自动授权重试 |
| 当前任务与工具状态 | 由当前消息、真实采样、审批和操作账本决定；历史记忆不能覆盖 |

固定运行边界和安全规则始终有效。在允许的表达/任务约束内，当前明确要求优先，其次为显式项目偏好，再为用户全局偏好；检索出的事实和历史经验是资料，不是同一层级的执行指令。同范围未解决冲突不同时注入相反要求。

读取先按权限、范围、来源、状态和时效过滤，再用本地检索提供少量短索引，正文按需读取；主请求不新增模型检索调用，不引入向量服务。使用记录区分“准备注入”“实际读取”和“模型是否遵从未知”，不能因为读过就宣称有效。

项目私有消息里形成的用户级偏好必须与私有来源权限隔离。即使用户明确选择全局，也不能把原项目标题、原话或证据暴露给无权项目；保留可撤回依赖。转为全局不能成为绕过来源撤回的复制通道。

## 7. 旧内容迁移与计划承接

| 旧状态 | 迁移要求 |
| --- | --- |
| 已采用、范围可等价表达的偏好 | 保留准确正文和版本，预览归属、条件和来源后承接；映射唯一，新旧链路不能同时注入 |
| 条件复杂的方法类资产 | 保留兼容应用或导出为用户检查的 Skill 草稿；不能自动改成无条件全局偏好或安装 Skill |
| 未采用、待审核、已拒绝/停用或来源已撤回 | 不因开启自动记忆变为有效记忆；保留原内容访问权限、拒绝与防复活记录 |
| 原有项目记忆与 V2 待复核数据 | 保留项目/资源隔离、设置和既有复核门槛；不能批量确认旧条目或更改项目归属 |
| 旧学习、纠错与实验记录 | 继续按 C1 退役，只读/撤回/清理按原权限；不得作为自动记忆的新增任务或成功证据 |

[Harness² 清理计划](refactor-harness-inspired-cleanup-1.md)的 C0/C1 保留完成事实；C2 的用户内容和入口承接由 N1～N5 落实，C3/C4 的公共依赖拆分、历史兼容和最终清理继续执行，不能先删新链路需要的记忆代码。原 [R0～R5](refactor-user-assets-and-experience-1.md) 不再指导新功能的逐条审核/采用交互。

[运维记忆 V2 计划](feature-operational-memory-2.md)继续承担资源事实、时效和来源验证；本计划扩展用户偏好、自然形成、轻提示/撤销及压缩增量。其项目隔离要求仍约束项目事实；新增用户级偏好不是跨项目事实共享。V2 验证中尚缺的升级/回退、竞态、Windows 和模型质量门槛仍须补齐，不以新名称绕过。

迁移前备份两库，兼容回退只在隔离副本验证，禁止覆盖最新任务或撤回账本。迁移本身不调用模型，也不自动重新整理历史会话。

## 9. 验收矩阵

| 编号 | 场景 | 必须满足的结果 |
