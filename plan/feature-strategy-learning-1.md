# Lake 策略学习与改进开发计划

本计划将提示词改进、用户提示词资产、来源血缘、有界纠错及开关对比组织为可分阶段交付的功能。用户能够查看学到了什么、为什么形成、在哪些场景生效，并编辑、停用或回滚。首期通过隔离故障环境证明策略效果，再开放正常任务中的只读纠错。

实现采用 Go，内嵌当前 Lake；复用官方 ADK 的模型与工具执行链路。借鉴 Harness² 的“提出候选—试跑—对比—合成—再次验证—积累经验”，不把 Python、OpenCode 或 Claude CLI 作为客户端运行依赖，不宣称与原版实验结果等价。

所有阶段初始均为待开发。任务完成必须附对应验证证据，不能以文件存在、模型输出正常或命令退出码为零替代功能验收。本次范围为计划编写，不包含功能实现。

## 1. 基线和现有能力

代码基线：`master` 提交 `9520dd7`，`VERSION=0.3.21`。工具链以 `go.mod` 和当前构建脚本为准，基线为 Go 1.26.6、ADK Go v2.6.0。后续实施先同步工作分支并核对接口，禁止照搬历史计划中的旧执行循环。

当前 `ScanSkills` 的同名顺序是工作区 `.agents/skills`、工作区 `.lake/skills`、Lake Home `skills`、登记的外部目录；前两项要求传入 Workspace。桌面/Web 的技能设置和引用解析目前传空工作区。本计划不顺便改变此行为。

## 2. 产品目标和交付边界

### 2.1 五项交付

1. 提示词三层化：固定规则、可优化策略、任务上下文分离。
2. 形成用户真实可见的提示词资产，支持编辑、范围、版本、采用和回滚。
3. 记录纠错和资产演化血缘，可从规则追溯到真实消息、调用和验证结果。
4. 在明确预算、进展判定和停止条件内纠错，保留所有失败和未知结果。
5. 总开关控制功能，实验分别记录应用、学习、纠错三个变量，支持前后对比。

### 2.2 分期范围

| 交付里程碑 | 包含内容 | 可发布边界 |
| --- | --- | --- |
| M1 可见资产 | 三层提示词、版本化资产、来源血缘、手动创建/导入/采用、总开关 | 不自动学习、不增加资源试跑 |
| M2 隔离优化 | 候选生成、可重置任务集、基线/候选/合成试跑、评估、实验总预算 | 仅登记的隔离夹具；提供单步与有界递归 |
| M3 只读纠错 | 正常任务的失败分类、进展检测、修订与有限继续、完整对比报告 | 仅服务端能证明为只读的动作；显式开启 |
| 后续 | 领域工具指引、SRE 分工策略、经验证的更复杂适用规则 | 按独立计划扩展；不默认为当前已承诺功能 |

首期不实现自动生产修复、自动故障注入、无预算的自我进化、跨用户/团队共享、模型微调、语义向量检索或 Skills 市场。不修改固定工具 schema、权限规则、四个 SRE 角色身份及验收标准来获取更好分数。

## 3. 架构与职责

```text
用户设置、真实纠正、已结束任务
             ↓
策略学习协调服务（Go，持久任务和总预算）
  ├─ 从脱敏来源生成候选资产
  ├─ 冻结候选与实验输入，创建独立运行
  ├─ 固定判据评估与候选合成
  └─ 展示差异，由用户采用到指定范围
             ↓
现有 ADK Runner / LlmAgent / Workflow
             ↓
现有工具目录、权限、审批、操作账本、真实证据
             ↓
隔离夹具；M3 允许当前授权范围内的只读调查
```

优化层调度的是有限的实验阶段，不新增 LLM/tool 循环或第二套 SRE 节点调度器。每次交互式 Agent 执行均进入现有 ADK；单次无工具的候选提取/比较可复用辅助 completion，并在架构检查中列明。涉及读取和编辑实验产物的多步模型任务仍经 ADK，不能借“提取”名义放入工具循环。

建议新增 `internal/strategy/` 保存纯契约、版本解析、预算和进展判定；该包不导入 `internal/ai` 或 `internal/web`。`internal/ai/strategy_*.go` 适配提示词与 ADK，`internal/web/strategy_*.go` 实现仓库、协调任务与 API。通过接口组合，避免 ai → strategy → ai 循环依赖。

### 3.1 三层提示词契约

| 层 | 内容 | 可修改主体 |
| --- | --- | --- |
| 固定规则 | 身份、权限、凭据、引用范围、SSH 信任、审批、未知效果、验收不可伪造 | 正式代码变更；优化器无写权限 |
| 策略资产 | 调查顺序、证据组织、工具使用建议、报告和用户工作偏好 | 用户；优化器仅产生候选修订 |
| 任务上下文 | 当次目标、资源、附件、历史、团队状态、记忆与实际额度 | 当前会话与可信运行时 |

先抽取现有提示词中混杂的规则，默认三层组合在关闭功能时保留基线语义。固定规则与策略有明确分隔、来源标签；用户资产始终标为低权限流程/偏好，不能通过正文伪造 system 身份。读取顺序或拼接在后不代表拥有更高授权。

每轮形成 `PromptManifest`：应用 build/commit、内置策略 hash、固定规则 hash、资产精确 revision/hash、Skill 快照 hash、模型/推理配置摘要、工具目录与权限策略版本、范围及目标指纹、上下文预算与已省略资产。禁止把密钥、认证头或带秘密的完整配置放进清单。

一轮内固定策略版本；下一次显式修订产生新的 run/attempt。权限收紧、资产停用及来源撤权要实时生效：不再继续注入，必要时取消并在新配置下恢复；不能以版本冻结绕过撤销。记录中保留当时实际使用的版本。已启动外部命令仍按现有停止/核实语义处理。

### 3.2 与 Skills、项目记忆的关系

- 策略资产是结构化、可版本化的工作方法；现有 Skill 是可由用户维护的文件，项目记忆是历史事实/偏好。三者不互相覆盖。
- 导入 Skill 生成新资产及来源快照，原文件保持不变；源 hash 变化后标记源已更新，不静默改已采用 revision。
- 导出 Skill 创建用户指定的新文件；覆盖已有文件需明确选择且遵循文件权限。不把数据库资产投影目录作为可直接编辑的权威来源。
- 记忆中可保存资产引用，避免正文和策略重复注入；从记忆转成策略必须保留来源且产生候选，不自动改写事实。
- 不扫描用户所有历史或主目录。自动候选只处理启用后的合格来源；历史任务由用户明确选取。
- 策略不能授予专员递归启动实验的能力；实验自身、候选提取、比较和反思输出不再次触发自动学习。

## 4. 用户资产与优先级

### 4.1 最小资产结构

资产包含稳定 ID、标题、类型、正文、适用条件、作用范围、状态、精确版本、来源、验证等级、创建和采用记录。类型先限定为用户偏好、领域排查流程、工具指引、报告要求；协作策略后续独立扩展。

“用户级”表示归当前本地 Lake 身份管理，默认仅在当前项目应用。全局范围必须由用户明确选择；本机不是团队账户，不新造未经认证的多租户权限。全局资产可含项目来源摘要，但从其他项目使用时不得泄露原项目原文、资源或操作数据。

适用条件首期使用可验证字段：项目、场景 profile、资源类型、用户选择的领域标签。自然语言适用说明辅助模型理解，不作为授予工具能力或权限的依据。不依赖额外模型每轮全库检索；只注入有界索引或明确采用的短策略，预算不足时确定性裁剪并记录。

### 4.2 状态与修订

正文修订不可变；资产状态和采用绑定通过追加事件改变：

```text
候选 → 试用 → 已采用
  └→ 已拒绝
已采用 → 已停用；后续可重新采用某个精确旧版本
```

保存内容与启用是独立动作。手工编辑也产生新候选版本，不原地修改已采用内容。已采用只表示用户选择应用，不等于效果已经验证。

验证等级单独记录：`user_confirmed`、`single_observation`、`fixture_validated`、`multi_task_validated`。用户纠正可证明偏好，不自动证明技术结论；一次成功试跑不能升级为普遍有效。

### 4.3 选择与冲突规则

1. 固定规则与实时执行权限永远适用。
2. 同一逻辑资产有项目覆盖版本时选择项目绑定，否则选择明确采用的用户全局绑定。
3. 本轮显式选择某个资产版本可替换该逻辑资产的默认版本，但不能跨越范围或读取无权来源。
4. 不同资产的互斥条件、排他组和优先选择由结构化设置确定，不能简单按文本先后覆盖。
5. 明确用户当前要求优先于历史偏好；若技术流程或多个资产存在不能确定的冲突，标记并排除冲突候选，必要时请求用户选择，不让模型悄悄合并。

同名标题不充当身份；通过 ID 和 revision 选择，避免与现有 `load_skill(name)` 的目录覆盖语义混淆。自动生成的新候选不会自动胜过用户编写资产。

## 5. 学习触发与血缘

### 5.1 合格触发

| 来源 | 能形成什么 | 提交限制 |
| --- | --- | --- |
| 用户明确要求记住或修改工作方法 | 用户偏好/约束候选 | 保存后展示正文；采用范围明确，不推断额外授权 |
| 用户纠正答案、目标或方法 | 纠错事件及候选 | 引用真实用户消息；不把所有负面用语当纠错信号 |
| 工具真实失败、反证、验证未通过 | 技术改进候选 | 保留原错误和调用；失败本身不证明新方法有效 |
| 固定任务对比及合成验证 | 可采用的领域流程 | 必须有完整评估；保留失败和退化样本 |

自动学习从已持久化的完成/失败/暂停终态来源提取；失败任务可以贡献“错误与缺口”，不能贡献虚构成功经验。运行中纠错先保留事件，稳定边界后再提取；用户明确保存使用同步提交路径。后台失败不改变原回复或任务结论。

来源登记、入队和幂等键必须持久化；建议键包含源 session/turn/event、提取器版本及来源集合 hash。重启可以重试无外部效果的候选生成，但不能重放资源动作，也不能重复提交同一候选。过期任务提交前重验开关、scope、epoch 和源版本。

### 5.2 血缘节点和关系

节点：真实用户消息、任务/计划修订、运行/尝试、工具调用、操作账本引用、证据引用、纠错事件、候选修订、评估、采用/停用/回滚事件。

关系：`derived_from`、`proposed_to_fix`、`tested_by`、`compared_with`、`composed_from`、`adopted_as`、`supersedes`、`reverted_to`。使用不可变 ID、内容 hash、时间、创建主体和关系类型；记录“基于哪个事件提出”，不声称仅凭时间先后证明因果。

每次运行同时保存任务结果、策略评估结果和外部操作效果，分别显示。模型报告、工具成功和业务恢复不得互相替代。血缘引用现有账本，不复制一份可被优化器修改的操作权威记录。

### 5.3 保留、删除与隐私

- 内容快照、数据库和导出遵循当前私有目录与脱敏边界，不存模型密钥、SSH 私钥、密码、认证头或原始内部推理。保存可解释的简短决策依据，不要求模型思维链。
- 来源保留脱敏摘要和 hash；原文按原项目权限访问。来源已删时显示 tombstone 和“原文不可用”，不得借资产恢复已删除的私密原文。
- 删除来源不自动证明资产失效，也不能继续显示其可完整复现；标记证据缺失，禁止自动推广。全量隐私删除需清理关联内容快照，并保留不含正文的审计身份（适用时）。
- 建议临时模型输入快照保留 30 天，详细实验轨迹 90 天；已采用版本、评估摘要及血缘元数据保留至用户删除。保留期在实现时作为设置固定，定时清理不得删除当前运行依赖。

## 6. 数据模型与事务

以下均为拟新增结构，不代表现有接口或已建表。命名在 P0 契约冻结时确认。

| 表/对象 | 关键字段和约束 |
| --- | --- |
| `strategyAssets` | id、kind、title、owner/local identity、createdAt；标题非唯一键 |
| `strategyRevisions` | assetId、revision、content、applicability、contentHash、sourceSetHash、createdBy；唯一(assetId, revision)，不可变 |
| `strategyBindings` | assetId、scope、projectId、revision、enabled、priority/exclusionGroup、expectedRevision；乐观锁 |
| `strategySettings` | scope、masterEnabled、applyEnabled、learnEnabled、correctEnabled、revision、epoch、budgetDefaults |
| `strategySourceEvents` | source IDs、type、timestamp、redactedSummary、hash、availability；真实源唯一键 |
| `strategyLineageEdges` | from/to typed IDs、relation、actor、createdAt；去重及类型校验 |
| `strategyJobs` | kind、idempotencyKey、status、lease、attempts、epoch、sourceSetHash、errorCategory；提交前重验 |
| `strategyExperiments` | fixture/task set、frozen manifest、budget、state、baselineDefinition、owner scope |
| `strategyRuns` | experiment、variant、manifest/hash、session/runtime IDs、fixture version/reset proof、usage、duration、stopReason |
| `strategyEvaluations` | run/pair IDs、judge contract version、objective checks、optional model comparison、metrics、verdict、limitations |
| `strategyEvents` | aggregate ID、seq、type、actor、payload digest、time；追加式，采用/撤销可审计 |

业务 SQLite 权威保存资产和优化状态；ADK 原生 session/state/artifact 继续权威保存 SDK 执行事实。跨库不假设原子事务：预写运行意图、稳定关联 ID、启动确认和恢复对账；发现不确定状态先读取原运行，不创建替代资源执行。

资产修订、来源边、采用事件与 outbox 通知在同一业务事务提交。内容投影/导出可重建，失败不得报告已采用。后台任务通过租约与 epoch 防止旧 worker 在关闭/删除后提交。

迁移前采用现有一致性快照方案；旧库新增表，无历史批量学习或默认全局采用。新 schema 被旧程序拒绝或只在兼容副本中打开。不得通过恢复执行前数据库覆盖后续操作账本。

## 7. 有界纠错策略

### 7.1 两种不同动作

- **传输重试**：对同一无外部副作用请求处理瞬时故障。
- **策略修订**：基于错误或新证据改变假设/方法，创建新的尝试；不是原调用的隐式重发。

M2 仅针对可重置夹具，环境复位是受信测试执行器职责，不把“只读 Agent”当成整套夹具无副作用。M3 只有可信 policy 能证明只读的操作可自动纠错；任意 Shell、SQL 或 MCP 工具不能因为模型声称或服务端注释而降为只读。

### 7.2 分类与停止

| 情况 | 允许动作 | 必须停止/等待的条件 |
| --- | --- | --- |
| 只读瞬时网络错误 | 有界退避重试，保留每次独立调用 | 达同调用重试上限或原操作仍 dispatched |
| 参数不合法 | 修正参数后新调用 | 同目标同错误重复且没有实质修正 |
| 假设被反证 | 更新假设和下一检查 | 没有可执行检查或证据已充分 |
| 权限拒绝/目标不明 | 保存缺口或请求必要决定 | 不得换工具、角色、目标绕过 |
| 修改/不透明操作 unknown | 新的合法只读核实，交给现有 reconcile | 未核实前不继续相关变更；不自动重放 |
| 只读采样 unknown | 原记录保留；无在途调用时新建采样 | 未取得新结果不能补写旧调用成功 |
| 没有新增信息 | 结束当前尝试，明确已知和缺口 | 连续无进展上限 |
| 用户取消/关闭功能/撤权 | 禁止新实验或纠错派发 | 等待子任务收尾，外部效果仍按账本核实 |

建议初始默认值（产品默认，须经 M2 校准）：

| 额度 | 默认 |
| --- | --- |
| 同一逻辑只读调用的额外瞬时重试 | 最多 2 次，初次执行之外；既有底层重试也计入 |
| 每任务自动策略修订 | 最多 2 轮，切换角色/计划不清零 |
| 无进展修订 | 连续 2 轮停止 |
| 实验顶层并发 | 1；复用现有模型限流，不额外绕开 |
| M2 单任务全部变体执行总数 | 最多 6 次，包含基线、候选、合成和最终复验 |
| 新增优化模型请求 | 最多 12 次，包含提案/比较/反思和其重试 |
| 优化附加累计 token | 100000；实际可用额度取父任务剩余额度与此上限的较小值 |
| 优化活动耗时 | 10 分钟；等待用户期间停止自动继续并持久化等待原因 |

达到任一额度停止，不能按每候选各领一份总预算。请求前预留、结束按实际量结算；usage 缺失采用保守预留并标记未知，不记成零。已知价格时可增加金额上限；未知价格不输出虚构费用。长时间用户等待另外设有效期，过期要求显式继续并重验配置。

### 7.3 进展定义

纠错 proposal 至少包含源错误/证据 ID、被否定假设、实际修改项、预期获得的信息、停止条件。仅换措辞、重复旧日志或重复已知采样不算进展。

运行时以证据 ID/hash/时间、结构化失败类别、固定检查和缺口集合辅助判定；模型可以解释，但不能独自宣布进展。新日志文本也不必然是有用信息；无法可靠判定时不延长预算。停止原因结构化保存为 completed、budget_exhausted、no_progress、permission_blocked、target_ambiguous、capability_missing、awaiting_reconciliation、awaiting_user、cancelled、failed 等，不把“回复结束”当作任务恢复成功。

## 8. 对照实验与采用门槛

### 8.1 固定环境对比

每个夹具冻结故障脚本/镜像版本、输入材料、资源映射、初始状态断言及验收契约。每个变体有独立 Lake Home、ADK session、终端、记忆/资产快照与环境状态；允许只使用测试合成凭据。每次复位完成需取得受信执行器证明，复位失败则该组无效。

区分可用实验臂：

- A：同一代码构建的默认内置策略；不应用学习资产、不新增学习与纠错。
- B：仅应用指定资产版本；其余条件与 A 相同。
- C：B 加有界只读纠错，单独评估纠错收益和成本。

为了只比较优化功能，A/B/C 使用相同的项目记忆快照和现有手写 Skill 快照，不把现有记忆能力一起关闭。学习产物在实验结束前不能跨臂注入。固定模型配置不保证远端模型输出确定性；记录提供方版本（可得时）、seed（支持时）、运行顺序和所有失败。

M2 首批 10～20 个案例，覆盖磁盘统计差异、服务日志错误路径、容器异常、数据库只读故障、SSH 连接失败/权限不足/工具不可用及无关对话。故障发现集与未用于提案的保留集分开；至少 3 个保留案例。推广前对可承受成本的代表任务进行每臂至少 3 次配对运行；样本不足展示原始结果，不宣称统计显著或通用提升。

### 8.2 评估和合成

指标包括诊断正确性、必需证据覆盖、错误结论、越界尝试、重复无效调用、用户纠正次数、总时间、模型请求/token、已知/未知费用和停止原因。拒绝/缺能力案例的正确停止也是合格结果，不能靠少调用或少回答获得高分。

验收由任务集固定且不提供给提案模型的判据决定；模型比较使用匿名 A/B 产物、原始证据和用户任务，不能读取隐藏答案、评分结果或跨任务秘密。评估环境限制答案泄漏渠道。比较模型失败单独记录为未评估，不记零分或候选胜出。

允许通用/领域两个候选，按预算选择串行或并行探索。根据行为差异合成新版本；合成版必须重新试跑，不能把两个候选各自的分数相加当合成收益。为迭代搜索设固定上限，不动态扩大预算挑选最好的一次。

采用至少要求：权限/秘密/操作恢复类硬检查无新增失败，目标案例达到固定条件，保留集没有未解释的关键退化，用户能看到效果和成本。没有候选胜出时保留基线，允许结果为 inconclusive。不得自动改验收条件、屏蔽失败样本或把基线失败全部剔除。

### 8.3 真实使用对比

正常任务只执行一次实际资源操作；不得为了对比重复修改生产资源。影子模式可对已有快照生成另一份不执行的分析，但标签为“影子分析”，不能计作实际完成/恢复。

真实使用统计分任务类型、模型、资源范围和版本展示，说明样本量、选择偏差与缺失数据。前后聚合不用于证明因果；可信的策略采用依据仍以固定环境配对评估和用户选择为主。

## 9. 开关与用户体验

### 9.1 设置语义

总开关默认关闭。高级设置分别保存 `applyEnabled`、`learnEnabled`、`correctEnabled`；用户可以只应用手写资产，也可以只生成候选。有效值是总开关、项目设置、场景允许和本轮选择的交集；后台定时任务不得偷偷打开。

| 操作 | 确定行为 |
| --- | --- |
| 总开关关闭 | 新轮次使用原默认策略和原有手写 Skills/记忆；不新建学习/纠错任务 |
| 运行中关闭 | 取消新增优化派发，已开始的普通原任务按现有语义收尾；若正处在优化附加尝试则停止并等待退出；不回滚外部效果 |
| 仅关闭学习 | 可应用已采用资产；停止排队生成，运行中提交需 epoch 校验；不删除资产 |
| 仅关闭应用 | 后续轮次不注入资产；允许生成候选，不能宣称产生了实际收益 |
| 仅关闭纠错 | 保留现有普通 Agent 推理和原有传输恢复；关闭新增策略修订循环 |
| 恢复开启 | 不追赶历史学习或重放旧实验；旧任务由用户显式重启 |
| 回滚资产 | 新增采用事件，绑定某个旧 revision；运行记录和操作账本不回滚 |

任务卡显示当次有效模式、采用版本和暂停/停止原因；避免给所有普通回复增加学习提示。基线模式明确记录关闭了哪些新能力，不能静默加载历史学习资产。

### 9.2 界面

在现有工作区/设置下增加“策略资产”入口，包含资产列表与范围、正文、版本差异、来源链、采用/停用/回滚和导入导出。候选生成显示简短理由、证据和适用范围，由用户预览后采用；不要求用户理解 ADK、harness 或 token 调度细节。

实验页比较基线与候选的实际结果、证据、调用量、用量及限制；“验证通过”与“用户采用”分开。血缘首版使用可展开的来源时间线即可，不依赖复杂图编辑器。前端使用 `AppSelect`、`Glyph` 等现有组件，验证键盘、窄窗口、深浅主题及中英文内容。

## 10. 接口草案

以下为拟议同源认证 API，不是已实现接口。服务端从当前会话/项目解析身份和范围，不信任客户端提交的 owner、project 权限或工具执行事实。

| 操作 | 拟议 API |
| --- | --- |
| 设置读取/修改 | `GET/PATCH /api/strategy/settings`，可通过已校验 project scope 选择项目设置，修改带 expectedRevision |
| 资产列表/手工创建 | `GET/POST /api/strategy/assets` |
| 版本详情/新修订 | `GET/POST /api/strategy/assets/:id/revisions` |
| 采用/停用/回滚 | `POST /api/strategy/assets/:id/bindings`，精确 revision、scope、expectedRevision |
| 来源血缘 | `GET /api/strategy/assets/:id/lineage`，分页且逐节点检查权限 |
| 从已选来源生成候选 | `POST /api/strategy/proposals`，提交 source IDs 与幂等键，不接受伪造工具结果 |
| 实验创建/读取 | `POST /api/strategy/experiments`、`GET /api/strategy/experiments/:id` |
| 取消/显式继续 | `POST /api/strategy/experiments/:id/cancel`、`.../:id/resume` |
| 报告与脱敏导出 | `GET /api/strategy/experiments/:id/report` |

变更使用 revision 冲突检查与幂等键；长操作返回任务 ID，不阻塞 HTTP/MCP 等待。首期不向所有 Agent 默认暴露实验启动工具，也不让模型采用/停用自己的策略。通知复用既有同源事件/查询机制；变更现有 events 类型前检查 schema CHECK，不能只加前端事件名。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| V01 | 新旧库、开关关闭、普通/终端/数据库/SRE/stdio/工作流/调度 | 仍走 ADK；没有学习资产注入或新优化请求；原有记忆和 Skills 行为保持 |

| V05 | 并发编辑/采用、重复请求、租约过期、关闭后旧 worker 返回 | revision 冲突或幂等返回；无重复版本/事件，无越过 epoch 的提交 |
| V06 | 崩溃于入队、模型返回、业务提交、ADK 启动和账本派发之间 | 恢复原身份和等待状态；不重放资源动作，unknown 保留 |
| V07 | 连续相同失败、参数修正、证据反证、无新信息 | 分类与进展记录真实；达到上限停止，不换角色清零 |
| V08 | 权限拒绝、目标不明、MCP 不透明操作、变更 unknown | 自动纠错不能绕过；需要决定/核实时正确等待 |
| V09 | 取消、运行中关闭总开关、停止子角色 | 不再派发新优化动作；已派发效果不虚构取消/回滚 |
| V10 | token/调用/耗时/候选数任一耗尽、usage 缺失 | 请求前预留，父子额度合并；停止而非超发，未知量明确 |
| V11 | A/B/C、复位失败、基线和候选相同 SRE step ID | 独立 session/环境和缓存，不复用其他变体成功结果 |
| V12 | 合成候选、比较失败、保留集退化、答案泄漏探测 | 合成再运行，评估失败保留未评估，无自动采用或篡改评分 |
| V13 | 血缘回溯、删除来源、全局资产跨项目读取 | 版本与真实来源可定位；敏感正文不可跨项目，缺证据状态准确 |
| V14 | 新增候选/反思自身再被观察 | 不产生递归学习风暴，不重复生成同源资产 |
| V15 | 键盘、深浅主题、窄窗口、大正文/分页 | 来源、差异、停止原因可读；使用共享组件 |
| V16 | 无关对话或简单查询 | 不因开关开启而启动故障采样、实验或多角色协作 |

按阶段运行有意义的 Go 单元/集成和前端测试，不为文案或可逆小改动重复全量环境演练。涉及执行、持久化或恢复的阶段必须有进程崩溃与真实隔离执行测试。发布门禁至少包括：

```sh

go test -race ./internal/ai ./internal/web ./internal/strategy
```

## 13. 发布与退出

M1/M2/M3 分别保持默认关闭。先在 Dev 启用，完成固定任务评估后提供实验性设置。若出现权限回归、秘密泄漏、重复外部操作、错误成功判定或开关无法停止新增任务，立即禁用对应阶段的新派发并保留审计记录。

退出优先关闭功能、取消排队任务、停止附加运行、核实账本并保留资产数据。回滚策略绑定与回退程序不同：前者仅影响后续提示词；后者必须使用兼容 schema 的签名构建，不覆盖最新执行账本。备份恢复不作为撤销生产操作的方法。
