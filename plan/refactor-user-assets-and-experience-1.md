# Lake 用户资产积累与经验复用开发计划

> **2026-10-28：原策略资产的新产品方向以[自然记忆重塑计划](feature-natural-memory-1.md)为准。** 本文保留 R0～R5 已交付的实现与验收历史，“候选—审核—采用”不再规定新记忆的日常交互。新计划承接用户内容、范围与来源保护，新增非阻塞形成、空闲整理、按范围使用及压缩前增量提取。[清理计划](refactor-harness-inspired-cleanup-1.md)继续约束旧执行退役与历史兼容；C1 已经 #107 合入，见 [C1 契约](../docs/design/strategy-execution-retirement-c1.md)，C2 转由新计划承接，N3 已提前清理无依赖退役派发器并折叠旧入口；C3/C4 其余清理仍待后续。

本计划接替[策略学习与改进开发计划](feature-strategy-learning-1.md)的后续开发方向：重点保留用户级资产、来源血缘和经验复用；在线纠错默认关闭；学习在后台生成待审核候选，不参与当前任务的成败判定。模型原有的分析、根据工具结果调整调查步骤等能力继续通过官方 ADK 执行，不强制经过额外的策略修订流程。

R0 盘点文档经 PR #68 合入。当前已实施 R1 的日常任务隔离和旧在线同意迁移，见 [R1 契约与验收](../docs/design/strategy-learning-daily-r1.md)；R2 已完成后台交付、前台优先与独立预算，见 [R2 契约与验收](../docs/design/strategy-learning-background-r2.md)。R3 已补齐审核、拒绝去重和显式晋升，见 [R3 契约](../docs/design/strategy-user-assets-r3.md)；R4 已补任务相关性、有效期/待复核、准确使用清单与反馈，见 [R4 契约](../docs/design/strategy-experience-reuse-r4.md)；R5 已完成同模型配对试点、真实 Dev 对照与旧优化退出，见 [R5 契约与结果](../docs/design/strategy-reuse-acceptance-r5.md)：72 组回放配对为 44 胜/28 平/0 退化，通用收益仍 inconclusive，不扩大默认范围。旧 P0～P8 的交付和收益结论保留为历史证据，不能把尚未实施的目标当作当前行为。

## 2. 目标使用流程与边界

```text
用户正常完成任务 / 明确纠正
  → 保存最小来源事件
  → 空闲时后台提取候选
  → 用户查看依据、编辑、选择范围并采用准确版本
  → 后续任务按适用条件选择少量资产
  → 记录使用与反馈，必要时重新验证、停用或回滚
```

1. **用户拥有资产，不意味着所有资产全局适用。** 当前 user scope 是本机用户身份，不是已实现的团队多租户。用户偏好可在确认后用于多个项目；项目事实和资源状态仍由项目记忆、CMDB 及实时工具结果承载。
2. 经验应表达“适用条件—处理方法—验证依据—已知限制”。一次失败或一次健康响应不直接升级为通用规则，也不证明整个服务恢复。
3. 保存候选、用户确认正文、验证有效性、采用版本继续分开。自动学习不自动采用，不写入手写 Skill，不自动改系统提示词、项目记忆或权限。
4. 学习与应用分别开启。允许只维护/应用手写资产，也允许只收集候选而不向任务注入。任何阶段都可停止学习，已采用资产按自身开关管理。
5. 不增加第二套模型/工具循环；辅助提取是无工具的单次 completion。学习失败、队列积压和候选预算不足只影响后台状态，不将已完成的业务任务改成失败。

## 4. 资产与经验的整理规则

### 4.1 范围、晋升和优先级

| 内容 | 默认归属 | 进入用户级资产的条件 |
| --- | --- | --- |
| 用户明确表达的报告偏好、协作方式 | 用户确认后可为 user；自动提取先留项目候选 | 显示原始纠正与提议正文，用户确认跨项目适用 |
| 项目命名、环境约束、特定工具操作方法 | project | 去掉项目标识/敏感信息，补齐适用限制，用户单独确认泛化版本 |
| 经验证的排障经验 | project 候选 | 保留成功和失败证据、验证方法、环境版本及限制；跨项目需重新审核 |
| 地址、凭据、临时资源状态、未验证猜测 | 事实存储或不提取 | 不作为可自动注入的通用策略；凭据始终不得进入资产 |

当前自动候选只支持 project scope。新增“提升为用户资产”应生成新的 user 资产/版本及受限的 `derived_from` 关系，不能只修改原行 scope 或把项目原始快照搬到全局。项目来源详情继续按原权限读取；跨项目展示不得泄露标题、正文、资源或消息摘要。晋升前预览最终正文和适用范围。

来源撤回/权限收紧需使依赖它的自动派生资产停止后续注入，清理可见缓存并保留合规墓碑。用户若要保留独立规则，须明确重新编写/确认新的来源与适用性，不能静默断开血缘逃避撤回。

固定规则、工具权限与当轮明确要求始终优先。沿用同一资产的项目绑定覆盖全局绑定（包括显式停用），相同标题不构成覆盖；多个互斥规则不自动选赢家。不同资产、Skill、项目记忆表达同一规则时优先避免重复注入，不据此删除用户源文件或记忆。

### 4.2 生命周期与质量

- 延续候选、准确版本采用、停用/回滚及来源状态；“用户确认”只证明内容被认可，不等于效果已验证。
- 在现有 revision/验证记录上补充：适用环境与前置条件、验证依据与时间、限制/失效条件、拒绝原因和复用反馈。确切字段及迁移在 R3 契约中冻结，不另建平行状态机。
- 内容改变产生新 revision，不能自动替换采用绑定。使用日志引用准确 revision/hash、选择原因和真实任务；区分“注入过”“被使用”“有证据改善结果”，不能把注入视为有效。
- 相同正文继续 hash 去重；近似重复先给审核建议，不自动合并。拒绝候选应抑制同来源/同内容反复生成；后台不得把用户拒绝再解释成支持证据。
- 环境、工具或模型发生变化时，方法类经验可标记待复核并暂停自动使用；明确偏好不应仅因模型升级失效。有效期按资产类型管理，不统一永久有效。

## 5. 后台学习：从已有异步提取补齐到不阻塞任务

### 5.1 采集与交付

前台只保存可恢复的最小来源事件：真实消息/轮次 ID、范围、epoch、触发类型以及有界证据引用。复用现有持久 outbox；较重的快照整理、提取、去重、候选入库和 Ack 重试交给后台。不得为学习复制无限会话历史或等待项目记忆提取成功。

现有引擎主状态保存仍属于业务可靠性边界。不能用“学习降级”吞掉真实会话保存失败、认证失败或执行权限失败。需要分离可选的学习处理错误与主存储错误；学习专属队列失败只记诊断/待重试，不修改最终答复和业务状态。

触发优先使用明确纠正与用户指定的记住要求；自然任务结果必须有可信工具证据及适用条件。单独一个工具错误只保存观察，不能直接形成已验证处理经验。取消、等待审批、未知资源效果不得作为成功样本。默认不追溯扫描全部历史；恢复扫描只处理已登记的待交付事件。

### 5.2 调度与预算

- 前台优先，后台并发初始为 1。领取前避让之外，还应处理任务启动后的竞争：辅助调用取消/延期，不占主任务会话锁；等待项目记忆/来源准备的状态留在队列内。
- 对同一模型共享槽位采用前台优先调度。若供应商/运行通道不能中断已发出的请求，需使用独立辅助通道或明确空闲窗口，不能宣称本地取消必然释放远端并发。
- 从在线纠错的重试/修订预算中拆出学习预算，按任务及日/队列上限管理。R2 已冻结：每候选最多 1 次模型请求，提取输入不超过 8 KiB、输出不超过 2,048 token、调用截止 30 秒；另设全局每日 12 次请求、61,440 token（未知用量保留预留），全局/项目待处理上限 100/20，48 小时队列有效期，UTC 次日重置。见 R2 契约；这些只控制后台提取，不扩大在线纠错额度。
- 保留来源去重、CAS、租约、epoch 和已提交结果复用；取消与提交竞争需有租约/epoch 提交校验。本地交付失败可退避重试，已保存的模型结果可重试入库；只有确定尚未派发的模型请求才允许重新派发。已发出但结果未知的请求保留未知状态，禁止自动再次收费调用。
- 用户关闭学习或撤回来源立即阻止新提取与提交；不因此取消无关的前台调查。候选异常显示在待审核/后台状态中，不向聊天追加纠错停止卡或改写完成状态。

### 5.3 应用资产也应可降级

按可信范围、场景、资源、明确标签及廉价任务关键词筛选，再执行去重、冲突和有效性检查；缺少匹配依据则不注入。先实现可解释的确定性排序，不引入向量服务或每轮模型检索。R4 已固定最多 3 条、总封装不超过 4 KiB，UTF-8 中文及 JSON 开销计入；按显式关键词匹配数、用户优先级和稳定 ID 排序。不以额外模型检索推断私有标签。

可选资产服务暂不可用、无匹配项、超限或尚未采用时，省略资产并保留诊断，主任务正常执行。**隐私/权限撤回不是可忽略的网络故障**：已注入的内容被撤回时，必须停止进一步使用或重建不含该内容的上下文后才可继续，不能一边沿用旧上下文一边声称已降级。固定执行权限、审批及未知操作恢复始终原样生效。

## 6. 开关、旧数据与退出范围

### 6.1 日常入口

日常界面围绕“应用已采用资产”和“后台积累候选”两个独立选择展开；全局与项目的收紧规则继续有效。资产查看、编辑、导入导出不需要开启学习或在线纠错。实验预算不与日常设置混排。

在线纠错若继续保留，放入实验入口并单独重新同意；默认关闭时不挂接观察/修订/预算拦截、不注册 `revise_readonly_strategy`。正常模型仍可在现有工具权限和原生操作账本内根据失败结果调整方法，不会为此消耗策略在线纠错额度。

### 6.2 老用户和在途任务

1. 设计版本化的能力同意记录：旧试用的 `onlineCorrectEnabled=true` 在升级后不直接视为新实验入口的同意，普通模式有效值为 false；保留旧设置与同意历史供审计，不静默开启学习或应用。
2. 原 `correctEnabled` 与快照优化的关系由兼容层解释并向用户说明，不直接改字段语义导致旧客户端误开启。应用/学习原有选择分别保留。
3. 未领取的在线/优化工作停止派发，记录停用原因；在途请求先核实结果与账本，未知状态不重置、不伪造成成功，也不自动续跑。禁止借迁移重放真实资源操作。
4. 保留资产、来源、历史报告和操作审计。数据库变更采用向前兼容迁移；上线前明确旧版读写范围。回滚不得恢复被撤回的正文、旧的在线同意或已取消任务。

### 6.3 不再作为日常功能投入

- 自动“提出—试跑—合成—递归”优化，不再是学习或采用资产的前置条件。
- 在线失败必须先提案再继续、纠错额度影响普通调查状态等耦合，移出普通模式。
- 以候选数量、修订次数、试跑完成率宣称自我进化收益的指标和引导文案，移除。
- 不做自动采用、跨项目自动晋升、生产资源自动试跑、模型微调或通用自反思框架扩张。

先关闭入口/派发、提供历史只读访问和兼容迁移，再分批删除无引用的在线/递归代码。不得直接 drop 历史表、删除迁移文件、清空账本，或删掉审批、来源撤回、未知结果核实的回归测试。按需离线 A/B 工具可以复用，但与后台提取队列、当前会话资源操作隔离。

## 9. 收益验证、停止条件与回退

比较的是 **同一当前模型 + 同一工具/Skills/项目记忆，有无已采用资产**。冻结模型版本、上下文、资产版本和任务判据；两组在线纠错均关闭，后台提取与试跑不混入被计时任务。使用可重置隔离环境或只读/回放证据，不在真实生产重复写操作。

样本应覆盖报告偏好、私有项目约定、已有经验再次适用、经验不适用/过期四类；先试行 20～30 个独立留出任务，每项至少 3 组配对并保留全部失败。这是试点建议，不构成统计显著性的承诺；模型升级后方法类资产重新抽查，不能沿用旧模型胜率。

主要记录任务完成质量、用户再次纠正次数、重复无效工具调用、前台耗时与 token/费用，以及错误规则迁移到新环境的损失；后台成本单独列出。使用率、审核负担、拒绝率用于解释成本，不把候选/采用数量当收益。

- 有明确帮助且无权限/隐私回归：只扩大已验证的资产类型与适用范围。
- 仍 inconclusive：保留手写资产和可选后台候选，不提升为默认自动经验应用；分析具体不适用、重复、错误泛化及审核成本后再立项。
- 出现来源越权、错误规则持续注入或前台被学习阻塞：停止该路径派发/应用，保留来源和调用证据；按绑定停用、配置回退与向前兼容修复处理，不以清空数据库回退。

## 10. 依赖、风险与执行规范

依赖现有业务 SQLite、官方 ADK、模型辅助 completion、项目来源与权限体系；无 Harness²/Python 客户端依赖，也不新增向量库。最大的实施风险是错误泛化、来源晋升泄露、共享模型并发争用，以及辅助故障与主存储故障划分不清。R1～R4 的契约与验收分别覆盖这些风险。

执行遵循 [AGENTS.md](../AGENTS.md)、[CONTRIBUTING.md](../CONTRIBUTING.md) 和[开发工作流](../docs/development-workflow.md)：普通 PR 目标为 develop，本地检查，合并须明确授权；只在 develop → master 的批次发布 PR 运行自动验证。历史 Windows CI 的单次授权不延伸到本计划。阶段开发授权不等于 PR 合并、Release 或生产安装授权；数据迁移限于对应阶段明确实现和验证的范围。
