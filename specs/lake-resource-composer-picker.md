# 会话输入框的湖资源快捷引用

## 产品规则

- 在会话输入框中，光标位于文本开头或空白字符之后时输入大写 `L`，打开当前会话所属湖的资源候选。小写 `l`、单词中间的 `L` 不触发；输入法组合中不抢占候选。
- 候选仅来自当前 `workspaceIdentity?.trim() || workspacePath` 唯一绑定的湖。未绑定湖、空资源、目录读取失败分别显示提示，不回退到其他湖或全局资源。
- 候选打开后第一条资源默认高亮；上下键循环移动，Enter/Tab 插入当前项，Esc 关闭；继续输入 `L` 后的文字可按名称、类型、环境、说明筛选。鼠标也可选择。
- 选择资源只向当前草稿插入「资源图标 + 名称」的引用，不打开 SSH、不建立连接、不改变湖目录。引用的发送文本仍包含选择时的登记快照与稳定资源 ID，明确它不是实时状态或授权凭据；它作为会话正文唯一持久化事实发送给 Agent，而不是另存一份仅 UI 可见的元信息。
- 已发送消息及分享只把可识别的湖资源引用显示为「资源图标 + 名称」，鼠标悬停可查看登记快照；复制、编辑与 Agent 上下文仍使用原始完整文本。旧版已经发送的长格式引用也按同样方式回显。普通用户文字不能因为只含「湖资源」几个字就被隐藏。关闭/重启后已发送消息仍可读；目录改名不改写历史消息。
- 资源查询结果是当前面板的临时 UI 状态，不能成为第二份持久化目录或跨湖缓存；切换工作区、关闭面板或异步查询过期后不得展示旧湖资源。

## 所有者、接口与顺序

```text
键入 L → Lexical 草稿/触发器 → base Host ILakeCatalogService
                                  getLakeForWorkspace(identity) → listLakeResources(lakeId)
       → 当前湖资源候选 → 选中并插入 mention 节点（图标 + 名称）
                            → 现有会话提交/序列化（完整登记快照）
                            → 消息回显/分享投影（图标 + 名称）
```

- 资源和湖绑定的唯一事实源是 `ILakeCatalogService`；输入框只保存当前查询结果与选中行。使用 base Host 读取应用级目录，远程会话仍按其 `workspaceIdentity` 匹配绑定。
- 不新增协议或资源访问权限。选择时的引用快照按现有纯文本提交路径交给 Agent；Agent 若需访问资产，仍须使用已有工具和权限，不因引用自动连接。
- 查询按输入框启用状态与工作区身份失效；晚于切换返回的响应必须丢弃。读取错误显示错误，不猜测湖归属。

## 验收场景

1. 在已绑定且有两条资源的湖会话中输入独立大写 `L`，出现该湖资源列表，第一项高亮；按下键、Enter 后插入对应资源引用，原有正文保留。
2. 输入 `L` 后继续键入资源名称片段，列表筛选；Esc 关闭，继续输入不自动提交；小写 `l` 和单词中的 `L` 不打开。
3. 切换到绑定另一个湖的同路径不同 identity 会话时，前一湖资源不出现；未绑定/空湖/读取失败不显示全局资源。
4. 发送选中资源的消息后，原始文本含湖、资源 ID、类型、环境和说明的登记快照，供 Agent 使用；当前消息、历史消息与分享页只展示图标加资源名，悬停可查看快照。复制和编辑保留完整原文；不触发 SSH、监控或凭据读取。
5. 已有长格式湖资源消息在升级后回显为短标签；不符合完整登记引用格式的普通文字原样显示，不吞掉相邻正文或多个引用。
6. 桌面与手机 Web 的候选可操作，中文和英文文案、明暗主题都可读。
